0.3 三类困难问题与“可证明安全”的口味

为什么"困难"要单独讲一节

密码学不是"把信息藏起来"的技术，而是"把安全性押在一个算不动的问题上"的技术。RSA 押在"大整数分解难"上，ElGamal 押在"离散对数难"上，Rabin 与 Fiat–Shamir 押在"模合数开平方难"上。整个本册的三个协议族，脚底下就是这三块地板。

这一节要解决三个问题：

  1. 这三块地板分别在说什么？它们之间谁依赖谁？
  2. "困难"是一个模糊的形容词，怎么把它变成一句可以写进定理的话？
  3. 什么叫"安全性可证明"？它有几种口味，各自能保证什么、不能保证什么？

三类困难问题

困难问题 一句话定义 正向（容易） 反向（难） 本册用在哪
大整数分解（integer factorization problem，IFP） 给合数 n=pqn=pqn=pq，求 p,qp,qp,q 两个大素数相乘 从乘积拆回因子 SET 的 RSA 签名；GQ 协议
离散对数（discrete logarithm problem，DLP） 给定 ggg 与 y≡gxy\equiv g^{x}y≡gx，求 xxx 从 xxx 算 gxg^{x}gx 从 gxg^{x}gx 反推 xxx 不可否认签名；Brands 电子现金；电话扑克；Schnorr
模合数平方根（square root problem，SQRT） 给定 n=pqn=pqn=pq 与 a≡x2a\equiv x^{2}a≡x2，求 xxx 已知 nnn 的一个因子时用 CRT 开方 只知 n,an,an,a 时开方 Rabin；电话投币；Fiat–Shamir；FFS

手算一个分解的玩具例子。333333 太小了，试除就能拆：除以 333 得 111111。300300300 位的 nnn 试除到 n\sqrt{n}n​ 需要 1015010^{150}10150 次除法——宇宙年龄也做不完。同一个问题的"容易"与"困难"只差在规模上，这是密码学里最常见的误会之一。

手算一个模合数开平方的玩具例子。n=33n=33n=33，已知 a=25a=25a=25 是某个数的平方（525^{2}52），要求全部平方根。按第 0.2 节的方法：模 333 的根是 1,21,21,2，模 111111 的根是 5,65,65,6，CRT 拼出四个根 {5,28,16,17}\{5,28,16,17\}{5,28,16,17}。知道 n=3×11n=3\times11n=3×11 时这四步都是小学算术；不知道分解时，你只知道"有四个根"却一个也写不出来。

翻译成人话：分解与开方是"一对亲兄弟"，会一个就会另一个；离散对数是"隔壁家的难题"，它和分解谁更难，至今没有答案。所以密码学同时使用这两族假设，等于把鸡蛋放在两个篮子里。

补"等价"在密码学里的准确含义是"多项式时间互相归约"，而不是"难度数值相同"。分解与开方满足这个条件（随机化意义下），所以常被当作同一个假设使用；而 DLP 与 IFP 之间既没有归约，也没有反例，属于"两个独立的信念"。另外，这三类问题在量子计算机上都会被 Shor 算法打破（分解与离散对数都有多项式时间量子算法），但在经典计算模型下它们依然困难——本册讨论的始终是经典对手。

单向函数与陷门单向函数

把"正向容易、反向难"抽象成一个数学对象，就是单向函数（one-way function，OWF）。

定义（直觉版）：函数 fff 是单向的，如果

  1. 存在多项式时间算法计算 f(x)f(x)f(x)；
  2. 对任何多项式时间算法 AAA，都存在可忽略函数 ε\varepsilonε，使
Pr⁡x←{0,1}k[A(f(x))=x]≤ε(k)\Pr_{x\leftarrow\{0,1\}^{k}}\big[A(f(x))=x\big]\le\varepsilon(k)x←{0,1}kPr​[A(f(x))=x]≤ε(k)

翻译成人话：随机挑一个输入 xxx，算出 f(x)f(x)f(x) 交给攻击者，他猜回 xxx 的成功率小到可以忽略——注意是"对随机输入平均而言"，不是"每个输入都难"。

这里的 kkk 是安全参数（security parameter），可以理解为"密钥有多少位"。概率是对随机选取的 xxx 取的，这一点很关键：密码学要的是"平均情况困难"（average-case hardness），而不是"存在某个难实例"。

"可证明安全"的四种口味

"这个方案是可证明安全的"这句话，在不同场合含义完全不同。初学阶段至少要能分清四种口味。

口味 安全从哪里来 典型例子 代价
信息论安全（information-theoretic / unconditional） 不依赖任何计算假设；敌人算力无限也破不了 一次一密（one-time pad）；Shamir 门限（t−1t-1t−1 个分享）；Chaum–Antwerpen 伪造概率 1/q1/q1/q 的界 密钥必须和消息一样长；功能很受限
归约到难题（reduction to a hard problem） 攻破方案 ⇒\Rightarrow⇒ 解出 IFP/DLP/SQRT，于是"难题难"蕴含"方案安全" Rabin 加密；Fiat–Shamir 的可靠性；Brands 电子现金 归约可能"松"（损失多项式因子）；依赖难题本身未被证明
理想模型（idealized model） 把 Hash 当随机函数（random oracle model），或把群当黑盒（generic group model） 用 Fiat–Shamir 启发式把交互协议变成的签名；Schnorr 签名的部分分析 真实世界不存在"随机函数"，模型里的证明可能不迁移
经验安全（heuristic / no known attack） 只有"目前没人攻破" DES、AES 本身；MD5 在被攻破之前的二十年 理论保证最弱，工程上最常用

翻译成人话：信息论安全是"物理定律级别"的保证；归约安全是"如果你相信这道难题，就必须相信这个方案"；理想模型安全是"在一个理想化的世界里证明成立"；经验安全是"暂时没人打穿"。

补为什么"归约"是主流？ 因为信息论安全太贵（一次一密要求密钥不重复、和明文等长），而理想模型又常被质疑（随机预言机模型里可证明安全的方案，在真实世界被攻破的例子不少）。归约安全是"成本与可信度"的折中：它把新方案的安全性"折算"成一道老难题的安全性，让你不必从零开始相信一个新东西。

归约的直觉：把攻击者当成一个黑盒

归约证明（reduction）的套路只有三步，但每一步都要写清概率。

  1. 假设：存在一个攻击者 A\mathcal{A}A，能以不可忽略的概率攻破方案。
  2. 构造：用 A\mathcal{A}A 当子程序，造出一个算法 B\mathcal{B}B，它去解那道公认的难题。
  3. 结论：B\mathcal{B}B 的成功率与 A\mathcal{A}A 的成功率挂钩。既然"难题难"，B\mathcal{B}B 不可能成功，于是 A\mathcal{A}A 也不可能成功。
    ┌───────────────────┐    ① 把难题实例伪装成协议实例     ┌───────────────────┐
    │  B：解难题的算法   │ ─────────────────────────────▶ │  A：假设存在的攻击者 │
    │  （我们构造的）     │ ◀───────────────────────────── │  （被当成黑盒调用）  │
    └─────────┬─────────┘    ② A 返回它对协议的"攻破结果"   └───────────────────┘
              │
              ▼  ③ 从 A 的结果里"读出"难题的解
        与"这道难题是困难的"矛盾 → A 不存在

翻译成人话：归约就是"如果你能撬开这把锁，我就能用同一把工具去拆那台保险柜"；既然保险柜没人拆得开，这把锁也就没人撬得开。

写成概率不等式，通常长这样：

Pr⁡[attack]≤Pr⁡[reduction]+ε\Pr[\mathrm{attack}]\le\Pr[\mathrm{reduction}]+\varepsilonPr[attack]≤Pr[reduction]+ε

翻译成人话：攻击者成功的概率，不超过"归约算法解出难题的概率"加上一个可忽略项；右边既然可忽略，左边也可忽略。

一个可以手算的归约例子（开平方 ⇒\Rightarrow⇒ 分解）：假设有一个"开方预言机" O\mathcal{O}O，给任意 aaa 都能返回一个平方根。用它分解 n=33n=33n=33：

  1. 随机取 r=2r=2r=2，算 a=r2=4a=r^{2}=4a=r2=4；
  2. 问 O\mathcal{O}O 要 444 的一个根，它可能返回 {2,31,13,20}\{2,31,13,20\}{2,31,13,20} 中任意一个，且四个等可能；
  3. 若返回 222 或 313131（即 ±r\pm r±r），这次失败，重来；若返回 131313 或 202020，则 gcd⁡(13−2,33)=11\gcd(13-2,33)=11gcd(13−2,33)=11，分解成功。

翻译成人话：每次尝试有一半概率得到"不是 ±r\pm r±r 的根"，于是两步之内就能把 333333 拆开；这解释了为什么"能开平方"与"能分解"在随机化意义下等价。

补归约的"紧"与"松"：如果上面这个预言机每次调用都成功概率 1/21/21/2，那么解分解的成功率至少是"调用一次开方"的一半——归约很紧。但很多真实归约里，B\mathcal{B}B 要模拟整个交互环境，模拟可能失败、可能要对 A\mathcal{A}A 做多次调用，最后成功率会掉一个多项式因子。"归约存在"不等于"实际安全强度等于难题强度"，这是读安全证明时必须盯住的地方。

可忽略概率：协议为什么必须用概率语言

几乎所有协议的安全定理都写成"某某事件发生的概率是可忽略的"。可忽略（negligible）有精确含义：

ε(k) is negligible  ⟺  ∀c>0, ∃k0, ∀k>k0: ε(k)<1kc\varepsilon(k)\ \text{is negligible}\iff\forall c>0,\ \exists k_{0},\ \forall k>k_{0}:\ \varepsilon(k)<\frac{1}{k^{c}}ε(k) is negligible⟺∀c>0, ∃k0​, ∀k>k0​: ε(k)<kc1​

翻译成人话：不管你把多项式 kck^{c}kc 取多大（k2k^{2}k2、k10k^{10}k10、k100k^{100}k100），只要参数 kkk 足够大，ε\varepsilonε 都比它小；换句话说，ε\varepsilonε 比"任何多项式倒数"衰减得都快。

几个具体数字，帮助建立量级感：

概率 约等于 类比
2−202^{-20}2−20 9.5×10−79.5\times10^{-7}9.5×10−7 百万分之一
2−402^{-40}2−40 9.1×10−139.1\times10^{-13}9.1×10−13 万亿分之一
2−802^{-80}2−80 8.3×10−258.3\times10^{-25}8.3×10−25 相当于随机猜中一个 80 位密钥
1/q1/q1/q（qqq 为 160 位素数） 2−1602^{-160}2−160 可忽略

翻译成人话：密码学里的"安全"从来不是"绝对不可能"，而是"成功的概率小到不值得尝试"。2−802^{-80}2−80 这个量级被广泛当作"实际安全"的门槛。

为什么协议必须用概率语言——三个来源：

  1. 随机数：协议里到处是随机挑战（Challenge），攻击者只能猜；猜中概率 1/21/21/2 或 1/q1/q1/q。
  2. 重复：把 kkk 轮独立执行串起来，作弊成功率变成 2−k2^{-k}2−k。Fiat–Shamir 每轮 1/21/21/2，202020 轮是 2−202^{-20}2−20，404040 轮是 2−402^{-40}2−40；FFS 每轮 2−k2^{-k}2−k；Chaum–Antwerpen 的伪造概率是 1/q1/q1/q，且与攻击者算力无关。
  3. 归约损失：归约里可能出现"模拟失败""多次调用"等事件，最终界里带一个可忽略项。

翻译成人话：只要协议里有"猜"的成分，结论就只能写成概率；把概率压到可忽略的办法，要么加大参数（qqq 更大），要么多跑几轮（kkk 更大）。

翻译成人话：第十讲靠 RSA 与离散对数，第十一讲一半靠信息论、一半靠平方根与离散对数，第十二讲靠平方根、RSA 与离散对数。先认清每个方案的"地板"，再读它的安全评述，就不会被一堆符号淹没。

补一个容易混淆的点："困难问题"不等于"难算的函数"。比如 Hash 函数（MD5、SHA-1）也是"正向容易、反向难"，但它不是靠数论难题，而是靠"压缩 + 混乱"的设计；它的安全性属于上面第四种口味（经验安全），目前没有归约证明。本册里 Hash 主要当工具用（做摘要、做承诺），不当"地板"。

本节要点

  1. 三类困难问题：大整数分解（IFP）、离散对数（DLP）、模合数平方根（SQRT）；前两者互不归约，分解与开方在随机化意义下等价。
  2. 单向函数 = 正向易、反向难（平均情况）；陷门单向函数 = 再加一段"后门信息"让持有者能反算。RSA 与 Rabin 有陷门，离散对数没有。
  3. "可证明安全"有四种口味：信息论、归约、理想模型、经验安全。本册三种都有，Shamir 门限是唯一的信息论安全。
  4. 归约三步：假设攻击者存在 → 用它构造解难题的算法 → 得出矛盾。写成概率不等式：攻击成功率 ≤\le≤ 解难题成功率 + 可忽略项。
  5. 协议的安全性必须用概率表述，因为随机挑战、重复轮数、归约损失都会引入"猜"的成分；可忽略概率是"比任何多项式倒数都小"。
