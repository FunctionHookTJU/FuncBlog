2.1 不可否认签名：动机与应用

第十讲从第 16 页开始讲第二块内容：不可否认签名（undeniable signature）。这一节只讲「为什么需要它、它长什么样、能用在哪」，具体怎么构造留到 2.2–2.3。第 16 页给动机与定义，第 17、18 页给两个应用。请先接受一个反直觉的前提：「签名人人都能验证」这件事，有时候是个缺点。

人人可验，未必是好事（PPT 第 16 页）

课件第 16 页的原文是这一节的全部立论：

一般的数字签名可以任意拷贝。有时候这一特性非常有用，例如，分发公开通知。但是，假定是对一封个人信件或商务信件的签名。这样的文件大量传播，并且可以为任何人验证是由某人签署，可能非常尴尬甚至为人利用勒索。一种解决办法是签名可由接收者认证，但是，没有签名者的同意，接受者不可能再向第三方证实签名确实来自签名者。

这段话的结构非常清楚：先承认好处，再指出坏处，最后给解决思路。 逐层读：

第一层：好处——「可以任意拷贝」正是数字签名的设计目标。 数字签名的验证只需要两样东西：签名者的公钥 + 消息本身。公钥是公开的，所以任何人、在任何时候、不需要签名者在场，都能验证。这正是我们想要的：政府发布公告，全国人都能验；软件发布签名，几百万用户都能验；证书签名，任何浏览器都能验。可传播性 = 可验证性 = 公钥的公开性，这三件事是同一件事。

第二层：坏处——有些签名不该被传播。 课件举了「个人信件或商务信件」。设想你给朋友写的一封私人邮件，或者你给合作方的一份报价函，上面有你的数字签名。任何人拿到这份文件，都能独立验证「这确实是某人签的」，而且验证过程完全不需要你参与。后果是：

  • 尴尬：一句私下的玩笑、一个临时的报价、一段情绪化的表达，一旦被截图转发，就变成「某人说过的话」的永久证据。
  • 勒索：攻击者不需要伪造签名，他只需要拥有你的签名，然后威胁「你不给钱，我就把它发给你的老板/客户/家人」。签名本身成了人质。

补勒索的可怕之处在于「签名是真的」。 如果是伪造的签名，你可以说「那是假的」；但在普通数字签名方案里，真签名与假签名的区别是数学上可判定的，而一旦判定为真，你就失去了全部辩解空间。 你无法说「我没签过」，也无法说「那不是我的本意」——密码学只验证「这串字节是不是你的私钥对这段消息作用的结果」，它不关心「你当时是不是被胁迫」「你是不是只想给一个人看」。普通签名把「我说过」和「我对全世界说」变成了同一件事。

第三层：解决思路——把验证权收回到签名者手里。 课件的原话是：「签名可由接收者认证，但是，没有签名者的同意，接受者不可能再向第三方证实签名确实来自签名者。」这句话里有两个「但是」级别的约束，缺一不可：

  1. 对接收者 B：B 必须能验证这个签名（否则 B 不敢信）；
  2. 对第三方 C：B 不能单方面向 C 证明这个签名有效（否则签名就能被传播）。

也就是说，B 的验证能力是「私人的、不可转让的」。这在普通签名里做不到（B 只要把文件和公钥交给 C 就行），所以需要一个新的签名方案。这就是不可否认签名。

把两种签名的「谁能验」画成图，差别一目了然：

【普通数字签名】—— 验证是公开的，谁都能做

      A ──签名──▶ B ──转发──▶ C ──转发──▶ D ……
                   │           │           │
                   ▼           ▼           ▼
                 验签 ✓      验签 ✓      验签 ✓      （不需要 A 参与）

【不可否认签名】—— 验证需要 A 配合，B 无法转手证明

      A ──签名──▶ B
                   │
                   │  B 想向 C 证明？必须拉 A 一起做验证
                   ▼
                  C ──"请 A 来验证"──▶ A ──"我不配合"──▶ C 无法确认
                                        │
                                        └─▶ B 的证明失败

不可否认签名的定义（PPT 第 16 页）

把课件那段话提炼成定义，一共三条：

定义（不可否认签名）：一种数字签名方案，满足 ① 签名的验证需要签名者参与（没有签名者的配合，接收者无法完成验证）； ② 没有签名者的同意，接收者无法向第三方证明签名有效； ③ 但如果签名者拒绝配合，接收者可以启动否认协议（disavowal protocol，课件第 25 页称「否认方案」），迫使签名者要么承认这个签名有效，要么证明它是伪造的。

第 ③ 条课件在本节没有写，是 2.3 节的内容（PPT 第 25–27 页），这里先记个名字，后面会展开。

补第 ① 条和第 ② 条的区别要分清。 ① 说的是「验证这个动作需要 A 在场」，② 说的是「就算 B 验过了，B 也拿不出证据给 C 看」。可以想象成：① 是「门锁需要两把钥匙同时插」，② 是「你开门的过程没留下能给别人看的录像」。一个方案可能 ① 很强但 ② 很弱（比如 A 每次验证都发一条「我确认」的消息，B 把这条消息拿给 C 看——那 ② 就破了）。所以两条要分别检查。

补「不可否认」这个名字容易理解反。 undeniable 的字面意思是「不能被否认」，听起来是在保护接收者（签名者不能赖账）。但在本节的语境里，它主要是在保护签名者（签名不能被别人拿去传播）。两件事都成立：

保护谁 防什么 靠机制
签名者 A 签名被任意传播、被拿来勒索 验证需要 A 配合，B 无法转手证明
接收者 B A 事后赖账说「我没签过」 否认协议：A 拒绝配合则等于承认（2.3 节）

这是一种「双向约束」的设计：A 不能装作没签，B 也不能拿签名去到处宣扬。 普通的数字签名只给了前半句，不可否认签名把后半句补上了。

补代价是什么？ 三条：①签名者必须在线（或至少能被联系上），否则验证做不了——这在离线文档、历史档案场景里是硬伤；②签名者可以恶意拒绝配合，所以必须有否认协议兜底；③协议是交互的，比「算一个函数」复杂得多。任何方案都有代价，不可否认签名用「可用性」换了「可控的传播性」。

应用一：软件转售与「来源不明的拷贝」（PPT 第 17 页）

课件第 17 页原文：

(1) 假定一个大的软件公司 AAA 开发了一个软件。AAA 可以签署软件把它买给实体 BBB。BBB 可能希望拷贝这个软件再买给第三方 CCC。CCC 则在没有 AAA 的帮助下无法验证软件确实来自 AAA。当然，这无法阻止 BBB 自己对软件进行签名，但是与公司 AAA 名字相关联的市场优势将消失。而且这也很容易追踪 BBB 的欺诈行为。

补引文里的两处「买给」按上下文应为「卖给」——这是课件原文（或提取过程）的用字问题，这里保留原样以便对照，理解时不必纠结。

把角色和动机摆清楚：

  • AAA：大软件公司，软件的作者，拥有品牌与技术支持能力；
  • BBB：买了正版的实体（可以是一家小代理商、也可以是普通用户）；
  • CCC：想买软件的第三方，BBB 想把拷贝卖给他。

如果没有不可否认签名（用普通签名）： AAA 把软件签给 BBB，BBB 把整个软件包（含 AAA 的签名）拷贝一份卖给 CCC。CCC 拿 AAA 的公钥一验——通过。于是 BBB 白嫖了 AAA 的品牌：CCC 以为自己买的是 AAA 的正版，实际上 AAA 一分钱没收到，还要提供技术支持。

有了不可否认签名： AAA 的签名只有 BBB 能验（需要 AAA 配合）。BBB 把拷贝交给 CCC，CCC 想验证就必须去找 AAA；AAA 可以拒绝为一个自己没卖过的拷贝做验证。于是 CCC 无法确认这份拷贝来自 AAA，交易做不成。

   普通签名：
     A ──(签名 + 软件)──▶ B ──(原样拷贝)──▶ C
                                            │ 自己验签 ✓
                                            ▼
                                     C 以为买到了 A 的正版（A 吃亏）

   不可否认签名：
     A ──(签名 + 软件)──▶ B ──(原样拷贝)──▶ C
                                            │ 需要 A 配合才能验
                                            ▼
                                     C 找 A ──▶ A 拒绝 ✗
                                            C 不敢买（B 的转卖失败）

课件紧接着补了两句非常重要的「边界说明」，很多人读到会以为方案有漏洞，其实是作者在诚实交代：

「当然，这无法阻止 BBB 自己对软件进行签名。」 也就是说，BBB 完全可以自己做一份签名，宣称「这是我卖的软件」。不可否认签名只防止冒充 AAA，不防止 BBB 卖东西。那为什么 BBB 不会这么做？

「但是与公司 AAA 名字相关联的市场优势将消失。而且这也很容易追踪 BBB 的欺诈行为。」 这两句是经济学论证而不是密码学论证：

  • 市场优势消失：客户买软件买的是「AAA 出品」这个牌子——它意味着质量、更新、技术支持、法律合规。BBB 自己的签名只能证明「这是 BBB 卖的」，提供不了任何品牌背书。BBB 的盗版因此卖不出正版的价钱，盗版的收益被压到接近零。
  • 容易追踪：BBB 要卖拷贝，就得留下交易痕迹（收款账户、发货渠道、客户名单）。AAA 一旦发现，可以顺着这些痕迹追责。密码学不负责抓人，但负责让「合法性的证明」变得不可伪造，剩下的交给法律。

补这个应用的现实对应物：软件序列号、激活码、授权证书、加密狗。它们和不可否认签名是同一个思路的工程近似——让「是不是正版」这件事必须向厂商确认，而不是买家用一个公开算法就能自己验完。 区别在于，序列号体系靠的是「厂商数据库」，不可否认签名靠的是「密码学协议」，后者不需要一个永远在线的中心数据库。

补注意这个应用里的一个尴尬之处：AAA 必须为每一个「正当的验证请求」提供服务。如果 BBB 是合法转售（比如 BBB 是授权经销商），AAA 就得配合；如果 BBB 是盗版，AAA 就拒绝。也就是说，不可否认签名的可用性依赖于签名者「按规则配合」——这既是它的安全边界，也是它的运营成本。2.3 节讨论「签名者恶意不配合」时，会回到这个问题。

补同一个机制也管住了反方向的赖账。 如果 BBB 反过来声称「这份软件根本不是 AAA 签的」（比如想赖掉授权费，或者把 AAA 的正版说成自己开发的），他同样拿不出可以让第三方独立核实的证据；而只要 AAA 愿意配合做一次验证，签名有效这件事就能被确认。所以「验证必须双方配合」对两边都是约束：AAA 不能赖掉自己签过的，BBB 也不能凭空否认 AAA 签过的事实。

应用二：银行保险箱与「访问记录」（PPT 第 18 页）

课件第 18 页原文：

(2) 实体 AAA（客户）希望通过实体 BBB（银行）获得某个安全区域的访问权限。例如，安全区域可以是银行保险箱放置的房间。BBB 需要 AAA 在访问之前签署一个访问日期和时间的文件。如果 AAA 使用不可否认签名，则在此之后 BBB 不可能在没有 AAA 的协助下，就向其他实体认证 AAA 在某个日期和时间访问过保险箱。

这个例子的结构和上一个几乎相反，值得仔细对照：

  • 场景：银行有一间放保险箱的房间，客户 AAA 要进去，银行 BBB 要求他先签一份「某年某月某日某时，我进入过保险箱房间」的记录。
  • 银行为什么要求签：为了责任划分——万一保险箱里的东西少了、坏了，银行能拿出「客户当时确实来过」的记录；也为了防止「客户说自己没来过，是银行弄丢的」这种纠纷。
  • AAA 为什么担心：这份记录一旦能被银行拿去给任何人看，就等于AAA 的行踪被永久记录并可被任意传播。

补这份记录能被用来干什么？ 想象几种现实场景：①离婚诉讼——对方律师拿到「AAA 在某日进入保险箱房间」的记录，可以推断 AAA 在转移财产；②商业调查——竞争对手知道 AAA 某日去过银行，可以推测融资、并购、资金链；③人身安全——知道 AAA 某日下午在银行，就能推断他家当时没人；④媒体曝光——「某某名人频繁出入保险箱」本身就是新闻。这些后果都不是「钱被偷」，而是「行踪被掌握」，属于隐私侵害。

用不可否认签名之后发生了什么？ 银行仍然能验证 AAA 的签名（在 AAA 配合时），所以银行自己的管理需求满足了：它能确认「AAA 确实签过这份访问记录」。但是，银行不能在没有 AAA 协助的情况下，把这份记录向第三方证明。 也就是说：

  • 对银行自己：记录有效，可用于内部管理、责任划分、和 AAA 当面对质；在银行这一侧，AAA 事后无法否认这次访问（因为银行手里有当场验证过的签名）；
  • 对第三方：记录「不能作为证据」——银行拿不出能让第三方独立验证的东西。
   访问前：  A ──签署「某日某时进入」──▶ B（银行）
                                          │
                                          ├─ 用途一：内部管理 ✓（A 配合时可验）
                                          │
                                          └─ 用途二：向 C（法院/记者/对手）证明 ✗
                                                    没有 A 配合，B 做不到

补这个应用里有个耐人寻味的地方：银行其实不完全乐意。 银行要这份记录，本来就是为了「将来出事时能拿出来」。不可否认签名让银行失去了把记录交给第三方的能力，等于削弱了银行自己的证据武器。所以这个方案在现实中要落地，通常需要双方事先约定（甚至写进合同）：银行同意「只用于内部责任划分，不向第三方披露」。技术只能保证「做不到」，做不到之后怎么用，是社会契约问题。

补这里出现了一个重要的「角色反转」，请一定注意到：

普通签名里的「不可否认」 本应用里的「不可否认」
保护谁 接收者（签名者不能赖账） 签名者（签名不能被传播）
防谁 签名者 接收者
典型场景 合同、支付、承诺 私人信件、访问记录、报价

同一个词，在两个场景里保护的是相反的一方。 这不是矛盾，而是因为「不可否认」这个词描述的是签名的性质（不可被随意否认/确认），而不是谁受益。受益方取决于你把签名用在哪一边。

两个应用的共同点（课件第 17–18 页的隐含结论）

课件没有专门写「共同点」这一小节，但两个应用摆在一起，共同结构非常清楚：

维度 应用一：软件转售 应用二：保险箱记录
签名者 AAA 软件公司 客户
接收者 BBB 买方/转售者 银行
想验证的第三方 CCC 下家买家 法院、记者、竞争对手
BBB 当场需要什么 确认「这软件是 AAA 的正版」 确认「AAA 确实来过」
BBB 转手需要什么 让 CCC 也相信这是正版 让 CCC 也相信 AAA 来过
不可否认签名卡住了哪一步 CCC 无法独立验证 BBB 无法向 CCC 举证
谁受益 AAA（保住品牌与授权收入） AAA（保住行踪隐私）

共同点可以归纳成三句话：

  1. 接收者需要「现在能确认」——所以签名必须对 BBB 有效，否则 BBB 不敢交易；
  2. 接收者不能「转手证明」——所以验证必须依赖签名者，否则签名会被无限传播；
  3. 签名的价值取决于签名者愿不愿意配合——AAA 配合，验证就成立；AAA 不配合，BBB 就卡住。这既是保护，也是新的风险。

第 3 点是关键，也是不可否认签名最脆弱的地方：如果签名者永远不配合，接收者岂不是永远无法验证？ 那 BBB 凭什么相信这个签名？答案就是前面提过的否认协议——如果 AAA 拒绝配合，协议会设计成「要么 AAA 承认签名有效，要么 BBB 能证明这是伪造」。这个机制留到 2.3 节（PPT 第 25–27 页）讲，本节只需要知道：「必须配合」这四个字是有强制力设计的，不是靠 AAA 的自觉。

补什么时候普通签名反而更好？ 不要以为不可否认签名是「升级版」。做一个对照：

场景 适合普通签名 适合不可否认签名
政府公告、软件发布、证书 ✓ 需要人人可验、长期可验 ✗ 签名者不可能永远在线
公开合同、需要第三方仲裁 ✓ 证据必须能交给法院 ✗ 转手不可证明，反而不利
私人信件、内部报价、访问记录 ✗ 一旦泄露无法收回 ✓ 传播受控
离线文档、历史档案 ✓ 几十年后仍可验证 ✗ 签名者可能已不存在

判断标准只有一条：这个签名将来需不需要「拿给别人看」。 需要，就用普通签名；不需要、甚至害怕被拿给别人看，才用不可否认签名。

通往 2.2 的接口

本节只回答了「为什么」和「用在哪」，还没回答「怎么造」。第 19 页开始，课件会给出 Chaum–Antwerpen 方案：用「qqq 阶循环子群上的离散对数」构造一个签名，其验证必须由签名者出一道随机挑战、接收者用签名者的回答来确认。大致骨架是：

   1. A 把签名 σ 交给 B
   2. B 选一个随机数 c（挑战），发给 A
   3. A 用私钥和 c 算出一个响应 r，发回 B
   4. B 用公开参数验证 r 与 c、σ 的关系
      —— 只有 B 能确认，因为 c 是 B 自己选的、别人不知道

为什么「只有 B 能确认」？ 因为校验等式中用到了 B 自己选的随机数 ccc，而 ccc 没有公开：第三方即便录下往来消息，也补不出校验所需的那一步（要从公开值反推 ccc，等价于解离散对数）。这就是「验证权不可转让」的技术来源——不是靠规定「B 不许说」，而是靠数学上「B 说不清」。

补这个骨架你其实已经见过。 它是「挑战–应答」（challenge–response）协议的一种，第十二讲的零知识证明鉴别协议（Fiat–Shamir、Schnorr 等）用的是同一个骨架。区别在于目的：零知识证明要证明「我知道一个秘密」，不可否认签名要证明「这个签名是真的」。同一个交互结构，可以服务于完全不同的目标——这又是本讲开头那句「把基本方案融入特定协议，得到附加功能」的一个例证。

本节要点

  • 普通数字签名的「人人可验」来自公钥公开，这既是优点（可传播）也是缺点（不可控传播、可被勒索）。
  • 不可否认签名：验证需要签名者参与，且接收者无法单方面向第三方证明；签名者若拒绝配合，则走否认协议（2.3 节）。
  • 它同时约束双方：签名者不能赖账，接收者也不能把签名到处宣扬；代价是签名的可用性依赖签名者在线与配合。
  • 应用一（软件转售）：阻止 BBB 借 AAA 的品牌转卖盗版；威慑来自品牌价值消失与可追踪，而不是密码学阻止 BBB 自己签名。
  • 应用二（保险箱记录）：阻止银行把客户的行踪记录当作对第三方的证据；这里「不可否认」保护的是签名者的隐私。
  • 两种应用的共同点：BBB 当场能验、BBB 转手不能证、签名价值取决于 AAA 是否配合。
  • 是否需要「拿给别人看」，是选择普通签名还是不可否认签名的唯一判断标准。
