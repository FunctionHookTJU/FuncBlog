### 使用说明

本附录是**全册术语中英对照表**，覆盖三讲：第十讲（电子商务与电子现金）、第十一讲（秘密分享与游戏）、第十二讲（零知识证明技术）。主条目共 119 条，按主题分成五组，每条给「中文名 | 英文名 | 一句话解释」；A.6 另有十组最容易混淆的术语对照，供考前背诵。

用途有三个：①读英文教材或论文时，把中文说法和英文原词对上；②复习时用一句话把概念复述出来，检验自己是否真懂；③确认某个术语在本册哪一讲、哪一节出现过（解释里都标了出处）。带「★」的是最容易混淆、建议优先背下来的条目。

【补】表中少数条目（「可验证秘密分享」「承诺」「安全参数」等）课件只点名或没有展开，是为了把前后知识接上而补入的；第一遍通读时可以先跳过，不影响三讲的主线。

### A.1 电子商务与 SET（第十讲 1–1.2.3 节）

| 中文 | 英文 | 一句话解释 |
|---|---|---|
| 电子商务 | electronic commerce (e-commerce) | 通过公开网络完成定货与付款的商务形态，安全性靠密码协议而不是面对面的物理接触。 |
| 安全电子交易 | Secure Electronic Transaction (SET) | 1996 年 MasterCard 与 Visa 联合几家公司在现有信用卡体系之上制定的网上支付标准（PPT 第 7 页）。 |
| 持卡人 | cardholder | 持卡、在网上下达定单并授权付款的一方，SET 中用字母 C 表示。 |
| 商家 | merchant | 提供商品或服务、向银行申请支付授权的一方，用字母 M 表示。 |
| 银行 | bank | 保管账户、验证支付指令并授权付款的一方，用字母 B 表示。 |
| 商品和服务定单 | goods and services order (GSO) | 描述「买什么、买多少、多少钱」的定单信息，字段含双方名字、商品数量、价格等（PPT 第 8 页）。 |
| 支付指令 | payment instruction (PI) | 描述「用哪张卡、付给哪个商家、付多少」的支付信息，含卡号（PPT 第 8 页）。 |
| 双重签名 ★ | dual signature | 两条消息先各求摘要、再把两个摘要连接起来求摘要并签名的构造；课件也称「双向签名」。 |
| 消息摘要 | message digest | Hash 函数的输出，把任意长消息压成短的定长值，改动一个比特就面目全非。 |
| Hash 函数 | hash function | 公开的单向压缩函数，本讲用它做摘要与承诺。 |
| 连接 | concatenation | 把两个串首尾拼接，记作 $\parallel$；拼接顺序不同，结果就不同。 |
| RSA 公钥加密 | RSA public-key encryption | 用一对（公开、私有）密钥分别做加密与解密的算法，签名与解密是同一个数学运算。 |
| 加密函数 | encryption function | 用对方公开密钥把明文变成密文的函数，SET 中记作 $E_C$、$E_M$、$E_B$。 |
| 解密函数 | decryption function | 用自己的私有密钥把密文还原的函数，记作 $D_C$、$D_M$、$D_B$；用私有密钥作用在摘要上就是签名。 |
| 公钥 / 私钥 | public key / private key | 可以公开的那把钥匙与必须保密的那把钥匙，二者成对生成。 |
| 认证 | authentication | 让接收方确信消息的来源与内容没有被冒充或改动。 |
| 真实性 | authenticity | 交易各方都是真实存在的实体、签名没有被伪造的性质（PPT 第 6 页第 (2) 条）。 |
| 隐私 | privacy | 敏感账户信息（例如卡号）不被无关方看到。 |
| 完整性 | integrity | 定单与账户文件在传输途中不能被变更，一旦变更必然被发现（PPT 第 6 页第 (3) 条）。 |
| 收条 | receipt (TC) | 商家发给持卡人的加密签名凭据，证明这笔交易已经完成（PPT 第 13 页）。 |
| 支付授权 | payment authorization (GP) | 银行发给商家的加密签名，承诺为这笔支付入账担保（PPT 第 13 页）。 |
| 信用欺诈 | credit fraud | 攻击者用窃得的卡号信息冒用他人信用额度。 |
| 拼接攻击 | splicing attack | 把一条支付指令与另一条定单强行配对的攻击，双重签名就是专门防它的（PPT 第 9 页）。 |
| 公开信道 | public channel | 任何人都能窃听、插入、篡改的信道，Internet 就是典型例子。 |

### A.2 不可否认签名与电子现金（第十讲 2–3.3 节）

| 中文 | 英文 | 一句话解释 |
|---|---|---|
| 数字签名 | digital signature | 用私钥产生的、任何持有公钥者都能验证的消息认证数据。 |
| 不可否认签名 ★ | undeniable signature | 只有指定接收者能通过与签名者交互来验证、没有签名者配合就无法向第三方证明的签名（PPT 第 16 页）。 |
| 确认协议 | confirmation protocol | 签名者与验证者交互、证明某个签名确实是自己签的协议（课件算法 3）。 |
| 否认协议 | disavowal protocol | 签名者与验证者交互、证明某个签名是伪造的协议（课件算法 4）。 |
| 签名者 | signer | 产生签名、并在验证时提供交互应答的一方，Chaum–Antwerpen 中记作 A。 |
| 接收者 | recipient | 拿到签名、有权要求签名者配合验证的实体。 |
| 第三方 | third party | 没有参与交互、事后被要求裁定签名真伪的实体；不可否认签名让它无法独自判断。 |
| 勒索 | blackmail | 攻击者以公开签名文件相要挟索取利益；不可否认签名削弱这种威胁（PPT 第 16 页）。 |
| 盲签名 | blind signature | 签名者在看不到消息内容的情况下对消息签名的技术。 |
| 受限盲签名 ★ | restrictive blind signature | 盲签名的一种：签名者虽不知内容，但能保证签出的钱币满足某种结构约束（PPT 第 36 页）。 |
| 盲化 | blinding | 把消息乘上随机因子再送签、事后除掉因子的过程，是盲签名能「盲」的关键动作。 |
| 电子现金 | electronic cash (e-cash) | 用数字形式表示货币、并尽量复制现金匿名性与离线性的支付系统。 |
| 匿名电子现金 | anonymous e-cash | 银行无法把取款记录与后来的存款记录对应到同一个人（PPT 第 33 页）。 |
| 不可追踪性 | untraceability | 任何人（包括银行和警察）都不能把一笔支付关联到用户身份。 |
| 离线支付 | offline payment | 支付时用户不需要与银行实时通信，商家事后才去存款（PPT 第 35 页）。 |
| 可转让 | transferable | 电子现金可以像实物现金一样转手给其他用户。 |
| 可分割 | divisible | 大面额电子现金可以拆成小面额使用，拆分后总额守恒。 |
| 重复花费 ★ | double spending | 同一份电子现金被花两次；防它的思路是「第二次出现时自动暴露身份」。 |
| 欺诈控制 | fraud control | 让伪造与重复花费在事后可被追查、并让骗子暴露身份的整套设计（PPT 第 45–46 页）。 |
| 钱币 | coin | 一份带银行签名的电子现金数据，在 Brands 方案中是一个元组。 |
| 面额 | denomination | 一份钱币代表的金额。 |
| 取款（产生钱币） | withdrawal | 用户从自己账户取出电子现金的过程，其中包含盲化（PPT 第 41–42 页）。 |
| 存款 | deposit | 商家把收到的电子现金提交给银行入账的过程（PPT 第 45 页）。 |
| 离散对数问题 ★ | discrete logarithm problem (DLP) | 已知 $g$ 与 $g^{x}$ 反求 $x$ 的困难问题，是本讲多数协议的安全基石。 |
| $q$ 阶子群 | subgroup of order $q$ | 由一个 $q$ 阶元素生成的循环子群，元素个数少、安全性靠 $q$ 中的离散对数。 |
| 生成元 | generator | 能通过反复自乘生成整个循环子群的元素。 |

### A.3 秘密分享与门限（第十一讲 1–3.3 节）

| 中文 | 英文 | 一句话解释 |
|---|---|---|
| 秘密分享 | secret sharing | 把秘密分成多份交给多人保管、按规则联合才能恢复的方案（第十一讲 1 节）。 |
| 秘密分割 | secret splitting | 最简单的秘密分享：所有碎片合起来才能恢复，缺一片都不行。 |
| 分享 / 影子 | share / shadow | 分给每一个参与者的那一份秘密。 |
| 门限方案 ★ | threshold scheme | 规定「任意 $t$ 份可以恢复、少于 $t$ 份不行」的秘密分享方案（PPT 第 10–11 页）。 |
| $(t,n)$ 门限方案 | $(t,n)$-threshold scheme | $n$ 个分享中任意 $t$ 个就能恢复秘密的方案。 |
| 二重控制 | dual control | 两个分量同时输入设备才能得到完整秘密的控制方式（PPT 第 12 页）。 |
| 一致同意控制 | unanimous consent control | 全部分量到齐才能恢复的控制方式，是 $(t,n)$ 中 $t=n$ 的特例（PPT 第 14 页）。 |
| 模加 | addition modulo $m$ | 把各分量相加再对 $m$ 取余得到秘密的运算。 |
| 异或 | exclusive-or (XOR) | 按位「不同为 1」的运算；两个相同比特异或得 0，是 $\mathbb{Z}_2$ 上的模加。 |
| 可信方 | dealer / trusted party | 负责生成并安全分发分享的实体，必须保证不泄露也不丢失（PPT 第 18 页）。 |
| 多项式插值 | polynomial interpolation | 用 $t$ 个点还原次数小于 $t$ 的多项式。 |
| Lagrange 插值 ★ | Lagrange interpolation | 把插值多项式写成基多项式加权求和的显式公式（PPT 第 20 页）。 |
| Lagrange 基多项式 ★ | Lagrange basis polynomial | 满足 $l_k(x_j)=\delta_{kj}$ 的「只在一点取 1、其余点取 0」的多项式。 |
| Vandermonde 矩阵 | Vandermonde matrix | 由各点的幂次排成的矩阵，其行列式为 $\prod(x_k-x_j)$（补充证明第 2 页）。 |
| 唯一性 ★ | uniqueness | 过 $t$ 个互不相同横坐标点的次数小于 $t$ 的多项式只有一个。 |
| 信息论安全 ★ | information-theoretic security | 不依赖任何计算困难假设、由信息本身决定的安全（PPT 第 16 页）。 |
| 完备秘密分享 | perfect secret sharing | 少于 $t$ 份时秘密在信息论意义上完全不确定的方案。 |
| 公开指标 | public index | 分享对应的横坐标 $x_i$，可以公开而不会泄露秘密。 |
| 预计算常数 | precomputed constant | 只与横坐标有关、与具体分享无关的 Lagrange 系数 $c_i$（PPT 第 21 页）。 |
| 向量方案 | vector scheme (Blakley) | 把秘密编码成 $t$ 维空间的点、每个分享给一个超平面的门限方案（PPT 第 27–32 页）。 |
| 超平面 | hyperplane | $t$ 维空间中一个线性方程的全部解组成的 $(t-1)$ 维平面。 |
| 交点 | intersection point | $t$ 个超平面唯一确定的那个点，其坐标给出秘密。 |
| 骗子 | cheating participant | 提交错误分享、让恢复结果出错的参与者（PPT 第 33 页）。 |
| 可验证秘密分享 | verifiable secret sharing (VSS) | 【补】在分发或恢复阶段就能检测、甚至纠正错误分享的加强版方案。 |
| 承诺 | commitment | 【补】先「封存」一个值、事后再打开以证明自己没改过的机制，是 VSS 与投币的公共工具。 |

### A.4 投币与扑克（第十一讲 4–5 节）

| 中文 | 英文 | 一句话解释 |
|---|---|---|
| 电话投币 | coin flipping by telephone | 双方通过电话或网络公平地产生一个随机比特的协议（PPT 第 37 页）。 |
| 公平投币 ★ | fair coin flipping | 任何一方都不能单方面决定结果、也不能在看到对方选择后反悔的投币。 |
| 二次剩余 | quadratic residue (QR) | 模 $n$ 下能写成某个数的平方的那些数。 |
| 二次非剩余 | quadratic non-residue (QNR) | 模 $n$ 下不能写成平方的那些数。 |
| Blum 整数 ★ | Blum integer | 两个都满足 $p\equiv q\equiv 3\pmod 4$ 的素数之积 $n=pq$，模它开平方恰好有四个根。 |
| 模平方根 | modular square root | 满足 $b^{2}\equiv y\pmod n$ 的 $b$。 |
| 中国剩余定理 | Chinese remainder theorem (CRT) | 由模 $p$ 与模 $q$ 的两个解拼出模 $pq$ 的解（PPT 第 43 页）。 |
| 因子分解困难性 | factoring hardness | 由 $n=pq$ 反求 $p,q$ 在计算上不可行，是投币协议安全的地基。 |
| 猜测获胜 | winning a guess | 投币中猜对 Bob 手里 $x$ 属于哪一对平方根，概率恰为 $1/2$。 |
| 电话扑克 | telephone poker | 双方不见面却要公平发牌的协议（PPT 第 47–49 页）。 |
| 发牌 | dealing | 把 52 张牌分配给双方的整个过程。 |
| 洗牌 | shuffle | 打乱牌的顺序，使对方无法从密文的排列推断牌面。 |
| 牌面编码 | card encoding | 用模 $p$ 的幂 $g^{k}$ 表示每张牌，使加密运算可以交换次序（PPT 第 50 页）。 |
| 可交换加密 ★ | commutative encryption | 两次解密（或加密）的先后次序可以互换的加密，电话扑克靠它让双方各自加密的牌仍能解开。 |
| 揭示密钥 | revealing keys | 牌局结束后双方公布自己的密钥，以便互相检查没人换牌（PPT 第 49 页）。 |
| 作弊检测 | cheat detection | 用一致性等式或二次剩余判别检查对方有没有偷偷换牌。 |
| 安全参数 | security parameter | 决定密钥长度或交互轮数、从而决定安全强度的整数（PPT 第 28 页）。 |

### A.5 零知识证明与鉴别协议（第十二讲 1–5 节）

| 中文 | 英文 | 一句话解释 |
|---|---|---|
| 零知识证明 ★ | zero-knowledge proof | 让验证者相信「我知道这个秘密」，却不在过程中泄露秘密本身的交互证明。 |
| 交互证明系统 | interactive proof system | 证明者与验证者多轮问答、验证者最后接受或拒绝的证明模型（PPT 第 10 页）。 |
| 证明者 | prover | 声称掌握某个知识、并回答挑战的一方，本讲记作 A 或 Peggy。 |
| 验证者 | verifier | 发出随机挑战并检查回答的一方，本讲记作 B 或 Victor。 |
| 完备性 | completeness | 诚实的证明者与验证者执行协议，一定（或以压倒概率）被接受（定义 1）。 |
| 正确性 ★ | soundness | 不掌握秘密的冒充者无法以不可忽略的概率让验证者接受（定义 2）。 |
| 零知识性 ★ | zero-knowledge property | 存在模拟器能生成与真实交互不可区分的记录，因此交互不泄露额外信息（定义 3）。 |
| 模拟器 ★ | simulator | 不知道秘密却能伪造出「看起来一模一样」的交互记录的算法。 |
| 不可区分 | indistinguishable | 两个分布用任何多项式时间算法都分不开。 |
| 分割选择技术 | cut and choose | 一方把东西等分成两半、另一方先选，从而保证公平的手法（PPT 第 9 页）。 |
| 承诺—挑战—应答 ★ | commit–challenge–response | 三次交互的一般结构：先发证据，再收随机挑战，最后作答（PPT 第 19 页）。 |
| 挑战 | challenge | 验证者发出的随机问题，通常是一个比特或一个向量。 |
| 应答 | response | 证明者根据挑战算出的答案。 |
| 冒充 | impersonation | 攻击者假扮合法用户；成功率随交互轮数指数下降。 |
| 身份鉴别 | identification | 证明「我是谁」而不出示口令的协议。 |
| Fiat–Shamir 协议 | Fiat–Shamir identification protocol | 基于模平方根、每轮只有一个比特挑战的鉴别协议（PPT 第 23–27 页）。 |
| Feige–Fiat–Shamir（FFS） | Feige–Fiat–Shamir | 把每轮挑战扩展成 $k$ 比特向量、每轮安全水平 $2^{-k}$ 的加强版（PPT 第 28–36 页）。 |
| GQ 协议 | Guillou–Quisquater protocol | 基于 RSA 的零知识鉴别，挑战范围是 $1\le e\le v$，每轮冒充成功率 $1/v$（PPT 第 37–43 页）。 |
| Schnorr 协议 | Schnorr identification protocol | 基于离散对数、应答在模 $q$ 下计算、可预计算的鉴别协议（PPT 第 44–51 页）。 |
| 冗余身份 | redundancy function | 把公开身份 $I_A$ 映射成模 $n$ 元素 $J_A=f(I_A)$ 的公开函数（PPT 第 38 页）。 |
| 证书 | certificate | 可信中心签署的、把身份与公开密钥绑定的数据，Schnorr 中记作 $cert_A$。 |
| 可信中心 | trusted center | 建立系统参数、签发证书的权威方，本讲记作 T。 |
| Fiat–Shamir 启发式 ★ | Fiat–Shamir heuristic | 用 $e=H(x\parallel m)$ 代替验证者的随机挑战，把交互鉴别变成数字签名（PPT 第 36、51 页）。 |
| 非交互签名 | non-interactive signature | 不需要验证者在线的签名，由上述启发式变换得到。 |
| 选择消息攻击 | chosen-message attack | 攻击者能拿到自己挑选的消息的签名来收集信息的攻击模型；零知识协议的不退化性可阻止它（PPT 第 21 页）。 |
| 不退化 ★ | non-degeneracy | 协议可以反复使用而不因重复而降低安全性（PPT 第 21 页）。 |
| 并行执行 / 串行执行 | parallel / sequential execution | 把多轮协议的多份执行同时跑以减少通信轮数，或一轮接一轮地跑。 |

### A.6 最容易混淆的十组术语（建议对照背诵）

| 易混对 | 区别要点 |
|---|---|
| 双重签名 vs 普通数字签名 | 普通签名只绑定一条消息；双重签名绑定两条消息，且让每条消息的持有者只能验证自己那一半（第十讲 1.2.3 节）。 |
| 加密 $E$ vs 解密 $D$ | $E$ 用公开密钥、谁都能做；$D$ 用私有密钥、只有本人能做。RSA 中「用 $D$ 作用在摘要上」才是签名。 |
| 不可否认签名 vs 普通签名 | 普通签名可被无限复制、人人可验；不可否认签名必须签名者配合才能验证，因此无法被拿到第三方去传播。 |
| 确认协议 vs 否认协议 | 确认证明「这个签名是我签的」；否认证明「这个签名是伪造的」。二者都是签名者与验证者的交互。 |
| 秘密分割 vs 门限方案 | 秘密分割要求「全部到齐」；门限方案允许「任意 $t$ 个」就够，是更灵活的推广（第十一讲 2–3 节）。 |
| 二重控制 vs 一致同意控制 | 二重控制是 $t=2$ 的特例；一致同意控制是 $t=n$ 的特例，二者都是 $(t,n)$ 门限方案的实例（PPT 第 17 页）。 |
| Shamir 方案 vs 向量方案 | 一个用「多项式的点」，一个用「超平面的交点」；安全性都来自 $t$ 个约束唯一确定解，但存储开销不同。 |
| 完备性 vs 正确性 | 完备性保护**诚实证明者**不被误拒；正确性保护**验证者**不被冒充者欺骗。两者方向相反，缺一不可。 |
| 零知识性 vs 正确性 | 零知识性说「不泄露额外信息」；正确性说「没秘密就骗不过去」。零知识性本身**不保证**协议安全（PPT 第 18 页）。 |
| Fiat–Shamir vs FFS | 前者每轮一个比特挑战、公开值 $v\equiv s^{2}$；后者每轮 $k$ 比特向量、公开值 $v_i\equiv s_i^{-2}$（指数上是**逆**）。 |

### A.7 三条背诵路线

如果只有半小时复习，按下面三条路线走，能把全册术语串成一条线：

1. **「给签名加功能」这条线**（第十讲）：数字签名 → 双重签名（加连接与分离）→ 不可否认签名（加访问控制）→ 盲签名与电子现金（加匿名）。每个新词都是在「普通签名做不到什么」这个问句上长出来的。
2. **「把秘密切开」这条线**（第十一讲）：秘密分割 → 二重控制 → 一致同意控制 → 门限方案 → Shamir（多项式）与 Blakley（超平面）→ 有骗子时怎么办。最后一跳是「用秘密分享做游戏」：投币与扑克。
3. **「只证明知道、不交出秘密」这条线**（第十二讲）：零知识 → 交互证明三性质 → 承诺—挑战—应答 → 四条协议按「难题」分类：模平方根（Fiat–Shamir、FFS）、RSA（GQ）、离散对数（Schnorr）→ Fiat–Shamir 启发式变成签名。

把每条线上的词按顺序复述一遍，再回表格里核对英文与一句话解释，附录 A 就算过关了。
