### 从"算法"到"协议"：语言要换一套

前一节讲的是困难问题，那是"算法层"的语言。从这一节开始进入本册真正的主场：**协议**（protocol）。两者的差别可以用一张表说清：

| 维度 | 算法 | 协议 |
|---|---|---|
| 参与方 | 一个 | 两个或更多（Alice、Bob、Carol……） |
| 执行方式 | 一次调用，输入输出 | 多轮消息往来，每轮依赖上一轮 |
| 对手 | 只关心"破解计算" | 还要关心"参与方偏离剧本作弊" |
| 安全目标 | 机密性、不可伪造 | 正确性、隐私、公平、可验证 |
| 典型产物 | 密文、签名 | 一次交易、一份分享、一次鉴别 |

**翻译成人话**：算法是一个人的手艺，协议是一群人的规矩；手艺再好，也管不住有人不守规矩。

协议里出现的角色，本册固定用这几个名字：

- **参与方**：Alice（$A$）、Bob（$B$）、Carol（$C$）。课件里的持卡人、商家、银行、证明者、验证者都是它们的具体化。
- **攻击者**：Eve（窃听者，被动）、Mallory（主动篡改者）。本册多数协议假设攻击者能**读、改、插、删**所有消息。
- **可信第三方**（trusted third party，TTP）：所有人都信任的裁判。有它协议会简单很多，但现实里往往没有——电子现金想摆脱银行实时在线、电话投币想摆脱裁判、零知识想摆脱中心，本册很多设计就是在"去掉 TTP"。
- **对手模型**：被动窃听（passive）、半诚实（honest-but-curious，遵守协议但偷看）、恶意（malicious，可以任意偏离）。【补】模型不声明，安全就无从谈起：同一个协议在"半诚实"下安全，在"恶意"下可能被秒破。

### 比特承诺：先封存，后揭晓

**比特承诺**（bit commitment）是本册最基础的"原子操作"，几乎所有防作弊协议都用到它。生活里的对应物是：把写着答案的纸条装进信封、封好、交给对方；等时机到了再一起拆开。

一个承诺方案要同时满足三条：

1. **隐藏性**（hiding）：在揭晓之前，接收方无法知道承诺的是 $0$ 还是 $1$；
2. **绑定性**（binding）：承诺者事后不能把 $0$ "改成" $1$；
3. **正确性**（correctness）：诚实揭晓时，接收方一定能验证通过。

**为什么不能只发一个明文摘要？** 假设承诺者直接发 $C=H(m)$，$m\in\{0,1\}$。接收方只要算一次 $H(0)$、一次 $H(1)$，就知道 $C$ 对应哪个——**隐藏性没了**。所以必须加一个随机"盐"（salt）：

$$C=H(r\lVert m)$$

**翻译成人话**：把随机数 $r$ 和消息 $m$ 拼起来再做 Hash；$r$ 有足够多的可能取值，对方无法穷举出 $C$ 对应哪个 $m$。揭晓时承诺者交出 $(m,r)$，接收方重算 $H(r\lVert m)$ 与 $C$ 比对。

**手算一个"玩具承诺"**（用 $H_{\mathrm{toy}}(u)=u^{2}\bmod 77$ 代替真实 Hash，只为看清机制）：

- 承诺 $m=1$：取 $r=200$，拼成 $u=256\times1+200=456$，$C=456^{2}\bmod 77$。$456^{2}=207936$，$207936=2700\times77+36$，所以 $C=36$。
- 揭晓：交出 $(m=1,r=200)$，接收方算 $456^{2}\bmod77=36$，与 $C$ 相等，接受。

**翻译成人话**：承诺值 $C$ 像一个"封好的信封"；揭晓就是当众拆封、重算一遍核对。

**但这个玩具方案不满足绑定性**。因为 $H_{\mathrm{toy}}$ 太弱：$36$ 在模 $77$ 下有四个原像 $\{6,27,50,71\}$。于是承诺者可以用 $(m=0,r=6)$ 来开同一个 $C=36$（$6^{2}=36$），把 $0$ 说成 $1$。

**翻译成人话**：信封能用两种方式拆开，绑定性就没了；真实的承诺必须用**抗碰撞的密码学 Hash**（如 SHA-256），让"同一个 $C$ 对应两组不同的 $(m,r)$"在计算上找不到。

把承诺的"隐藏 + 绑定"与它的用途连起来看：

| 场景 | 承诺什么 | 为什么必须承诺 |
|---|---|---|
| 电话投币 | Alice 先把 $n$ 与二次剩余 $x$ 交给 Bob，Bob 必须先"猜"一个根 | 若 Bob 等 Alice 揭晓后再猜，他就必胜 |
| 电话扑克 | 双方先承诺自己的密钥 | 事后才能用公布的密钥验证"没人换牌" |
| 零知识证明 | 证明者先发 $x\equiv r^{2}$（对随机数 $r$ 的"承诺"） | 承诺锁死了 $r$，之后只能对一种挑战答对 |
| 存在骗子的秘密分享 | 参与者先公布分享的 Hash 摘要 | 事后可查出谁交了假分享 |

**翻译成人话**：承诺的本质是"**现在锁定、以后揭晓**"；所有"防止事后反悔"的协议，第一步几乎都是承诺。

### 盲化：签名者签了名，却不知道签了什么

**盲化**（blinding）是另一个高频动作，它解决的问题是：**Alice 要 Bob 的签名，但不想让 Bob 知道被签的内容**。生活里的对应物是"把文件装进带复写纸的信封，让 Bob 在信封外面签字"——签完之后，Bob 的笔迹落在里面那张纸上，但他从没看过内容。

以 RSA 盲签名（blind signature）为例，手算一遍（$n=33$、$e=3$、$d=7$，要签的消息 $m=5$，盲因子 $r=2$）：

1. **盲化**：请求者算 $m'=m\cdot r^{e}\bmod n$，把 $m'$ 交给签名者。手算：$r^{e}=2^{3}=8$，$m'=5\times8=40\equiv7\pmod{33}$。
2. **签名**：签名者对 $m'$ 正常签名，$\sigma'=(m')^{d}\bmod n$。手算：$7^{7}\bmod33$：$7^{2}=49\equiv16$，$7^{4}\equiv16^{2}=256\equiv25$，$7^{7}\equiv25\times16\times7=2800\equiv28\pmod{33}$。
3. **去盲**：请求者算 $\sigma=\sigma'\cdot r^{-1}\bmod n$。手算：$r^{-1}=2^{-1}\equiv17\pmod{33}$（$2\times17=34\equiv1$），$\sigma=28\times17=476\equiv14\pmod{33}$。
4. **验证**：任何人算 $\sigma^{e}\bmod n$。手算：$14^{3}=2744=83\times33+5\equiv5$，等于 $m$，签名有效。

**翻译成人话**：请求者把消息"乘以一个随机数再取模"，签名者看到的是 $7$（他并不知道真实消息是 $5$），却仍然签出了一个对 $5$ 有效的签名；去掉盲因子后，签名就"落"回了原消息上。

为什么签名者无法把"签过的 $7$"和"后来的 $5$"对上号？因为 $r$ 是随机选的，$m'=m\cdot r^{e}$ 在签名者眼里与一个随机数没有区别。**这就是电子现金匿名性的来源**：银行在取款时签的是"盲化后的钱币序列号"，事后商家来存款时银行看到的序列号与取款记录对不上（详细机制见第十讲 3.3 节 Brands 方案）。

三个容易混淆的动作，用一张表分开：

| 动作 | 目的 | 典型式子 | 谁知道内容 |
|---|---|---|---|
| 加密 | 防偷看 | $c=E(m)$ | 有私钥的人 |
| 哈希 | 压缩 + 防篡改 | $h=H(m)$ | 谁都能算，但反推不出 $m$ |
| 承诺 | 先锁定、后揭晓 | $C=H(r\lVert m)$ | 承诺者；接收方揭晓后知道 |
| 盲化 | 让签名者"隔层"签 | $m'=m\cdot r^{e}$ | 请求者；签名者看不到 $m$ |

**翻译成人话**：加密是"不给看"，承诺是"现在不给看、以后给看"，盲化是"给签但不给看"。

### 交互与挑战-应答

**交互式证明**（interactive proof）是本册后半段的主角：证明者（prover，$A$）与验证者（verifier，$B$）来回多轮，最后 $B$ 决定"接受"还是"拒绝"。它和数学证明最大的区别是：**交互证明是随机的、概率的**，所以结论写成"以压倒概率接受"。

几乎所有零知识协议都长成"承诺—挑战—应答"的三轮结构：

```
   证明者 A                          验证者 B
      │  ① 承诺：发一个精心构造的数 x     │
      │ ─────────────────────────────▶ │
      │                                │  ② 挑战：随机问一个问题 b
      │ ◀───────────────────────────── │
      │  ③ 应答：用秘密算出 y 发回去      │
      │ ─────────────────────────────▶ │
      │                                │  ④ 验证：代入公式检查
```

**翻译成人话**：$A$ 先"把牌扣在桌上"（承诺），$B$ 随机指定要哪一张（挑战），$A$ 只能照做（应答）；由于 $B$ 的挑战是在承诺之后才产生的，$A$ 无法提前准备一个能同时应付所有挑战的答案。

三个性质在本册会被正式定义（详见第十二讲 1.2 节），这里先给直觉：

- **完备性**（completeness）：诚实的 $A$ 面对诚实的 $B$，一定能让 $B$ 接受。
- **可靠性**（soundness，课件译作"正确属性"）：不掌握秘密的骗子，无法让 $B$ 接受（除非碰巧猜中挑战）。
- **零知识性**（zero-knowledge）：$B$ 从交互记录里学不到任何关于秘密的新信息——判据是存在一个**模拟器**（simulator），它不需要秘密就能生成一份与真实记录不可区分的"录像"。

**手算一个 Fiat–Shamir 三轮交互**（$n=77$，$s=5$ 是秘密，$v=s^{2}=25$ 公开）：

1. $A$ 选随机数 $r=9$，发承诺 $x=r^{2}=81\equiv4\pmod{77}$；
2. $B$ 随机挑战 $b=1$（只可能是 $0$ 或 $1$）；
3. $A$ 应答 $y=r\cdot s^{b}=9\times5=45\pmod{77}$；
4. $B$ 验证 $y^{2}\equiv x\cdot v^{b}$：左边 $45^{2}=2025=26\times77+23\equiv23$，右边 $4\times25=100\equiv23$，两边相等，接受。

**翻译成人话**：$A$ 用秘密 $s$ 把随机数 $r$ "绑"到承诺 $x$ 上；$B$ 只随机问一个比特，$A$ 每次都能答对，但骗子只有 $1/2$ 的机会答对。

【补】**为什么"猜中挑战"的概率决定了安全性**：骗子若提前知道 $b$，就能针对性地伪造；所以 $B$ 必须在看到承诺之后才选 $b$。每轮猜中概率 $1/2$，$k$ 轮独立执行后是 $2^{-k}$；这正是本册所有鉴别协议的"安全旋钮"。另外，若把挑战换成 $e=H(x\lVert m)$（Hash），协议就变成**非交互**的签名方案——这就是 Fiat–Shamir 启发式（Fiat–Shamir heuristic），第十二讲第 5 节用它把 Schnorr 鉴别协议变成 Schnorr 签名。

### 三讲共用的词汇表：把"大概"变成"精确"

本册三讲反复出现一批术语，而它们的日常含义与密码学含义经常不同。下面这张表是后面每一讲都要回来查的。

| 术语 | 精确含义 | 最容易混的点 |
|---|---|---|
| **匿名性**（anonymity） | 从记录中看不出"是谁" | 匿名 ≠ 无法追踪；匿名者仍可能被关联分析认出 |
| **不可追踪 / 不可连接**（unlinkability） | 无法把两次行为（如取款与花钱）关联到同一个人 | 电子现金要的是这一条，比"匿名"更强 |
| **不可伪造**（unforgeability） | 没有私钥就造不出新的合法签名 | 与"不能篡改已有签名"是两件事（后者由完整性保证） |
| **不可否认**（non-repudiation） | 签名者事后不能抵赖"这不是我签的" | **这是普通签名的性质** |
| **不可否认签名**（undeniable signature） | 没有签名者配合，接收者无法向第三方证明签名有效 | **方向相反**：签名者反而可以"否认" |
| **公平性**（fairness） | 协议结束时结果已定，任何一方不能单方面反悔或偷看 | 电话投币、电话扑克的核心要求 |
| **完备性**（completeness） | 诚实的双方跑完协议必成功 | 零知识三性质之一 |
| **可靠性**（soundness） | 骗子无法让验证者接受 | 课件第十二讲译作"正确属性"，指同一个东西 |
| **零知识**（zero-knowledge） | 交互记录可由模拟器单独生成 | 零知识 ≠ 协议安全（可能以别的方式泄密） |
| **模拟器**（simulator） | 不需要秘密就能造出不可区分记录的算法 | 证明零知识的工具，不是真实参与方 |
| **可信第三方**（TTP） | 所有人信任的裁判 | 有它一切都简单；本册很多协议的目标是去掉它 |

【补】**最值得单独记住的一对词：non-repudiation 与 undeniable signature。** 普通数字签名提供的是"不可否认"：签了就跑不掉，谁都能验证。不可否认签名提供的是"可控认证"：只有指定接收者能确认签名有效，没有签名者配合，接收者无法向第三方证明——**所以签名者获得了"否认"的能力**。这两个词中文都带"不可否认"，含义却几乎相反，是本册最容易被问倒的一处。

### 怎么读后面那些"算法框"

课件第十讲到第十二讲有大量算法框（算法 1、算法 2……协议 1、协议 2……），初读容易晕。用下面三步去读，每个框都能拆开：

1. **谁发给谁**：先看每一行开头的主语；协议的"信息流"通常是一条链（持卡人 → 商家 → 银行 → 商家 → 持卡人）。
2. **每一步在算什么**：把式子里的每个量标上"公开/秘密/随机"三种身份，秘密只在持有者那一步出现。
3. **最后怎么验证**：每个协议都有一句"如果……则接受/拒绝"；找到那个等式，它就是整个协议的安全支点。

**举例**：Fiat–Shamir 的验证式是 $y^{2}\equiv x\cdot v^{b}\pmod n$。按三步读：$x$ 是 $A$ 发的（公开）、$y$ 是 $A$ 回的（公开）、$v$ 是公开密钥、$b$ 是 $B$ 的随机挑战；验证式说的其实是"$A$ 的应答必须同时对上承诺 $x$ 与公钥 $v$"，而只有知道 $s$（满足 $v\equiv s^{2}$）的人才能对两种 $b$ 都答对。

**翻译成人话**：读协议不要从第一行背到最后一行，而要问三个问题——谁在发、发的东西是公开还是秘密、最后那个等式凭什么能卡住骗子。

### 本节要点

1. 协议 = 多方 + 多轮 + 对手模型；与算法的根本差别是"要防参与方自己作弊"。
2. 比特承诺 = 先锁后揭，靠"随机盐 + 抗碰撞 Hash"同时做到隐藏与绑定；只发 $H(m)$ 会被穷举。
3. 盲化让签名者"隔层签名"：$m'=m r^{e}$ → $\sigma'=(m')^{d}$ → $\sigma=\sigma' r^{-1}$，得到对 $m$ 有效的签名而签名者不知道 $m$。
4. 交互证明的骨架是"承诺—挑战—应答"，三条性质是完备性、可靠性、零知识性；每轮猜中概率 $1/2$，$k$ 轮压到 $2^{-k}$。
5. 术语要精确：匿名 ≠ 不可追踪；non-repudiation（普通签名的性质）与 undeniable signature（签名者可否认）方向相反。

### 自测题

1. 为什么承诺不能只发 $C=H(m)$？加盐之后，隐藏性和绑定性分别由什么保证？
2. 用 $n=33$、$e=3$、$d=7$、$m=4$、盲因子 $r=5$ 走一遍盲签名（提示：$5^{3}=125\equiv26$，$5^{-1}\equiv20\pmod{33}$）。
3. Fiat–Shamir 中把挑战 $b$ 换成 $b\in\{0,1,2,3\}$（四选一），每轮作弊成功率是多少？跑 $10$ 轮后是多少？
4. 区分：普通数字签名的"不可否认"与"不可否认签名"，各是谁获得了什么能力？
5. 一个协议若满足完备性与可靠性，是否就等于"零知识"？反过来呢？各举一个反例或说明理由。

<details><summary>答案</summary>

1. 只发 $H(m)$ 时，接收方可以穷举 $m\in\{0,1\}$ 的两个 Hash 值直接比对，隐藏性失效。加盐后 $C=H(r\lVert m)$：隐藏性来自 $r$ 的取值空间足够大（无法穷举出对应哪个 $m$）；绑定性来自 $H$ 的抗碰撞性（找不到两组 $(m,r)$ 给出同一个 $C$）。
2. 盲化：$m'=m r^{e}=4\times26=104\equiv5\pmod{33}$。签名：$\sigma'=(m')^{d}=5^{7}$：$5^{2}=25$，$5^{4}=625\equiv31$，$5^{7}\equiv31\times25\times5=3875$，$3875=117\times33+14$，故 $\sigma'=14$。去盲：$\sigma=\sigma'\cdot r^{-1}=14\times20=280\equiv16\pmod{33}$（$280-264=16$）。验证：$16^{3}=4096=124\times33+4\equiv4=m$。
3. 四选一时每轮猜中概率 $1/4$，跑 $10$ 轮是 $4^{-10}=2^{-20}\approx9.5\times10^{-7}$——还落在"百万分之一"的量级，实际系统需要更多轮或更大的挑战空间。
4. 普通签名：签名者获得的是"无法否认自己签过"的约束（验证者/任何人有能力验证，所以签名者赖不掉）。不可否认签名：签名者获得"没有我配合，别人无法验证"的能力，即获得了**否认**的可能；接收者必须求签名者参与确认协议。
5. 都不等。完备性 + 可靠性只说明"诚实的能过、骗子过不了"，完全没有约束"泄露多少"——一个直接把秘密发给验证者的协议也满足前两条，却毫无零知识可言。反过来，零知识性只说明"不泄露"，不保证"骗子过不了"（课件第十二讲明确评述：零知识属性本身不保证协议安全）。
