### 2.1 使用模加的二重控制

#### 2.1.1 方案原文：两个人各拿一半

（PPT 第 12 页）课件把场景写得很具体：

> 如果一个秘密数字 $S$，$0\le S\le m-1$，这里 $m$ 是某个整数，必须输入到设备（例如，一个种子密钥），但是由于操作的原因，不希望任何单独个人（除可信第三方以外）知道这个数字，则可以使用如下方案。一个可信第三方产生一个随机数 $1\le S_1\le m-1$，并将数值 $S_1$ 和 $S-S_1\ (\mathrm{mod}\ m)$ 分别交给实体 $A$ 和 $B$。$A$ 和 $B$ 分别将他们的数值输入设备，它们之和模 $m$ 即可恢复出 $S$。

把方案写成三步，并用记号 $S_2$ 表示交给 $B$ 的那一份：

1. **分发**：可信第三方 $T$ 在 $\{0,1,\dots,m-1\}$ 上均匀随机取一个数 $S_1$，计算

$$S_2\equiv S-S_1\pmod{m},\qquad 0\le S_2\le m-1 .$$

**翻译成人话**：$S_2$ 就是「$S$ 减去随机数之后剩下的那部分」，为了让它落在 $0$ 到 $m-1$ 之间，减法要在模 $m$ 意义下做（如果减成负数就加 $m$）。

2. **持有**：$A$ 得到 $S_1$，$B$ 得到 $S_2$。两人各持一个数，谁也不掌握另一个。
3. **恢复**：两人同时把数值输入设备，设备算

$$S\equiv S_1+S_2\pmod{m}.$$

**翻译成人话**：设备把两个数加起来再对 $m$ 取余，$S$ 就出来了。注意这一步没有任何「解密」动作，只是加法——安全性完全来自「$S_1$ 是随机数，所以 $S_2$ 也是随机数」这一点。

```
   二重控制（PPT 第 12 页）的信息流向
                    ┌────────────────────┐
                    │  可信第三方 T      │
                    │  知道 S；掷随机数 S_1 │
                    └───────┬────────────┘
             S_1            │            S_2 = S - S_1 (mod m)
        ┌───────────────────┴───────────────────┐
        ▼                                       ▼
   ┌─────────┐                             ┌─────────┐
   │ 实体 A  │                             │ 实体 B  │
   │ 只知 S_1 │                             │ 只知 S_2 │
   └────┬────┘                             └────┬────┘
        │           同时输入设备                  │
        └──────────────┬─────────────────────────┘
                       ▼
              ┌──────────────────┐
              │  设备：S_1 ⊕ S_2  │  ← 这里的 ⊕ 表示「模 m 相加」
              │  = S - S_1 + S_1  │
              │  = S  (mod m)     │
              └──────────────────┘
```

**手算一个例子**（取 $m=10$，$S=7$）。第三方掷出 $S_1=3$，则

$$S_2\equiv 7-3\equiv 4\pmod{10},\qquad A\ \text{拿}\ 3,\ B\ \text{拿}\ 4 .$$

恢复时 $3+4=7$，恰好是 $S$。再试一组：掷出 $S_1=8$，则 $S_2\equiv 7-8\equiv -1\equiv 9\pmod{10}$，恢复时 $8+9=17\equiv 7\pmod{10}$。

**翻译成人话**：不管随机数取几，两人手里的数加起来都对 $m$ 同余于 $S$；而单看任何一个数，它就是一个完全随机的数。第三方每做一次分发就重新掷一次随机数，所以每次得到的两个份额都不同。

#### 2.1.2 为什么单个份额「没有信息」

安全性要单独论证，不能只靠直觉。假设攻击者只知道 $S_1$，想要猜 $S$。对任意候选值 $S'$，都存在唯一一个「配套」的第二份额

$$S_2'\equiv S'-S_1\pmod{m},$$

使得 $(S_1,S_2')$ 是一份合法的二重控制分割。于是每个候选值都「说得通」：

$$\Pr\big[S=S'\ \big|\ S_1\big]=\frac{1}{m},\qquad S'\in\{0,1,\dots,m-1\}.$$

**翻译成人话**：拿着 $S_1$ 去猜 $S$，与闭着眼睛瞎猜的成功率一模一样，都是 $1/m$。这就是「份额单独没有信息」的严格含义——不是「难猜」，而是**后验分布没变**。

（PPT 第 13 页）课件的评述与此一致：

> (1) 如果可以相信 $A$ 和 $B$ 不存在串谋，则没有人知道任何 $S$ 的信息，这是由于两人拥有的只是在 $0$ 到 $m-1$ 之间的一个随机数。
> (2) 这是知识分割方案的例子，其将对秘密 $S$ 的知识在两个人之间做分割。任何对秘密 $S$ 的操作可以看作二重控制——需要两人共同触发。

第 (2) 条给出了这个方案的名字与用途：**知识分割（knowledge splitting）**，以及它的操作含义——**二重控制（dual control）**。「二重」强调的不是「有两个人」，而是「必须**同时**由两人触发」。这正是第十一讲第 4 节（电话投币协议）、以及现实中的「双人复核」「双钥匙保险柜」的数学模型：

| 场景 | 单方能做什么 | 双方同时在场才能做什么 |
|---|---|---|
| 双钥匙保险柜 | 打开自己那把锁 | 打开柜子取物 |
| 发射控制器 | 插一把钥匙 | 触发发射 |
| 二重控制方案 | 拿到 $S_1$，猜 $S$ 的成功率 $1/m$ | 输入 $S_1$ 与 $S_2$，得到 $S$ |

【补】**课件把 $S_1$ 的范围写成 $1\le S_1\le m-1$，实现时应当改成 $0\le S_1\le m-1$。** 原因有两条：
（1）若排除 $0$，那么「$S_2$ 与 $S$ 不相等」就成了一个公开可知的事实——$B$ 拿着 $S_2$ 就能推断「$S\ne S_2$」，虽然只排除掉一个候选值，但已经不是严格意义下的零信息；
（2）更严重的退化出现在 $m=2$（即逐比特操作）时：此时 $S_1$ 唯一可能取值是 $1$，$B$ 拿到 $S_2=S-1$ 就直接算出 $S$，方案完全失效。
所以正确的取值区间是全体 $0\le S_1\le m-1$，这样 $S_2$ 才是真正的均匀随机数。1.1.2 节那个「随机比特 + 异或」的例子用的就是这个规范形式。

### 2.2 使用模加的一致同意控制

#### 2.2.1 从两人推广到 t 人

（PPT 第 14 页）课件把二重控制直接推广：

> 二重控制方案很容易加以推广，将秘密 $S$ 分割给 $t$ 个用户，只有全部用户参与才能恢复 $S$。方法如下：可信第三方 $T$ 产生 $t-1$ 个相互独立的随机数 $S_i$，$0\le S_i\le m-1$，$1\le i\le t-1$。$S_1$ 到 $S_{t-1}$ 分别交给实体 $P_1$ 到 $P_{t-1}$，每人一个。实体 $P_t$ 得到 $S_t=S-\sum_{i=1}^{t-1}S_i\ (\mathrm{mod}\ m)$。秘密可以通过 $S=\sum_{i=1}^{t}S_i\ (\mathrm{mod}\ m)$ 恢复。

写成公式就是：

$$S_t\equiv S-\sum_{i=1}^{t-1}S_i\pmod{m},\qquad S\equiv\sum_{i=1}^{t}S_i\pmod{m}.$$

**翻译成人话**：前 $t-1$ 个人各拿一个纯随机数，最后一个人拿的是「凑数的那一块」——用 $S$ 减去前面所有人份额之和，剩下的差额全给他。恢复时把 $t$ 个数加起来，前面那些随机数两两抵消，只剩 $S$。

为什么「凑数的那一块」必须交给最后一个人，而不是随便谁？因为它的值是**被其他份额算出来的**，一旦提前固定了它，其他人的份额就无法保持独立随机。**最后一个份额是「因变量」，前 $t-1$ 个是「自变量」。**

**手算一个例子**（$m=100$，$S=42$，$t=3$）。第三方掷出 $S_1=13$、$S_2=57$，则

$$S_3\equiv 42-(13+57)\equiv 42-70\equiv -28\equiv 72\pmod{100}.$$

恢复时 $13+57+72=142\equiv 42\pmod{100}$，与 $S$ 一致。

**翻译成人话**：三个人各拿 $13$、$57$、$72$，单看任何一个都是 $0$ 到 $99$ 里的一个随机数；只有三个数同时输入设备，加起来对 $100$ 取余才是 $42$。

```
   一致同意控制（PPT 第 14 页，t = 3 的情形）
                 ┌─────────────────────────┐
                 │   T：掷 S_1, S_2（独立随机）│
                 │   算 S_3 = S - S_1 - S_2   │
                 └───┬─────────┬─────────┬───┘
                     ▼         ▼         ▼
                ┌────────┐┌────────┐┌────────┐
                │  P_1   ││  P_2   ││  P_3   │
                │  13    ││  57    ││  72    │
                └───┬────┘└───┬────┘└───┬────┘
                    └─────────┼─────────┘
                              ▼
                 ┌──────────────────────────┐
                 │ 13 + 57 + 72 = 142 ≡ 42    │
                 │ 全部到齐才能触发 → 一致同意 │
                 └──────────────────────────┘
   少任何一个人：剩下的两个份额加起来是随机数，无法定出 S。
```

#### 2.2.2 这个方案的强度与代价

（PPT 第 15 页）课件给出两条评述，第 (2) 条尤其重要：

> (1) 本方案和二重控制方案的模 $m$ 操作都可以由异或操作替代，其中使用的数值 $S$ 和 $S_i$ 都是固定 $\log_2 m$ 比特长度。
> (2) 在一个分割控制方案中，个人的秘密应该是完全长度的。与分割一个 $r$ 比特秘密为 $t$ 份每份 $r/t$ 比特相比，这将提供更好的安全强度。例如，$r=56$ 和 $t=2$，如果两个实体各得到秘密的 28 比特，每个实体穷举搜索都只需要做 $2^{28}$ 次测试，然而，如果每个实体得到一个 56 比特的数据，则需要进行 $2^{56}$ 次测试。

第 (2) 条讲的是一种**极其常见的错误实现**，值得单独摊开。假设有人想「简单地」把一个 56 比特的密钥对半分：前 28 比特给 $A$，后 28 比特给 $B$。这看起来也是「两个人合起来才能用」，但安全性完全崩了：$A$ 拿着前 28 比特，只要枚举后 28 比特的 $2^{28}$ 种可能，就能试出完整密钥。

正确做法的两个份额**各自都是 56 比特**，攻击者拿着任意一份，穷举另一份的工作量是

$$2^{56}\ \text{次}.$$

**翻译成人话**：分半法把搜索空间从 $2^{56}$ 砍到 $2^{28}$（一把就破），而模加法给出的份额不会砍任何空间——每个份额本身都占满 $56$ 比特，且是纯随机的。代价是：**总存储量翻倍了**（$2$ 份 × 56 比特 > 1 份 × 56 比特）。安全的提升就是这么换来的。

把安全性度量写成一个可以随手估算的式子。若 $m=2^{k}$，即每个份额占 $k$ 比特，则只拿到一份的攻击者猜中 $S$ 的概率是

$$\Pr[\text{一次猜中}]=\frac{1}{m}=\frac{1}{2^{k}}.$$

**翻译成人话**：$k=56$ 时成功率是 $2^{-56}$（约 $1.4\times 10^{-17}$，可以忽略）；若按「分半法」把份额缩到 $k/2=28$ 比特，成功率立刻升到 $2^{-28}$（约 $3.7\times 10^{-9}$，在真实的在线猜测攻击里已经不够看了）。**「一次猜测成功概率」是衡量分割控制方案强度的统一标尺**，后面第十一讲 3.1 节的门限方案也可以用同一把尺子去衡量。

#### 2.2.3 用异或实现：243 的具体例子

（PPT 补充证明第 1 页）课件在补充材料里给了一个逐比特的实例，正好把「模 $m$ 换成异或」这句话落到实处。原始数据是

$$S=243=(11110011)_2,\qquad S_1=159=(10011111)_2,\qquad S_2=69=(01000101)_2 .$$

**翻译成人话**：$243$ 展开成 8 个二进制位是 $1,1,1,1,0,0,1,1$，$159$ 是 $1,0,0,1,1,1,1,1$，$69$ 是 $0,1,0,0,0,1,0,1$。三个数都是 8 位，这是「固定 $\log_2 m$ 比特长度」的具体体现。

补充材料写的是「$S_1,S_2$ 任意选择，$S_3=S\oplus S_1\oplus S_2$」，而 $S_3$ 一栏只留下空白的位串和结果 $(00101001)_2=41$。把它逐位算出来：

```
        逐位异或（⊕ 表示按位不同则 1、相同则 0）
  位序      7  6  5  4  3  2  1  0
  ------------------------------------------
  S   243 = 1  1  1  1  0  0  1  1
  S_1 159 = 1  0  0  1  1  1  1  1
  S_2  69 = 0  1  0  0  0  1  0  1
  ------------------------------------------
  S ⊕ S_1 = 0  1  1  0  1  1  0  0   = 108
  ⊕ S_2   = 0  0  1  0  1  0  0  1   =  41  ← 这就是 S_3
```

把 $S_3$ 的 8 个位换算回十进制：$32+8+1=41$，与补充材料给出的 $41$ 完全一致。恢复时再做一次异或即可：

$$S_3\oplus S_1\oplus S_2=41\oplus 159\oplus 69=243=S .$$

**翻译成人话**：异或和模加一样，加两次就自己抵消（因为 $x\oplus x=0$），所以「凑出的那一份」既能用来恢复，又不破坏其他份额的随机性。

为什么异或能替代模加？因为「$k$ 比特数据 + 固定长度」这个前提下，模 $2^{k}$ 的加法和按位异或是**同一个群**上的两种写法（都是 $\mathbb{Z}_2^{k}$ 上的加法，只不过一个把进位带到高位、一个不带）。异或的实现优势是：**没有进位**，每一位独立处理，软件里就是一条指令，硬件里就是一排 XOR 门；模加则需要处理进位链。

【补】**这种分割有一个顺带的好处：加法同态。** 若 $S$ 与 $S'$ 分别按同样方式分割成 $(S_1,S_2)$ 与 $(S_1',S_2')$，那么两人各自把手里两个份额相加，就得到 $S+S'$ 的一个合法分割：

$$(S_1+S_1')+(S_2+S_2')\equiv (S_1+S_2)+(S_1'+S_2')\equiv S+S'\pmod{m}.$$

**翻译成人话**：不用先恢复 $S$ 和 $S'$，就能算出「两秘密之和的份额」。这在**电子投票计票**、**联邦学习求梯度平均**之类「只想要总和、不想要单项」的场景里极其有用——这正是「安全多方计算」的最朴素入口。

最后把两种控制方式摆在一起对比：

| 对比项 | 二重控制 | 一致同意控制 |
|---|---|---|
| 用户数 / 门限 | $t=2$，$(2,2)$ | $t$ 任意，$(t,t)$ |
| 单份份额是否有信息 | 无（$1/m$ 的猜测率） | 无（$1/m$ 的猜测率） |
| 少数人缺席 | 直接无法恢复 | 直接无法恢复（任何一人缺席都瘫痪） |
| 少数人串谋 | 两人即全体，无所谓「少数」 | $t-1$ 人串谋也拿不到 $S$ |
| 主要风险 | 两人必须同时在场，可用性差 | 任何一份丢失/损坏都让秘密永久消失 |
| 典型用途 | 双人复核、双钥匙、发射控制 | $n$ 方共同授权、一次性密钥托管 |

**这两种方案共同的短板是「全或无」**：安全性很好（$t-1$ 份零信息），但可用性很差（少一份就完蛋）。要同时兼顾两侧，必须允许「多于 $t$ 人时也能恢复」，也就是真正的 $(t,n)$ 门限方案——这就是第十一讲 3.1 节 Shamir 多项式方案要解决的问题。
