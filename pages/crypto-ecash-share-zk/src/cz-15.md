### 两难的起点：密钥既丢不起，也漏不起

（PPT 第 2 页）第十一讲的开场只有一段话，但整讲的全部动机都在里面：

> 秘密分享方案是与密钥建立相关的多方协议。秘密分享的原始动机是：为了保证密码密钥不丢失，希望产生密钥备份，但是越多的密钥备份，密钥泄露的可能就越大；越少的密钥备份，密钥丢失的可能就越大。秘密分享方案就是用来提高密钥可靠性而不增加泄露风险的方法。

这段话里有两个方向相反的力，先把它们分开看：

1. **副本越多，越不容易丢，但泄露面越大。** 每一份副本都是一次独立的「被偷看」的机会：一份锁在办公室抽屉里、一份放在家里、一份交给同事保管。任何一处出事，密钥就整份泄露——因为**每一份副本都是完整可用的密钥**。
2. **副本越少，越不容易漏，但丢失风险越大。** 硬盘坏掉、房子烧掉、保管人离职或去世，都会让这把钥匙永远消失。

换句话说，**「备份」这个动作本身是有代价的**：它不是免费的可靠性，而是拿泄露风险去换丢失风险。这个权衡可以写成两条单调函数。设每一份副本独立地以概率 $q$ 丢失、以概率 $r$ 泄露（$0<q,r<1$），一共备份 $k$ 份，则：

$$P_{\mathrm{lost}}(k)=q^{k},\qquad P_{\mathrm{leak}}(k)=1-(1-r)^{k}.$$

**翻译成人话**：$k$ 变大时 $q^{k}$ 飞快趋近 $0$（越不容易全丢），但 $1-(1-r)^{k}$ 飞快趋近 $1$（越容易被偷）。两个目标是反向的，所以**不存在一个「最安全」的备份份数**，只能二选一——这就是两难。

取 $q=r=0.1$ 手算一遍：

| 备份份数 $k$ | 全部丢失的概率 $q^{k}$ | 至少泄露一份的概率 $1-(1-r)^{k}$ |
|---|---|---|
| 1 | 0.1 | 0.1 |
| 2 | 0.01 | 0.19 |
| 3 | 0.001 | 0.271 |
| 5 | 0.00001 | 0.40951 |

表格说明得很直白：为了把丢失概率从 $10^{-1}$ 压到 $10^{-5}$，泄露概率从 $10\%$ 涨到了约 $41\%$。**备份做得越认真，安全性反而越差**，这就是课件所说「越多的密钥备份，密钥泄露的可能就越大」的具体数字。

用一张结构图记住这个死结：

```
        安全性的两块天花板（普通备份策略下无法同时突破）
   ┌────────────────────────────────────────────────┐
   │  备份份数 k 增加 ──→ 丢失风险 P_lost = q^k  ↓   │
   │                  └→ 泄露风险 P_leak = 1-(1-r)^k ↑   ✗ 撞线
   │  备份份数 k 减少 ──→ 泄露风险 ↓                 │
   │                  └→ 丢失风险 ↑            ✗ 撞线
   └────────────────────────────────────────────────┘
   结论：只要每份副本都是「完整的密钥」，k 调到哪里都不安全。
```

【补】**一个必须点破的误解**：把密钥复制成两份放在两个保险箱里，这不叫秘密分享，只叫**复制**。它的致命点在于——任何一份副本单独拿出来就能直接使用，所以安全强度等于「最弱的那个保险箱」。真正的秘密分享要求**每一份碎片单独拿出来毫无意义**，这是「复制」永远做不到的。换句话说，要给密钥做冗余，必须先把密钥**编码**成另一种形态，让单份碎片不构成信息。

### 秘密分享：把「复制」换成「分割」

同一页 PPT 的最后一句给出了出路：「秘密分享方案就是用来提高密钥可靠性而不增加泄露风险的方法。」关键动作是**不复制、改分割**。

一个秘密分享方案（secret sharing scheme）由三个动作组成：

1. **分发（distribution）**：分发者（dealer）持有秘密 $S$，按某个规则产生 $n$ 份份额（share，也叫「影子」shadow）$S_1,S_2,\dots,S_n$，再通过安全信道把 $S_i$ 单独交给用户 $P_i$。
2. **恢复（reconstruction）**：某个**授权组**的用户把各自份额拿出来，一起算出 $S$。
3. **安全（security）**：任何**未授权**的用户组，无论怎样计算，都得不到 $S$ 的任何信息。

第 3 条是全部难点所在，它的数学说法是：对任意不合格的用户组、任意候选值 $S'$，事后验算出的概率与事前完全一样：

$$\Pr\big[S=S'\ \big|\ S_{i_1},S_{i_2},\dots,S_{i_{k}}\big]=\Pr\big[S=S'\big],\qquad k<t .$$

**翻译成人话**：看见那 $k$ 份碎片之后，你对「秘密是几」的把握和没看见时一模一样——碎片**没有**提供任何可用信息。这不是「算不出来」的计算困难，而是「根本无从算起」的信息论不可区分。

【补】**术语对照表**（后面各节反复出现，先统一）：

| 中文 | 英文 | 含义 |
|---|---|---|
| 秘密分享 | secret sharing | 把秘密拆成多份、组合才能恢复的整套技术 |
| 份额 / 影子 | share / shadow | 分给单个用户的碎片 |
| 分发者 | dealer | 产生并分发份额的可信方（也叫可信第三方） |
| 门限 | threshold | 能恢复秘密所需的最少份额数，常记作 $t$ |
| 授权结构 | access structure | 规定「哪些用户组有权恢复」的集合族 |
| 授权组 | qualified set | 有权恢复的那类用户组 |

【补】**为什么「提高可靠性」与「不增加泄露」可以同时成立？** 因为分割把「一份完整信息」换成了「$n$ 份残缺信息」，而残缺信息的总量被设计成恰好等于一份完整信息（这叫**理想**方案，见第十一讲 3.1.10 节）。信息论的直觉是：碎片加起来才够解码，少一份就缺一个自由度，于是既没有多余的副本可被偷，也没有单点可以丢。这是一个**编码**问题，不是**复制**问题。

把普通备份和秘密分享摆在一起对比，差别一目了然：

| 维度 | 普通备份（复制） | 秘密分享（分割） |
|---|---|---|
| 单份碎片是否可直接使用 | 是，完整泄露 | 否，单独毫无意义 |
| 丢一份的后果 | 无影响（还有别的副本） | 取决于方案：门限方案里通常仍可用 |
| 被偷一份的后果 | 秘密完全泄露 | 门限方案里不泄露任何信息 |
| 抗内部人 | 几乎为零 | 只要不够 $t$ 份就安全 |
| 需要的数学 | 无 | 有限域上的多项式或线性方程组 |

### 从「单个函数」到「多方可信」：本讲在课程中的位置

到此为止，本课程前面几讲（对称加密、公钥密码、数字签名、哈希函数）研究的都是**单个函数**：输入一段数据，输出另一段数据；安全性归结为「密钥不被人知道」。使用场景是「一个人对一台机器」或者「一个人对另一个人」。

秘密分享把问题换了一个维度：**参与者变成多人，每个人只掌握一部分信息，谁都不该单独说了算。** 这正是课件把它称作「与密钥建立相关的**多方协议**（multi-party protocol）」的原因（PPT 第 2 页）。

【补】**什么是多方协议？** 通俗地说，$n$ 个参与者 $P_1,\dots,P_n$ 各自持有一份**私有输入**（别人看不到），按照约定的规则互相发送消息，最后各自算出一个**输出**；协议要求：只要参与者按规则执行，输出就是正确的（正确性）；而少数作弊者拿不到不属于自己的信息（安全性）。按对手能力通常分两档：

- **半诚实模型（semi-honest / honest-but-curious）**：参与者严格按协议执行，但会偷偷用收到的所有数据去推断别人的隐私。
- **恶意模型（malicious）**：参与者可以任意篡改消息、伪造份额、中途退出。

再叠加一个假设：有多少人可以**串谋（collusion）**。本讲前面几节默认「没有串谋」或「串谋人数不到门限」，第十一讲 3.3 节末尾提到的「存在骗子的秘密分享」（PPT 第 33 页起）才开始处理恶意行为。

```
     传统加密（单方/双方）                多方协议（本讲的主场）
   ┌──────┐  密文 c   ┌──────┐      ┌─────┐  ┌─────┐  ┌─────┐
   │  A   │ ───────→  │  B   │      │ P_1 │  │ P_2 │  │ P_3 │
   └──────┘           └──────┘      └──┬──┘  └──┬──┘  └──┬──┘
    私钥 k              私钥 k          └──── 互发消息 ────┘
   安全性 = 密钥保密                  安全性 = 少数人拿不到整体信息
```

这张图想说的是：**前面几讲的安全性靠「一把钥匙藏好」，本讲的安全性靠「信息分散在多人手里」。** 后者的好处是，连「钥匙」这个概念都可以不存在——秘密从来没有在任何单独一方手里完整出现过。

### 现代密码学的一面旗帜：高级安全协议

（PPT 第 3 页）课件紧接着给了一句评价很高的话：

> 现代密码学的一个主要成就在于高级安全协议的发展。这些协议可以让用户在网上解决现实世界中许多问题，进行各种游戏，也能执行各种有趣而复杂的分布任务。

这句话的分量在于：密码学不再只是「加密通信」，而是**在网上重建现实世界里的信任机制**。课件列出的四类任务，恰好对应四种不同的难点：

| 任务 | 一句话目标 | 真正的难点 |
|---|---|---|
| 电子选举 | 计票正确，但谁都不知道你投了谁 | 既要匿名，又要可验证结果没被篡改 |
| 电子拍卖 | 出价密封，开标时价高者得 | 拍卖方不能偷看别人的出价 |
| 电话投币 | 双方隔着电话「同时」抛一枚硬币 | 任何一方不能单方面决定结果 |
| 电话扑克 | 隔着电话发牌、打牌 | 洗牌要随机，且不能偷看别人的牌 |

【补】**历史坐标**：电话投币（coin flipping over the telephone）由 Blum 在 1981 年提出，它第一次说明「互不信任的双方也能共同产生一个谁都无法操纵的随机比特」，靠的工具叫**比特承诺（bit commitment）**。电话扑克（mental poker）由 Shamir、Rivest、Adleman 在 1979 年提出，是「不借助可信第三方也能公平发牌」的第一个方案。这两件事都在第十二讲（零知识证明）里会以更强的形式再出现：**证明一件事而不泄露这件事之外的信息**，正是零知识证明的主题。

这里还要点出本讲与前几讲的一个结构性区别：前面讲的是**保密**（confidentiality）——不让别人看到；本讲和下一讲越来越多地讲**正确性**（correctness）与**公平性**（fairness）——不让别人作弊。秘密分享是这两条线的交汇点：它既要保密（碎片无意义），又要正确（够数就能恢复），还要**容错**（少数碎片损坏或被篡改也不至于全盘失效）。

| 课件提纲 | 课件页码 | 本讲义的位置 | 一句话内容 |
|---|---|---|---|
| 秘密分享的应用 | 5–11 | 第十一讲 1.1–1.2 节 | 烹饪方法、核导弹、门限思想 |
| 秘密分割 | 12–15 | 第十一讲 2.1–2.2 节 | 模加的二重控制与一致同意控制 |
| 门限方案 | 16–32 | 第十一讲 3.1–3.2 节 | Shamir 多项式方案、Blakley 向量方案 |
| 电话投币协议 | 33 页之后 | 后续小节 | 互不信任双方的共同随机性 |
| 电话扑克协议 | 33 页之后 | 后续小节 | 不泄露手牌的发牌与打牌 |

在进入第十一讲 1.1 节之前，先把全讲共用的记号钉死，后面不再重复解释：

| 记号 | 含义 | 取值范围 |
|---|---|---|
| $S$ | 要保护的秘密（数字形式） | 常见约定 $0\le S\le m-1$ 或 $S<p$ |
| $n$ | 份额总数 = 用户数 | 正整数 |
| $t$ | 门限值：恢复所需的最少份额数 | $1\le t\le n$ |
| $p$ | 大素数（多项式和超平面都建在它上面） | 素数，$p>\max(S,n)$ |
| $\mathbb{Z}_p$ | 模 $p$ 的整数环（因为 $p$ 是素数，它其实是**域**） | $\{0,1,\dots,p-1\}$ |
| $S_i$ | 第 $i$ 个用户拿到的份额 | $\mathbb{Z}_p$ 中的元素 |
| $f(x)$ | Shamir 方案里隐藏秘密的随机多项式 | 次数 $<t$，$f(0)=S$ |

【补】**为什么后面处处要用素数 $p$ 而不是任意整数 $m$？** 因为恢复秘密要用**除法**：Lagrange 插值公式里有分母 $x_k-x_j$，解线性方程组要做消元。在模 $m$ 的算术里，只有与 $m$ 互素的数才可逆；一旦 $m$ 是素数，除 $0$ 之外的每个数都可逆，除法就畅通无阻。这就是 $\mathbb{Z}_p$ 被称为**有限域**（finite field）而 $\mathbb{Z}_m$（$m$ 合数）只能叫**环**的原因。第十一讲 2.1 节与 2.2 节的模加分割不涉及除法，所以那里的模数可以取任意 $m$；第十一讲 3.1 节一开始就必须换成素数。

【补】**一把钥匙能不能既「分给多人」又「谁都看不到完整密钥」？** 可以，而且这正是本讲的中心思想：**把「知道秘密」这件事，换成「能否让某个特定行为被触发」这件事。** 后文第十一讲 3.1 节会看到，参与者甚至不需要看到秘密本身，只需要各自把份额输入一台可信设备，设备内部完成恢复并执行动作（比如发射导弹、解密一段数据）。这个视角上的切换，是秘密分享从「备份技巧」升级为「密码学原语」的关键一步——也是后面门限签名、门限解密、安全多方计算等一大堆技术的起点。
