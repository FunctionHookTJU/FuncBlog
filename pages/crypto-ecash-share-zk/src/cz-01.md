### 为什么第 0 章必须存在

本册三讲对应的三份课件——第十讲《电子商务与电子现金》（49 页）、第十一讲《秘密分享与游戏》（60 页，另附 3 页 Shamir 证明）、第十二讲《零知识证明技术》（52 页）——有一个共同点：它们**几乎不发明新的加密算法**。它们做的是把前面几册已经造好的零件（Hash 函数、RSA、模运算、离散对数、数字签名）**组装成协议**，去解决现实里的一类问题：在公共信道上做买卖、把一把钥匙拆给五个人、隔着电话公平地掷硬币、证明"我知道口令"却一个字都不说。

问题在于，课件默认你手里已经有这些零件，也默认你熟悉"模运算""困难问题""可忽略概率"这类说法，于是直接开始讲 SET 协议、Shamir 方案、Fiat–Shamir 协议。这个默认往往不成立。所以第 0 章（0.1–0.4 四节）承担四件事：

1. **画地图**（0.1）：三讲各自在密码学的哪个位置、彼此怎么接上。
2. **补数论**（0.2）：模逆、二次剩余、Euler 判别法、模平方根、Blum 整数——补到能动手算的程度。
3. **说清"安全"**（0.3）：三类困难问题、单向函数与陷门、"可证明安全"到底在证什么。
4. **建协议语言**（0.4）：参与方、比特承诺、盲化、交互、完备性/可靠性/零知识。

本章四节**没有对应的 PPT 页**——课件是从第十讲的正文开始的——所以整章都属于 `【补】` 性质：课件没讲，但你读后面每一讲都要用到。也正因为没有 PPT 页码可标，本章的目标不是"覆盖某个页面的知识点"，而是"让你在读到第十讲第一个协议时，不会因为某个符号停住"。

### 密码学有两层楼：算法层与协议层

理解本册位置的最快方式，是承认密码学有两层楼。

| 层次 | 研究对象 | 前三册的典型内容 | 本册的典型内容 |
|---|---|---|---|
| **算法层**（primitive，原语） | 单个函数、单次密钥操作 | DES、AES（分组密码）；SHA-1、MD5（Hash）；RSA、Rabin（公钥加密）；ElGamal、Schnorr（签名） | 基本不造新原语：把 $H$、RSA、离散对数、签名当零件用 |
| **协议层**（protocol） | 多个参与方 + 多轮消息 + 对手模型 | 少量：Diffie–Hellman 密钥交换、CBC-MAC | 主战场：SET 双重签名、不可否认签名、电子现金、Shamir 门限、电话投币、电话扑克、四条零知识鉴别协议 |

两层楼的差别不是"难易"，而是**安全的定义对象变了**：

- 算法层问的是"给定密文/签名，攻击者能不能反推出密钥或明文"；
- 协议层问的是"**任何一个参与方，在任何一步，能不能通过偏离剧本给自己捞到好处**"。

后一个问题更难，因为它必须把"作弊"写成可证明的命题。本册的每一讲，本质上都在回答这个问题的一个特例。

一个协议可以被拆成四个部件：

$$\text{protocol}=\big(\ \text{parties},\ \text{messages},\ \text{algorithms},\ \text{adversary model}\ \big)$$

**翻译成人话**：一个协议就是"谁参加、按什么顺序发什么消息、每方用什么算法处理消息、以及我们假设对手能做什么"这四件事的完整剧本；少写最后一项，安全讨论就没有意义。

### 三讲各自要解决的问题

| 讲 | 篇幅 | 要解决的问题 | 关键方案 | 依赖的难题 |
|---|---|---|---|---|
| 第十讲 电子商务与电子现金 | 49 页 | 公共信道上做买卖：认证、隐私、防篡改、**匿名支付** | SET 双重签名；Chaum–Antwerpen 不可否认签名；Brands 电子现金 | RSA / 大整数分解；离散对数 |
| 第十一讲 秘密分享与游戏 | 60 页 + 3 页证明 | 一把钥匙太危险：怎么把秘密拆开，怎么让互不信任的两方公平决策 | 模加二重控制；Shamir 门限；Blakley 向量方案；电话投币；电话扑克 | 信息论安全（不靠难题）；模合数平方根 / 分解；离散对数 |
| 第十二讲 零知识证明技术 | 52 页 | 怎么证明"我知道口令"而不泄露哪怕一个比特 | 洞穴故事；Fiat–Shamir；FFS；GQ；Schnorr | 模合数平方根；RSA；离散对数 |

【补】**页数与结构**：三份课件合计 164 页。第十讲 49 页里，真正的协议只有三个（SET 双重签名、不可否认签名、Brands 电子现金），其余是背景与应用场景；第十一讲的 60 页里有一半在讲门限方案的各种构造；第十二讲的 52 页有一半在讲四个鉴别协议（Fiat–Shamir、FFS、GQ、Schnorr）的具体式子。**先把"每讲要解决什么问题"记住，再去记式子，效率会高得多。**

**第十讲：别人看得见的东西，怎么只让该看的人看见。** 电子交易里有两类信息：商品和服务定单（Goods and Services Order，GSO）与支付指令（Payment Instruction，PI）。GSO 该给商家看、不该给银行看；PI 该给银行看、不该给商家看；可是这两条信息又必须被绑在一起，否则商家可以把一份支付指令挪到另一份定单上。双重签名（dual signature）就是为这个"既连接又分离"的要求设计的。同一讲里的不可否认签名解决另一个矛盾：签名既要能证明身份，又不能变成一张可以被任意复印的把柄。电子现金则要求：银行签了这张钱，却不知道这张钱后来是谁花的。

**第十一讲：把信任拆散。** 秘密分享（secret sharing）的原始动机很朴素：密钥备份多了容易泄露，备份少了容易丢失，那就把密钥拆成 $n$ 份，任何 $t$ 份合起来能恢复、少于 $t$ 份什么也得不到。门限方案（threshold scheme）是它的数学形态；电话投币（coin flipping by telephone）与电话扑克（mental poker）则把同一套思想搬到"两个人互相不信任、又没有裁判"的场景。这一讲最特别的地方是：Shamir 方案的安全性**不依赖任何计算困难问题**，是信息论意义上的安全。

**第十二讲：证明但不泄露。** 你要向银行证明"我知道账户口令"，但银行服务器可能是假的（课件里的假 ATM 机案例），一旦你说出口令，对方就能冒充你。零知识证明（zero-knowledge proof）要求：证明者让验证者相信自己掌握某个秘密，但验证者事后**无法向第三方复述出这个秘密，也无法自己冒充**。四个鉴别协议都是同一个骨架的不同实现。

### 主线一：给数字签名"加功能"

第十讲第 3 页（PPT 第 3 页）把方法论说得非常清楚：本讲使用**带附加功能的数字签名技术**，签名机制可以提供认证与不可否认之外的额外功能；而在多数情况下，这是通过"**把基本签名方案融入一个特定的协议**"来实现的。

先把"基本签名"写成式子：

$$\mathrm{Sig}_{A}(m)=\sigma,\qquad \mathrm{Ver}_{A}(m,\sigma)\in\{\text{accept},\text{reject}\}$$

**翻译成人话**：签名就是"A 用私钥把消息 $m$ 压成一段数据 $\sigma$，任何人拿 A 的公钥都能验证这段数据确实出自 A、且 $m$ 没有被改过"。

这个式子能提供的只有**认证**（确实是 A 签的）与**完整性**（消息没被改）。它天然做不到下面三件事，而这三件事正好对应第十讲的三个方案：

| 想要的附加功能 | 单靠签名为什么做不到 | 靠什么机制补上 | 在本册哪里 |
|---|---|---|---|
| 商家看不到卡号、银行看不到定单，但两条信息必须绑定 | 签名把整条消息当一个整体签，无法"一半公开一半隐藏" | 对两个摘要的**拼接**再签名（双重签名） | 第十讲 1.2.2–1.2.3 |
| 签名只对该接收者有效，别人拿不走当证据 | 签名一旦公开就可被任何人独立验证，天然可传播 | 签名 + 确认协议（交互）+ 否认协议 | 第十讲 2.1–2.3 |
| 签名者签了名，却不知道（也不记得）自己签了什么 | 签名算法要求签名者看到 $m$ 才能算 | 盲化（blinding）：先把 $m$ 乘上一个随机因子再签 | 第十讲 3.1–3.3 |

把这条主线画出来：

```
      ┌─────────────────────────┐
      │  基本数字签名（认证）    │
      │  Sig_A(m) = σ           │
      └───────────┬─────────────┘
                  │ 嵌进协议 + 加随机数 / 加交互
      ┌───────────┴─────────────┐
      ▼             ▼           ▼
  ┌────────┐  ┌──────────┐  ┌──────────┐
  │双重签名│  │不可否认   │  │盲签名    │
  │连接+分离│  │签名+确认  │  │签名+盲化 │
  └───┬────┘  └────┬─────┘  └────┬─────┘
      ▼            ▼             ▼
   银行与商家   只有接收者     电子现金
   各看一半     能先验证      （匿名支付）
```

【补】**为什么"附加功能"一定要靠协议，而不能靠更强的算法？** 因为签名是**单方**操作：A 一按按钮，$\sigma$ 就生成了，之后它脱离 A 的控制。凡是要求"签名者事后还能参与决定"（不可否认签名）、"签名者当时不知道内容"（盲签名）、"与另一条消息绑定但彼此不可见"（双重签名）的要求，本质上都涉及**第二方或多方的行为约束**，单方算法在原则上就无法表达。这是本册的方法论核心，也是为什么第 0.4 节要专门讲"协议语言"。

### 主线二：把秘密拆开、把知识藏起来

第十一讲与第十二讲的衔接没有第十讲那么明显，但它们共享同一个动作：**先承诺，再接受挑战，最后揭示/应答**。

第十一讲的门限方案可以先用一个式子预览（细节在第 0.2 节与第十一讲 3.1 节）：

$$f(x)=S+a_{1}x+a_{2}x^{2}+\cdots+a_{t-1}x^{t-1}\pmod p,\qquad (x_i,y_i)=(i,f(i))$$

**翻译成人话**：把秘密 $S$ 藏进一条 $t-1$ 次多项式的常数项，第 $i$ 个分享就是曲线上的一个点 $(i,f(i))$；$t$ 个点能把曲线唯一地画回来，从而读出 $f(0)=S$，少于 $t$ 个点则 $S$ 可以取任意值而曲线依然能穿过这些点。

第十二讲的三条性质预告（正式定义在第十二讲 1.2 节）：

- **完备性**（completeness）：诚实的证明者与诚实的验证者跑完协议，验证者一定接受；
- **正确性/可靠性**（soundness）：不掌握秘密的骗子无法让验证者接受（除非以极小概率碰巧）；
- **零知识性**（zero-knowledge）：验证者从交互记录里学不到任何关于秘密的新东西。

把两讲合起来看，本册所有"防作弊"协议都长这样：

```
   证明者/发起方                     验证者/接收方
        │  ── ① 承诺（commit）──▶      │   先锁死一个值，不能再改
        │  ◀── ② 挑战（challenge）──    │   随机问一个问题
        │  ── ③ 应答（response）──▶     │   只能有一种答法能过
        │                              │   ④ 验证（verify）
```

**翻译成人话**：先把手里的牌扣在桌上（承诺），等对方随机指定要哪一张（挑战），再翻给他看（应答）；因为对方是在你扣牌之后才提要求的，你无法事先准备好一个能同时糊弄所有要求的答案。这个骨架在第十一讲叫"投币/扑克"，在第十二讲叫"零知识证明"，在第十讲叫"挑战-应答式认证"。

### 四条贯穿全册的技术线索

读本册时如果只记住三讲的标题，会觉得很散；记住下面四条线索，就会发现它们在反复出现。

| 线索 | 是什么 | 本册出现在哪 | 前置知识在哪一册 |
|---|---|---|---|
| **Hash 函数** | 把任意长消息压成固定短摘要，抗碰撞 | SET 双重签名（摘要拼接）；比特承诺；Fiat–Shamir 把交互协议变成签名 | 《密码 Hash 函数与 RSA / Rabin 算法》 |
| **模运算与平方剩余** | 模 $p$ 的平方、开方、判定；模合数 $n=pq$ 的四个平方根 | Shamir 的模 $p$ 多项式；电话投币的 Blum 整数；FFS/Fiat–Shamir 的模平方根 | 第二册的模运算补课 + 本书 0.2 |
| **离散对数** | 给定 $g$ 与 $g^{x}$ 求 $x$ 很难 | Chaum–Antwerpen 不可否认签名；Brands 电子现金；电话扑克；Schnorr 鉴别 | 《离散对数与数字签名》 |

这四条线索对应一句经验：**本册的协议几乎都是"难题 + Hash + 随机数 + 交互"这四样东西的不同排列组合**。看到一个新协议，先问四个问题——它靠哪个难题？哪里用到 Hash？随机数起什么作用？需要几轮交互？——基本就能猜出它的安全论证长什么样。

### 本册的记号约定

后面每一讲都会反复出现这些记号，先把它们固定下来（与课件的记号保持一致）：

| 记号 | 含义 | 注意 |
|---|---|---|
| $p,q$ | 大素数 | 课件里 $q$ 有时表示"$q\mid(p-1)$ 的素数"，有时是 Blum 整数的因子，看上下文 |
| $n$ | 模数，通常是 $n=pq$ | $n$ 公开，$p,q$ 保密 |
| $H(\cdot)$ | 公开的 Hash 函数 | 输出当"摘要"用，可当随机数发生器用（0.4 会讲它的两面性） |
| $E_{A},D_{A}$ | 实体 $A$ 的加密/解密函数 | 第十讲用 $E_{C},E_{M},E_{B}$ 表示持卡人、商家、银行 |
| $a^{-1}\bmod n$ | $a$ 的模逆 | 只有 $\gcd(a,n)=1$ 时存在（0.2 详讲） |
| $x\equiv y\pmod n$ | 同余 | 读作"$x$ 与 $y$ 除以 $n$ 余数相同" |
| $\oplus$ | 按位异或 | 自逆：$a\oplus a=0$ |
| $\lVert$ | 字符串拼接 | 双重签名里 $\mathrm{MD}(H(\mathrm{GSO})\lVert H(\mathrm{PI}))$ 用它 |
| $(t,n)$ | 门限参数 | $n$ 个分享中任意 $t$ 个可恢复 |
| $A,B,C$ | 参与方（Alice/Bob/Carol） | 攻击者常用 Eve（窃听者）或 Mallory（主动攻击者） |

### 本节要点

1. 密码学分两层：**算法层造零件，协议层装机器**。本册在协议层。
2. 三讲的问题分别是：**让该看的人看见该看的**（第十讲）、**把秘密拆开且拆得公平**（第十一讲）、**证明知识但不泄露知识**（第十二讲）。
3. 第十讲的主线是"给数字签名附加功能"：双重签名 = 摘要拼接再签；不可否认签名 = 签名 + 确认/否认协议；电子现金 = 盲签名。
4. 本册所有协议共享骨架：**承诺 → 挑战 → 应答 → 验证**，靠随机性把作弊成功率压到可忽略。
5. 四条技术线索：Hash、模运算与平方剩余、离散对数、随机数与盲化。

### 自测题

1. 用一句话区分"算法层"与"协议层"，并各举一个本册的例子。
2. 第十讲为什么需要"双重签名"？如果只把 GSO 和 PI 分别签名再一起发送，会出什么问题？
3. 门限方案里"少于 $t$ 个点恢复不出秘密"这一条，为什么可以说"不依赖计算困难问题"？它靠的是什么？
4. 本册所有防作弊协议共享的骨架是哪四步？随机数出现在哪一步、起什么作用？
5. 四条技术线索里，哪一条是"第十讲与第十一讲都会用到、但第十二讲用得最多"的？举两个例子。

<details><summary>答案</summary>

1. 算法层研究单个函数的安全性（如 AES 的密钥不可反推）；协议层研究多方交互中任何一方能否作弊（如 SET 中商家能否看到卡号）。本册第十讲的双重签名属于协议层，而它内部调用的 RSA 签名属于算法层。
2. 分别签名再一起发，两条签名之间没有任何绑定关系：商家可以把一份 PI 的签名挪到另一份 GSO 上，或者把别人的支付指令拼到自己的定单后面。双重签名通过"对 $H(\mathrm{GSO})\lVert H(\mathrm{PI})$ 这个拼接摘要签名"把两条信息锁在一起，同时让持有完整消息的一方才能验证自己那一半。
3. 它靠的是**信息论**：给定 $t-1$ 个点，任何候选秘密 $S'$ 都能配出一条经过这些点的 $t-1$ 次多项式，所以 $t-1$ 个分享对 $S$ 没有提供任何信息——这与攻击者有多少算力无关（详见第十一讲 3.1 节）。
4. 承诺（先锁死一个值）→ 挑战（对方随机提问）→ 应答（只能有一种答法能过）→ 验证。随机数出现在挑战里：因为挑战是在承诺之后才产生的，作弊者无法提前准备一个能同时糊弄所有挑战的答案。
5. Hash 函数：SET 双重签名要把两个摘要拼接后再签；Fiat–Shamir 用 $e=H(x\lVert m)$ 把交互协议压成非交互签名（后者用得最多）。另外离散对数线索也横跨三讲，但"用得最多"的是 Hash 与平方剩余这两条。
