1.3–1.4 一般结构与零知识协议 vs 非对称协议

三次交互：一大类零知识协议的一般结构

前面两节讲了直觉（1.1）与定义（1.2）。第十二讲 1.3 节做的是提炼：把洞穴故事和后面四个具体协议共同的骨架抽出来，写成三行（PPT 第 19 页）：

A→BA\to BA→B：证据 A←BA\leftarrow BA←B：提问 A→BA\to BA→B：回答

课件紧接着给出这一结构的完整说明：

以上描述了一大类三次交互零知识协议的一般结构：证明者随机的选择一个在事先定义的集合上的元素做一个秘密承诺，并从中计算相关的公开证据。这提供了一个每一次协议执行的随机性，并限定了 AAA 在本次协议执行中所能回答问题的集合，因此，也就限定了将来的可能答案。

先用一张时序图把这个结构画出来：

   A（证明者）                                       B（验证者）
        │                                                │
        │  ① 随机选一个「承诺值」，算出公开证据 x         │
        │  ────────────── x（证据）────────────────────▶ │
        │                                                │
        │  ◀──────────── e（提问 / 挑战）──────────────  │
        │                                                │
        │  ② 用秘密 s 与随机数算出回答 y                  │
        │  ────────────── y（回答）────────────────────▶ │
        │                                                │
        │                        ③ 检查 y 与 x、e 是否相容 │
        │                          接受 / 拒绝             │

逐句翻译课件那段话，把每一个短语都落到操作上：

  • 「证明者随机地选择一个在事先定义的集合上的元素做一个秘密承诺」：AAA 从一个双方事先约定好的集合里随机取一个元素（在 Fiat-Shamir 里就是取 r∈{1,…,n−1}r\in\{1,\dots,n-1\}r∈{1,…,n−1}），并对它做承诺（commitment）。承诺的意思不是「把 rrr 加密后发过去」——rrr 本身绝不会被发送。承诺是：AAA 先把某个由 rrr 决定的公开值发出去，从而把自己锁在 rrr 上。
  • 「并从中计算相关的公开证据」：这个公开值（记作 xxx）是从 rrr 算出来的，在 Fiat-Shamir 里是
x≡r2(modn).x\equiv r^{2}\pmod n.x≡r2(modn).

翻译成人话：把 rrr 平方后模 nnn 发出去。对方看到 xxx 但算不出 rrr（模 nnn 开平方难），所以 rrr 被「藏住」了；可是 rrr 已经通过 xxx 被「钉死」了，AAA 事后再也换不了。

  • 「这提供了一个每一次协议执行的随机性」：rrr 每轮都要重新随机，所以每一轮发出的 xxx 都不同。这正是「使用不退化」（第十二讲 1.4 节）的技术来源。
  • 「并限定了 AAA 在本次协议执行中所能回答问题的集合」：这句话是整段的核心。xxx 一旦发出，能被 xxx 验证通过的 yyy 的集合就被固定了。用公式写：给定承诺 xxx 与挑战 eee，合法回答的集合是
Ye(x)={ y : y2≡x⋅ve(modn) }.Y_{e}(x)=\left\{\,y\ :\ y^{2}\equiv x\cdot v^{e}\pmod n\,\right\}.Ye​(x)={y : y2≡x⋅ve(modn)}.

翻译成人话：AAA 发完 xxx 之后，它在这次执行里「能交出的答案」已经是一个固定的集合了；它可以在集合里挑，但不能跳出集合。所以「将来可能的答案」在 xxx 发出的那一刻就已经被限定——这就是承诺的全部作用。

  • 换个角度看：AAA 在出题之前就已经把自己锁死了。

补承诺（commitment）的两个性质，缺一不可。 一个承诺方案通常写成

c=Com(r; ρ),c=\mathrm{Com}(r;\ \rho),c=Com(r; ρ),

翻译成人话：把要承诺的值 rrr 和一个随机辅助串 ρ\rhoρ 一起塞进承诺函数，得到承诺值 ccc；将来打开承诺时把 (r,ρ)(r,\rho)(r,ρ) 一起交出来，对方重算 Com(r;ρ)\mathrm{Com}(r;\rho)Com(r;ρ) 与 ccc 比对。它必须同时满足：

  • 隐藏性（hiding）：看到 ccc 的人猜不出 rrr。否则承诺就等于提前泄密。
  • 绑定性（binding）：承诺者事后不能把 ccc 解释成另一个 r′r'r′。否则「先承诺、后挑战」的顺序就白设计了。

补Fiat-Shamir 里的 x≡r2(modn)x\equiv r^{2}\pmod nx≡r2(modn) 是一种「不严格的承诺」。 它满足隐藏性（不知道 nnn 的分解就开不出平方根），但不满足严格的绑定性：xxx 在模 nnn 下通常有四个平方根，AAA 理论上可以在 xxx 发出后再挑另一个平方根。不过这对协议无害——协议验证的是「y2≡x⋅vey^{2}\equiv x\cdot v^{e}y2≡x⋅ve」，四个平方根里的任何一个都能通过验证。所以这里真正被绑定的不是「rrr 这个数」，而是「xxx 的平方根这个集合」：AAA 无论怎么反悔，都只能在这个集合里选，逃不出 Ye(x)Y_{e}(x)Ye​(x)。理解这一点，才不会误以为所有承诺都必须是严格绑定的。

补反例：如果去掉「承诺」这一步，协议立刻崩掉。 假设把顺序改成「BBB 先发挑战 eee，AAA 再发 xxx 和 yyy」。那么一个不知道 sss 的冒充者可以这样做：随便选一个 yyy，然后倒着算 xxx：

x≡y2⋅v−e(modn).x\equiv y^{2}\cdot v^{-e}\pmod n.x≡y2⋅v−e(modn).

翻译成人话：先决定答案 yyy，再按验证式反推出应该提交的证据 xxx。这样交出去的 (x,y)(x,y)(x,y) 必然通过验证，冒充成功率 100%100\%100%。

这个反例把「为什么必须承诺在前」讲透了：承诺的唯一目的，就是剥夺 AAA「根据挑战反推证据」的自由。 一旦 AAA 能先看题再作答，它就可以永远答对。这同时也解释了第十二讲 1.1 节洞穴故事里那句「Victor 必须在 Peggy 消失之后才走到 B 点」为什么是协议的关键而不只是叙事细节。

循环：用轮数把欺骗概率压下去

课件接着讲协议的第二半（PPT 第 20 页）：

根据协议设计，只有知道秘密知识的合法 AAA 才有能力回答所有根据公开证据提出的问题，而回答一个问题，并不能帮助分析 AAA 的秘密知识。BBB 接着选择一个问题提交给 AAA，AAA 做出回答，而 BBB 检查是否正确。协议是一个循环执行过程，如果需要，就可以通过控制循环次数降低欺骗成功的概率。

逐句翻译：

  • 「只有知道秘密知识的合法 AAA 才有能力回答所有根据公开证据提出的问题」：注意「所有」两个字。协议的设计目标是让每一条合法问题都需要秘密才能答对。如果存在某条问题不需要秘密就能答，那它就成了一条漏网之鱼，冒充者可以专挑它回答。
  • 「而回答一个问题，并不能帮助分析 AAA 的秘密知识」：这是零知识属性在一般结构层面的表述——回答问题不产生新信息。严格版本就是第十二讲 1.2 节的定义 3（模拟器）。
  • 「BBB 接着选择一个问题提交给 AAA，AAA 做出回答，而 BBB 检查是否正确」：这三步就是「挑战—应答—验证」。
  • 「协议是一个循环执行过程，如果需要，就可以通过控制循环次数降低欺骗成功的概率」：重复是唯一的安全性调节旋钮。

把「循环」量化。设每一轮的挑战有 kkk 个可能的取值（kkk 称为挑战空间大小），且挑战均匀随机、各轮独立。一个不知道秘密的冒充者在每一轮里最多只能答对其中一个取值，因此单轮通过率是 1/k1/k1/k。ttt 轮独立重复后，全部通过的概率是

Pt = (1k)t = k−t.P_{t}\ =\ \left(\frac{1}{k}\right)^{t}\ =\ k^{-t}.Pt​ = (k1​)t = k−t.

翻译成人话：每一轮都有 kkk 个问题可选，冒充者只准备了一个答案，所以每轮蒙中的机会是 1/k1/k1/k；ttt 轮全蒙中的机会是 k−tk^{-t}k−t。

不同协议只是把 kkk 换成了不同的东西（细节见第十二讲 2–5 节）：

协议 每轮挑战的空间 kkk 达到 2−202^{-20}2−20 量级需要的轮数
洞穴故事 左 / 右 222 t=20t=20t=20
Fiat-Shamir（第十二讲 2 节） e∈{0,1}e\in\{0,1\}e∈{0,1} 222 t=20t=20t=20

翻译成人话：想省钱就把「kkk 做大」，想简单就把「ttt 做大」——两种办法都在同一把公式 k−tk^{-t}k−t 里。第十二讲 3–5 节的三个协议，本质上都是在「把 kkk 做大」上做文章。

补循环还有一个工程上的分支：串行还是并行。 ttt 轮可以一轮接一轮地做（串行），也可以把 ttt 轮的证据一次性全发出去、让 BBB 一次抛 ttt 个挑战（并行）。并行能省通信轮次，但安全性论证要重新做——这两者的区别在第十二讲 3 节 Feige-Fiat-Shamir 会正式讨论。这里只要建立一个意识：「重复」不是免费的，重复的方式会影响安全证明。

1.4 零知识协议 vs 非对称协议：为什么要比较

讲完结构，课件用两页（PPT 第 21–22 页）把零知识协议与传统的非对称（公钥）协议做五点对比。这个比较很重要，因为它纠正两种极端印象：一种认为「零知识更先进所以更安全」，另一种认为「零知识是纯理论玩具不可用」。真实情况在两者之间。

先明确比较对象：非对称协议指的是基于 RSA、离散对数等公钥技术的鉴别与签名方案；零知识协议指的是本讲这一族「承诺—挑战—应答」协议。两者的安全基础其实高度重叠（都用计算困难问题），差别在工程特性上。

(1) 使用不退化

(1) 使用不退化：协议具有零知识属性因此不会因为重复使用而降低安全性并可阻止选择消息攻击。这可能是零知识技术在实践中最吸引人之处。（PPT 第 21 页）

逐句翻译：

  • 「不会因为重复使用而降低安全性」：把同一个协议用一万次，安全性不下降。这是零知识属性的直接推论：每一轮的记录都只是随机噪声的伪装（定义 3 的模拟器），所以收集历史记录等于收集公开信息，一点用都没有。
  • 「可阻止选择消息攻击」：选择消息攻击（chosen-message attack） 指攻击者可以指定自己想让它签的消息，让合法方签，然后从签名里寻找规律去伪造新签名。零知识协议天然免疫，因为每一轮的证据都是新鲜随机的，历史记录与未来轮次之间没有任何可利用的关联。

把这个好处写成一句话公式。记 Suc\mathsf{Suc}Suc 为「冒充成功」事件，Histm\mathrm{Hist}_{m}Histm​ 为「已看到 mmm 轮历史记录」这一条件，则

Pr⁡[ Suc∣Histm ] = k−t.\Pr[\,\mathsf{Suc}\mid \mathrm{Hist}_{m}\,]\ =\ k^{-t}.Pr[Suc∣Histm​] = k−t.

翻译成人话：看过 mmm 轮录像之后，冒充者去骗一次新协议的通过概率仍然是 k−tk^{-t}k−t——这个式子的右边不含 mmm。这就是「不退化」最直白的读法：历史记录不改变成功率。

举三个对照物，差别立刻显现：

方案 用一次之后安全性怎么变 原因
静态口令 变差：多一次被偷听就多一份风险 证明是固定比特串，可重放
一次性口令（OTP） 不变差，但只能用一次 用过的口令作废，必须重新同步
零知识协议 不变差，且可以无限次使用 每轮重新随机，记录可模拟

翻译成人话：静态口令是「用一次就更危险一点」，一次性口令是「用一次就废」，零知识协议是「随便用，永远一样安全」。这就是课件说它「在实践中最为吸引人」的原因——它同时拿到了「可重复使用」和「不退化」这两件通常互斥的好处。

(2) 无需加密

(2) 无需加密：许多零知识技术都不需要使用加密算法。（PPT 第 21 页）

翻译成人话：协议里没有「加密 / 解密」这两个操作，全部运算只有模加、模乘、模平方、模幂。以第十二讲 2 节的 Fiat-Shamir 为例，双方做的只有三种事：平方（r↦r2r\mapsto r^{2}r↦r2）、相乘（r↦r⋅sr\mapsto r\cdot sr↦r⋅s）、比对（y2≡x⋅vey^{2}\equiv x\cdot v^{e}y2≡x⋅ve）。没有一处需要加密一个消息，也没有解密。

这带来三个实际好处：

  1. 实现简单，出错面小。 加密方案要处理分组模式、填充、初始化向量，每一项都是历史漏洞的重灾区；零知识协议把这些统统绕开了。
  2. 没有「加密」的合规负担。 补这一点有真实的历史背景：1990 年代美国对加密技术实施出口管制，很多产品不敢带加密功能。零知识鉴别协议因为技术上「不做加密」，在当年的出口分类中相对好处理，这是它被工业界迅速接纳的现实原因之一。
  3. 计算原语少，容易做常数时间实现。 只有模乘和模平方，侧信道防护的目标很明确。

补「无需加密」不等于「不需要秘密」。 协议依然要保护 sss 与 rrr，只是保护的手段不是加密，而是数学上的难解性（模平方根难算、离散对数难算）。「藏」靠的不是密码箱，而是计算困难。 这也是为什么零知识协议的安全性完全依赖困难假设——代价在 (4) 里会明说。

(3) 效率：零知识是有代价的

(3) 效率：虽然一些零知识基技术非常有效，但是具有零知识属性的协议通常比没有零知识属性的非对称协议需要更多通信和计算开销。更为有效的实用零知识基方案通常源于交互证明的特性，而不是它的零知识特性。（PPT 第 21 页）

这段话有两层，第二层尤其容易被读漏：

  • 第一层：零知识要付代价。 为了把欺骗概率压到可以忽略，协议必须重复，而重复意味着更多轮、更多消息、更多模运算。
  • 第二层：真正让这些方案实用的，是「交互证明」本身，而不是「零知识」。 换句话说，工程上大家喜欢 Fiat-Shamir 这一族协议，主要因为它们证明短、计算省（交互证明的优点），而不一定是因为它们零知识（那个是附加保证）。

把代价算清楚。设要做一次 2−202^{-20}2−20 安全级别的鉴别：

方案 需要的轮数 消息条数（每轮 3 条） 备注
Fiat-Shamir（k=2k=2k=2） 202020 606060 每轮只有 1 比特挑战，只能靠轮数堆安全性
Feige-Fiat-Shamir（k=20k=20k=20） 111 333 一次抛 20 比特挑战，一轮到位
一次 RSA 签名 000（无交互） 111 完全不需要来回

翻译成人话：用 1 比特挑战的 Fiat-Shamir 协议要来回 20 次、发 60 条消息才能达到 2−202^{-20}2−20 的安全；而一个 RSA 签名只要发一条消息，且不来回。这就是「零知识要付通信代价」的具体数量级。 也正因为如此，第十二讲 3 节的 Feige-Fiat-Shamir 才要把挑战从 1 比特扩到 kkk 比特——用「每轮更贵」换「轮数更少」，这是一笔很划算的买卖。

(4) 没有证明的假设

(4) 没有证明的假设：许多零知识协议（「证明知识」）本身依赖于和非对称技术一样的未经证明的假设（例如，分解的困难）。（PPT 第 22 页）

翻译成人话：零知识并没有给出更牢靠的数学地基。 Fiat-Shamir 族协议的安全性依赖「分解大整数难」「离散对数难」，而这些恰恰就是 RSA、ElGamal 依赖的、至今没有被证明的假设。任何一个假设被推翻，零知识鉴别和非对称签名会一起垮。

补这条评述值得和第十一讲做个对照。 第十一讲的 Shamir 门限方案是信息论安全的：攻击者即使拥有无限计算能力，少于 ttt 个分享也恢复不出秘密——它不需要任何困难假设。而零知识鉴别协议全是计算安全的：给攻击者足够的时间，它就能算出秘密。同样是「保护秘密」，两讲的数学地位完全不同。 这不是零知识技术的缺陷，而是鉴别这件事情本身的性质决定的：要在开放网络里完成鉴别，就必须有一个「公开可验但难伪造」的量，而这必然依赖难解问题。

(5) 零知识基与零知识：两个容易混淆的东西

(5) 零知识基与零知识：虽然有着严谨的理论支持，许多基于零知识概念的技术在实践中缺少形式化的零知识和 / 或正确属性的支撑，导致这一切的是出于效率或其它原因的参数选择问题。事实上，许多这类概念是渐进的，并不能直接应用到实用协议中来。（PPT 第 22 页）

这是五条里最需要警惕的一条。它区分了两个东西：

  • 「基于零知识概念的协议」（zero-knowledge-based）：设计思路来自零知识证明。第十二讲 2–5 节的四个鉴别协议都属于这一类。
  • 「已被形式化证明为零知识的协议」（zero-knowledge）：能用第十二讲 1.2 节定义 3 严格论证。

课件说：前者的很多实例，并没有真正满足后者的要求。 原因主要有两个：

  1. 参数选择为了效率而妥协。 比如为了省轮数把挑战空间取得很小、为了省通信把多轮并行化、为了省计算简化随机数生成——每一步都可能让形式化证明的前提失效。
  2. 理论结论是渐进（asymptotic）的。 定义 1、2、3 里的「可忽略」「多项式时间」都是关于安全参数 κ→∞\kappa\to\inftyκ→∞ 的陈述。它们告诉你「存在足够大的 κ\kappaκ 使协议安全」，但没有告诉你具体该取多大。从渐进结论到具体参数，中间还需要一大段工程分析。

补两个具体的「理论严谨、实践打折」例子。 第一个：把 ttt 轮交互并行执行能省通信，但并行重复下零知识性是否仍然成立，在密码学史上曾是长期未决的难题（后来被证明对一般的黑盒模拟并不成立）。第二个：第十二讲 5 节会用 Fiat-Shamir 变换把交互协议变成签名——做法是把「验证者的随机挑战」换成「哈希函数算出的挑战」，这样任何人都能复算、验证。这一步极其有效，但它的安全性证明需要把哈希函数当成随机预言机（random oracle），而这个模型本身也是一个未经证明的假设。所以「零知识 + 哈希 = 签名」这句话在实践里成立，在理论上是有条件的成立。

五条对比总表

把第十二讲 1.4 节的五点整理成一张表，方便对照记忆：

对比维度 零知识协议 传统非对称协议 谁更优
(1) 重复使用 不退化，可无限次使用，抗选择消息攻击 鉴别类方案需防重放；签名类方案有各自的攻击模型 零知识明显更优
(2) 需要的运算 只有模乘、模平方、模幂，不加密 需要加密 / 解密或签名 / 验签 零知识更简单
(3) 通信与计算开销 通常更大（需多轮） 通常更小（可一次完成） 非对称更省
(4) 依赖的假设 与 RSA 相同的未证明假设（分解、离散对数） 同样的未证明假设 打平，都不免费
(5) 理论保证的落地 很多「零知识基」方案缺少形式化证明；概念是渐进的 成熟标准与实现 非对称更成熟

翻译成人话：零知识协议的独门优势只有第 (1) 条（不退化）和第 (2) 条（无需加密）；第 (3)(4)(5) 条它都不占优，甚至更吃亏。所以选型时要问的不是「零知识是不是更先进」，而是「我是不是真的需要『不退化』这个性质」——如果需要（比如智能卡每次都要鉴别、且攻击者能大量观测），零知识就很值；如果不需要，传统方案更省事。

本节要点

  1. 一大类零知识协议是三次交互：A→BA\to BA→B 证据（承诺），A←BA\leftarrow BA←B 提问（挑战），A→BA\to BA→B 回答（应答）。
  2. 承诺的作用：把 AAA 锁死在 Ye(x)Y_{e}(x)Ye​(x) 这个合法答案集合里，让它无法「先看题再作答」；随机性保证每轮记录新鲜。
  3. 去掉承诺（先挑战后证据）会让冒充成功率升到 100%100\%100%——因为冒充者可以倒推出 x≡y2v−ex\equiv y^{2}v^{-e}x≡y2v−e。
  4. 循环把欺骗概率压到 k−tk^{-t}k−t，其中 kkk 是每轮挑战空间大小，ttt 是轮数；把 kkk 做大与把 ttt 做大是等价的两种省钱方式。
  5. 第十二讲 1.4 节的五点对比：零知识的优势是不退化（抗选择消息攻击）与无需加密；代价是通信/计算开销更大、依赖同样的未证明假设、很多「零知识基」方案缺少形式化证明。
  6. 渐进的理论结论不能直接翻译成具体参数；Fiat-Shamir 变换（用哈希替代随机挑战）也需要随机预言机假设。

  2. 为什么「先承诺、后挑战」的顺序不可交换？请给出一个冒充者利用「先看题」在 100%100\%100% 情况下通过的具体做法。
  3. 写出 k−tk^{-t}k−t 的含义，并解释为什么把 kkk 从 2 提到 2202^{20}220 与把 ttt 从 1 提到 20 效果相当。
  4. 「使用不退化」在公式上表现为哪个量不出现在概率表达式里？这与静态口令的差别是什么？
  5. 第十二讲 1.4 节说零知识协议「无需加密」，那它靠什么保护秘密？请结合 Fiat-Shamir 的运算说明。
  6. 判断并说明理由：「零知识协议比 RSA 更安全，因为它不依赖未证明的假设。」
答案
  1. A→BA\to BA→B：发证据 xxx（承诺 rrr，由 x≡r2(modn)x\equiv r^{2}\pmod nx≡r2(modn) 锁死）；A←BA\leftarrow BA←B：收挑战 eee；A→BA\to BA→B：发回答 yyy。承诺在前，挑战在后。
  2. 因为协议的安全性完全来自「AAA 在不知道题目的情况下先把自己锁死」。若顺序交换，冒充者可以先随机选 yyy，再倒推 x≡y2v−e(modn)x\equiv y^{2}v^{-e}\pmod nx≡y2v−e(modn)，交出的 (x,y)(x,y)(x,y) 必然通过验证，成功率 100%100\%100%。
  3. kkk 是每轮挑战的取值个数，ttt 是轮数，k−tk^{-t}k−t 是冒充者全部蒙对的概率。把 kkk 从 2 提到 2202^{20}220 相当于每轮就提供 20 比特安全性，与 20 轮 1 比特挑战的总安全性 2−202^{-20}2−20 相同，但只需一轮通信。
  4. 「已观测到的历史轮数 mmm」不出现在 Pr⁡[ Suc∣Histm ]=k−t\Pr[\,\mathsf{Suc}\mid\mathrm{Hist}_{m}\,]=k^{-t}Pr[Suc∣Histm​]=k−t 的右边，所以看到再多历史记录也不提高成功率。静态口令相反：每被偷听一次，攻击者就多一份可重放的材料，安全性单调下降。
  5. 靠数学上的计算难解性：x≡r2x\equiv r^{2}x≡r2 藏住 rrr 是因为模合数开平方难；v≡s2v\equiv s^{2}v≡s2 藏住 sss 是因为从 vvv 求 sss 等价于分解 nnn。全程只有模乘、模平方，没有加解密操作。
