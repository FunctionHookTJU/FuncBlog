3.3 存在骗子的秘密分享

3.3.1 地下掩体里的三条分享

上一节我们一直把 Shamir 门限方案（Shamir threshold scheme）当成一台可靠的机器：任意 ttt 份分享进去，秘密出来。课件在这里踩了一脚刹车，先讲了一个不好笑的故事（PPT 第 33 页）：

上校 Alice、Bob、Carol 在某个隔离区很深的地下掩体中。一天，他们从总统那里得到密码消息：「发射导弹，我们要根除邪恶国家。」Alice、Bob、Carol 出示他们的分享，但 Carol 拿出的只是一个随机数。她实际是一个和平主义者，不想发射导弹。由于 Carol 的错误输入信息，他们恢复出来错误的秘密。导弹还停留在发射井里。更糟糕的是，没人知道究竟是谁在其中捣鬼。

把故事翻译成协议语言：三个人参与一个 t=3t=3t=3 的门限恢复，各交一份分享。恢复算法照常运行——三个点插值出一条多项式，取常数项——于是它「成功」输出了一个数。问题在于这个数是假的，而且没有人能指出是谁干的。

这条故事线暴露了门限方案一个被反复忽略的前提：它假设所有提交的分享都是诚实产生的。门限方案通常只保证两件事：

  1. 任意 ttt 份诚实分享可以恢复秘密（正确性）；
  2. 任意 t−1t-1t−1 份分享得不到关于秘密的任何信息（保密性）。

它没有保证第三件事：伪造的分享会被发现（完整性）。而恢复过程恰恰对此毫无防备——它只是一次「照着公式算」，从不质疑输入。

补为什么「算错」比「报错」更危险？ 如果系统能直接报错（例如密钥校验失败），至少大家知道出事了。可这里插值永远成功：ttt 个点永远唯一确定一条次数低于 ttt 的多项式，无论这些点诚实与否。于是一个随机数被「平滑」成了一个看起来完全合法的秘密。课件那句「没人知道究竟是谁在其中捣鬼」，说的正是这种无声失败（silent failure）——错误被系统吞掉了，只留下一个错的结果。

补攻击者站在哪里？ 本节针对的是「恶意分享者」（dishonest shareholder）：他们手里本来就握着真的分享，所以能伪造出与真分享在格式上无法区分的假分享。这和「外部窃听者」完全是两回事——外部人连一个点都没有，随便编三个点毫无意义（下一节会看到，随机点几乎必然算出一个非法值）。课件讨论的是最难的情况：内鬼。

3.3.2 性质 1：先把「骗成功」定义清楚

课件接下来给出一条性质（PPT 第 34 页），它是整节的形式化目标：

性质 1　假定秘密 S∈{0,1,⋯ ,s−1}S\in\{0,1,\cdots,s-1\}S∈{0,1,⋯,s−1}。任何 t−1t-1t−1 个参与者 i1,i2,⋯ ,it−1i_1,i_2,\cdots,i_{t-1}i1​,i2​,⋯,it−1​ 仅有小概率 ε>0\varepsilon>0ε>0 可以伪造新的分享 Si1′,Si2′,⋯ ,Sit−1′S'_{i_1},S'_{i_2},\cdots,S'_{i_{t-1}}Si1​′​,Si2​′​,⋯,Sit−1​′​ 来欺骗第 ttt 个参与者。这里，欺骗第 ttt 个参与者意味着从 Si1′,Si2′,⋯ ,Sit−1′S'_{i_1},S'_{i_2},\cdots,S'_{i_{t-1}}Si1​′​,Si2​′​,⋯,Sit−1​′​ 和 SitS_{i_t}Sit​​，可以恢复出一个合法的秘密 S′S'S′，也就是 S′∈{0,1,⋯ ,s−1}S'\in\{0,1,\cdots,s-1\}S′∈{0,1,⋯,s−1}，但是这个秘密不正确，也就是 S′≠SS'\neq SS′=S。

这句话信息密度很高，逐块拆：

（1）秘密空间是有限的。 秘密从一个只有 sss 个元素的集合里取：

S∈{0,1,⋯ ,s−1},∣{0,1,⋯ ,s−1}∣=s.S\in\{0,1,\cdots,s-1\},\qquad \left| \{0,1,\cdots,s-1\} \right| = s .S∈{0,1,⋯,s−1},∣{0,1,⋯,s−1}∣=s.

翻译成人话：秘密不是「任意大的数」，而是 sss 个候选值之一——这正是实际应用的样子：一个 4 位口令（s=104s=10^{4}s=104）、一个「发射/不发射」的判定（s=2s=2s=2）、或者一段被编码成整数的消息。

（2）骗子是 t−1t-1t−1 个人。 他们离门限只差一份分享，所以只要再拉一个人（或骗一个人）就能恢复。

（3）骗子伪造的是「新分享」。 注意 Si1′,⋯ ,Sit−1′S'_{i_1},\cdots,S'_{i_{t-1}}Si1​′​,⋯,Sit−1​′​ 带撇号：这是骗子编出来的值，不是他们的真分享。他们当然会把真分享留着——事后被质询时可以拿出来装无辜。

（4）「骗成功」必须同时满足两个条件。 课件用的是「合法但不正确」，这两半都要：

  • 合法：S′∈{0,1,⋯ ,s−1}S'\in\{0,1,\cdots,s-1\}S′∈{0,1,⋯,s−1}，即算出来的东西落在秘密空间里，格式上像个真秘密；
  • 不正确：S′≠SS'\neq SS′=S，即内容确实被改掉了。

用一段伪代码把判定条件写死：

骗成功  ⟺  ( S' ∈ {0,1,...,s-1} )  且  ( S' ≠ S )
            └── 格式合法 ──┘         └── 内容错误 ──┘

骗失败  ⟺  ( S' ∉ {0,1,...,s-1} )          ← 一眼看穿是乱码
        或 ( S' = S )                       ← 白忙一场，结果没变

翻译成人话：光让受害者算错还不够——算出来的必须像个真秘密，否则受害者立刻知道出了事；可如果算出来恰好就是真秘密，那骗子的力气全白费。所以「骗成功」是一条很窄的缝。

（5）概率 ε\varepsilonε 可以任意小。 这是本节真正要证明的承诺，也是后面修改方案里模数 ppp 的取值依据。

补为什么这里只能用概率，不能做「绝对检测」？ 因为在 (t,n)(t,n)(t,n) 门限方案里有一个绕不过去的信息论事实：任何 ttt 个点都唯一确定一条次数低于 ttt 的多项式。当骗子凑齐 t−1t-1t−1 个伪造点、受害者手里握着第 ttt 个点时，这 ttt 个点一定能插出一条多项式——恢复算法没有「点不对」这个概念，它不可能主动停机。所以「发现伪造」只能做成概率性的：让受害者大概率领不到一套能骗过自己的伪造点。这是「检测」而不是「预防」，其精神与后面零知识证明里「以极大概率抓住作弊」完全一致。

补保密性与完整性不是一回事，容易串线。 教材常说「t−1t-1t−1 份分享泄露不了秘密」，那是保密性，靠的是多项式自由度（t−1t-1t−1 个点定不下一条次数低于 ttt 的多项式）。本节说「t−1t-1t−1 个骗子骗不过第 ttt 个人」，那是完整性，靠的是下一节把 xxx 坐标变成秘密——让骗子无法对准受害者「点射」，只能「盲打」。同一个数学对象，两种性质各管一头，读的时候要分清。

3.3.4 欺骗概率的上界是怎么来的

课件的证明（PPT 第 36 页）不长，但每一步都要看懂。先把原文摆出来：

把证明拆成五步，每步都用「翻译成人话」落地：

qS′(x):qS′(0)=S′,qS′(xij′)=dij′ (1≤j≤t−1).q_{S'}(x):\quad q_{S'}(0)=S',\qquad q_{S'}(x'_{i_j})=d'_{i_j}\ (1\le j\le t-1).qS′​(x):qS′​(0)=S′,qS′​(xij​′​)=dij​′​ (1≤j≤t−1).

翻译成人话：骗子并不是随便乱写数，他们的最优打法是「我先编好一条曲线，再把曲线上的点喂给你」。

第二步：受害者要解出 S′S'S′，假曲线必须通过他手里的真点。 受害者手里有真点 (xit, q(xit))(x_{i_t},\,q(x_{i_t}))(xit​​,q(xit​​))，它与骗子给的 t−1t-1t−1 个点一起插值。插出来的多项式正好是 qS′q_{S'}qS′​ 本身，当且仅当受害者的点也落在 qS′q_{S'}qS′​ 上：

翻译成人话：假曲线必须通过受害者手里那个真点，否则插出来的就是另一条曲线，常数项也就不是 S′S'S′ 了。

3.3.6 另一条路：承诺、摘要与纠错

补课件只给了机制 3 这一种思路。工程上还有两条更常用的路线，理解了它们，才能看懂第十二讲里零知识证明为什么要反复用「承诺」（commitment）。

路线一：每个份额配一个「公开承诺」。 分发时，除了把 (xi,di)(x_i,d_i)(xi​,di​) 秘密交给用户，还公开一个与 did_idi​ 绑定的值，例如

Ci=gdi mod p,C_i = g^{d_i}\bmod p ,Ci​=gdi​modp,

翻译成人话：把份额藏在指数上，公开 gdig^{d_i}gdi​。公开这个值不会泄露 did_idi​（这叫离散对数问题，第十二讲会详细讲），但任何人之后都可以用「CiC_iCi​ 是不是对得上」来核对一份份额有没有被篡改。

承诺方案有两个必须同时成立的性质：隐藏性（hiding，公开 CiC_iCi​ 不泄露 did_idi​）与绑定性（binding，同一个 CiC_iCi​ 不可能对应两个不同的 did_idi​）。有了它，恢复时每个人不仅交 did_idi​，还能被验证，因此可以定位到具体的作弊者——这是机制 3 做不到的。

路线二：多要几份分享，用纠错把坏人筛出来。 机制 3 的模型是「刚好 ttt 份、不知道谁坏」。如果愿意多取一些分享（比如 t+2et+2et+2e 份），就可以把「恢复秘密」变成「在含 eee 个错误的点集上做多项式插值」，用纠错码（error-correcting code）的思路把真值还原出来，同时把偏离曲线的点标为可疑对象。代价是分发更多份额、计算更复杂。

补这三条路线和第十二讲的关系。 「公开一个绑住秘密的值、之后用随机挑战检验对方有没有说谎」正是零知识证明的标准骨架。机制 3 用「随机坐标」制造概率，承诺方案用「随机挑战」制造概率——两者都是在赌对手猜不中我们的随机数。把这句话记住，第十二讲会反复回响。
