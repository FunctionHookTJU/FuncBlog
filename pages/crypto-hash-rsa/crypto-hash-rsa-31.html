MD5 的消息字使用次序（PPT 第 42 页）

PPT 原文：

MD5 压缩的每个 512 比特消息分组要经过 4 轮处理，第 1 轮以其 32 比特连续分组的初始顺序使用，而第 2 至 4 轮处理按如下三个置换计算出的顺序使用：

p2(i)=(1+5i) mod 16p_2(i) = (1 + 5i) \bmod 16p2​(i)=(1+5i)mod16
p3(i)=(5+3i) mod 16p_3(i) = (5 + 3i) \bmod 16p3​(i)=(5+3i)mod16
p4(i)=7i mod 16p_4(i) = 7i \bmod 16p4​(i)=7imod16
这里 i=0,1,…,15i = 0, 1, \ldots, 15i=0,1,…,15。

意思是：每一步要用一个消息字 X[k]X[k]X[k]。kkk 取多少，由当前是第几轮、第几步决定：

  • 第 1 轮：k=0,1,2,…,15k = 0, 1, 2, \ldots, 15k=0,1,2,…,15（按顺序用）
  • 第 2 轮：k=p2(i)k = p_2(i)k=p2​(i)，iii 从 0 到 15
  • 第 3 轮：k=p3(i)k = p_3(i)k=p3​(i)，iii 从 0 到 15
  • 第 4 轮：k=p4(i)k = p_4(i)k=p4​(i)，iii 从 0 到 15

把这三张"使用次序表"算出来（这就是附录 B 里那张表的来历，不要手抄，要会算）：

第 3 轮：p3(i)=(5+3i) mod 16p_3(i) = (5 + 3i) \bmod 16p3​(i)=(5+3i)mod16

第 4 轮：p4(i)=7i mod 16p_4(i) = 7i \bmod 16p4​(i)=7imod16

补手工验算两个，确认你理解了：

  • p2(2)=(1+5×2) mod 16=11 mod 16=11p_2(2) = (1 + 5 \times 2) \bmod 16 = 11 \bmod 16 = 11p2​(2)=(1+5×2)mod16=11mod16=11 ✓
  • p2(3)=(1+15) mod 16=16 mod 16=0p_2(3) = (1 + 15) \bmod 16 = 16 \bmod 16 = 0p2​(3)=(1+15)mod16=16mod16=0 ✓（注意这里"绕回来了"）
  • p4(2)=14 mod 16=14p_4(2) = 14 \bmod 16 = 14p4​(2)=14mod16=14 ✓
  • p4(15)=105 mod 16=105−96=9p_4(15) = 105 \bmod 16 = 105 - 96 = 9p4​(15)=105mod16=105−96=9 ✓

补为什么要打乱使用次序？三个理由：

  1. 让消息比特"被充分地交叉使用"。第 1 轮按顺序用，消息的局部字节先被吸收；第 2 至 4 轮打乱之后，相隔很远的字会被放到一起运算，扩散更快。
  2. 抵抗"差分分析"的常规手法。差分分析喜欢追踪"相邻比特/相邻字之间"的传播规律。打乱次序之后，攻击者没法用一个简单的线性模型描述"消息的哪一部分影响了输出的哪一部分"。
  3. 让每一轮"看起来不一样"。配合前面说过的"4 轮函数不同、常量不同、移位不同"，次序不同是这套"最大化轮间差异"策略的第四块拼图。

补注意这三个置换的系数：555、333、777。

  • p2p_2p2​ 的系数 555：gcd⁡(5,16)=1\gcd(5, 16) = 1gcd(5,16)=1 ✓（能遍历所有 16 个值）
  • p3p_3p3​ 的系数 333：gcd⁡(3,16)=1\gcd(3, 16) = 1gcd(3,16)=1 ✓
  • p4p_4p4​ 的系数 777：gcd⁡(7,16)=1\gcd(7, 16) = 1gcd(7,16)=1 ✓

这个条件必须满足：如果系数和 16 不互素（比如取 4），那么 kkk 只能取到 16 的几个值，有些消息字永远用不到——那就等于丢掉了消息的一部分，直接破坏单向性。所以"系数与 16 互素"是这三个置换能用的前提。 这是一个典型的"参数必须满足数论条件"的例子。
