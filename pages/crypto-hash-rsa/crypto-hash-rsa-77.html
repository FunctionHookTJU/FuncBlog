29. 步 计算 作用
（1） 用扩展 Euclidean 算法求 a,ba, ba,b 使 a⋅p+b⋅q=1a\cdot p + b\cdot q = 1a⋅p+b⋅q=1 得到两个"选择性消失的单位"：b⋅q≡1(modp)b\cdot q \equiv 1 \pmod pb⋅q≡1(modp) 且 ≡0(modq)\equiv 0 \pmod q≡0(modq)；a⋅pa\cdot pa⋅p 反之。只依赖 p,qp,qp,q，可预计算
（2） r≡c(p+1)/4(modp)r \equiv c^{(p+1)/4} \pmod pr≡c(p+1)/4(modp) ccc 的一个模 ppp 平方根
（3） s≡c(q+1)/4(modq)s \equiv c^{(q+1)/4} \pmod qs≡c(q+1)/4(modq) ccc 的一个模 qqq 平方根
（4） x≡(a⋅p⋅s+b⋅q⋅r)(modn)x \equiv (a\cdot p\cdot s + b\cdot q\cdot r) \pmod nx≡(a⋅p⋅s+b⋅q⋅r)(modn) CRT 组合：模 ppp 下只剩 b⋅q⋅r≡rb\cdot q\cdot r \equiv rb⋅q⋅r≡r，模 qqq 下只剩 a⋅p⋅s≡sa\cdot p\cdot s \equiv sa⋅p⋅s≡s → 所以 x≡r(modp)x \equiv r \pmod px≡r(modp)、x≡s(modq)x \equiv s \pmod qx≡s(modq) → x2≡cx^2 \equiv cx2≡c ✓
（5） y≡(a⋅p⋅s−b⋅q⋅r)(modn)y \equiv (a\cdot p\cdot s - b\cdot q\cdot r) \pmod ny≡(a⋅p⋅s−b⋅q⋅r)(modn) 同上，但得到 y≡−r(modp)y \equiv -r \pmod py≡−r(modp)、y≡s(modq)y \equiv s \pmod qy≡s(modq) → 也是平方根
（6） 4 个根 = ±x,±y(modn)\pm x, \pm y \pmod n±x,±y(modn) 正好覆盖 (±r,±s)(\pm r, \pm s)(±r,±s) 的 4 种组合 ✓

30. 三个角色：

角色 说明
① 唯一性 从 4 个候选里筛出 1 个（这是 Rabin 独有的需求——RSA 的解密本来唯一）
② 完整性/错误检测 4 个根都不符合 → 判定"非法密文"，拒绝
③ 抗选择密文攻击 拒绝"不合格式的密文"，打断攻击者的询问

为什么实际要复制 64 比特而不是 6 比特：

Pr⁡(一个随机根也满足冗余规则)=2−b\Pr(\text{一个随机根也满足冗余规则}) = 2^{-b}Pr(一个随机根也满足冗余规则)=2−b
  • b=6b = 6b=6：2−6=1/642^{-6} = 1/642−6=1/64——4 个根里有另一个也满足的概率约 3/64≈4.7%3/64 \approx 4.7\%3/64≈4.7%，太高了；
  • b=64b = 64b=64：2−64≈5.4×10−202^{-64} \approx 5.4 \times 10^{-20}2−64≈5.4×10−20——"4 个根里恰好有另一个也满足"的概率约 1.6×10−191.6 \times 10^{-19}1.6×10−19，完全可忽略。

所以 64 比特是"保证筛选唯一性"的安全长度。

31. 归约的方向：证明"能解 SQROOT ⟹ 能分解 nnn"。

（反方向显然：知道 (p,q)(p,q)(p,q) 就能套第 6.1 节的公式算平方根。）

做法：

输入：待分解的合数 n
①  随机选 x，满足 gcd(x, n) = 1
②  算 a ≡ x² (mod n)          ← 故意"造一个平方数"
③  调用 SQROOT 算法 R，输入 (a, n)
    → R 返回 a 的一个模 n 平方根 y
④  若 y ≡ ±x (mod n)：本次失败，换一个 x 重试
    否则：gcd(x − y, n) 给出 n 的一个非平凡因子 ✓

第④步为什么成立：y2≡a≡x2(modn)y^2 \equiv a \equiv x^2 \pmod ny2≡a≡x2(modn) 且 y≢±x(modn)y \not\equiv \pm x \pmod ny≡±x(modn) —— 正好是基本原理 1 的条件（nnn 的因子被"分配"在 y−xy-xy−x 和 y+xy+xy+x 之间，gcd⁡\gcdgcd 把它们分开）。

为什么"每次成功概率 1/2"：a=x2a = x^2a=x2 在模 nnn 下有 4 个平方根：{x,−x,z,−z}\{x, -x, z, -z\}{x,−x,z,−z}。其中 xxx 和 −x-x−x 是平凡的（返回它们会让第④步判定为"失败"），zzz 和 −z-z−z 是非平凡的（返回它们就成功）。RRR 返回哪一个是随机的，所以

Pr⁡(成功)=24=12\Pr(\text{成功}) = \frac{2}{4} = \frac{1}{2}Pr(成功)=42​=21​

——试 kkk 次全失败的概率是 2−k2^{-k}2−k，试 100 次是 10−3010^{-30}10−30，所以"以很高概率成功"。

32. 攻击做法：

  1. 攻击者自己随机选一个 mmm；
  2. 算 c≡m2(modn)c \equiv m^{2} \pmod nc≡m2(modn)——这和上面归约证明里的第②步一模一样；
  3. 把 ccc 交给 AAA 的解密机（当作一条正常密文），AAA 返回"某个"明文 yyy（AAA 不知道攻击者原本想的是 mmm，因为 ccc 有 4 个根）；
  4. 若 y≡±m(modn)y \equiv \pm m \pmod ny≡±m(modn)：本次失败，换 mmm 重试；否则 gcd⁡(m−y,n)\gcd(m - y, n)gcd(m−y,n) 给出一个素因子 ✓

要害：攻击者用方案的解密机"替代"了归约证明里的算法 RRR——"解密机 = 那个能算平方根的黑盒"。攻击者自己不做任何数学工作。

冗余规则为什么能挡住：

  • 提交含冗余的 mmm：AAA 按规则筛选，因为另外 3 个根"恰好也含冗余"的概率只有约 2−642^{-64}2−64 → AAA 返回的一定是 mmm 本身 → 攻击者得到的是他自己造的数，白问一次（原来期望的 1/2 概率变成了 2−642^{-64}2−64）；
  • 提交不含冗余的 mmm：4 个根都不满足规则 → AAA 判定"非法密文" → 拒绝、不做任何回应 → 攻击者什么也得不到。

前提："解密失败时不返回任何信息"必须成立。 如果解密机在拒绝时返回"格式错误"之类的信息，攻击者仍能区分两种 ccc——这个"能区分"本身就是信息泄露（Bleichenbacher 攻击针对 PKCS#1 v1.5 就是利用了这类"错误响应差异"）。正确做法是统一返回模糊的错误（或固定延迟后返回）。

34. 对称密码里的处境：

  • 认证容易：双方共享同一把密钥。接收方能正确解密（或验证 MAC），就说明发送方也持有这把密钥——基本可以认定是对方发的。
  • 不可否认不成立：因为双方的能力完全对等。发送方可以说"这是接收方自己伪造的"，而接收方无法反驳（他确实也有那把密钥能造出这条消息）。A 能做的事=B 能做的事⟹\text{A 能做的事} = \text{B 能做的事} \LongrightarrowA 能做的事=B 能做的事⟹ 无法区分"谁做的"。

公钥密码里实现的方式（PPT 的式子）：

Ekb(Ska(m))=Ekb(Dka(m))E_{k_b}\big(S_{k_a}(m)\big) = E_{k_b}\big(D_{k_a}(m)\big)Ekb​​(Ska​​(m))=Ekb​​(Dka​​(m))

内层 Dka(m)D_{k_a}(m)Dka​​(m)——用 A 的私钥做"解密"运算。因为只有 A 有 A 的私钥，所以"谁能算出这个值，谁就是 A"→ 提供认证和不可否认（A 事后无法抵赖）。

外层 EkbE_{k_b}Ekb​​——用 B 的公钥加密，提供机密性（只有 B 能解开）。

注意：实际数字签名要先做 Hash：Ska(h(m))S_{k_a}(h(m))Ska​​(h(m))——这也是第四讲 Hash 函数在第五讲的应用（第 1.2 节讲过"数字签名必须用 CRHF"，否则攻击者可以用碰撞"偷换"被签名的文件）。

35. 陷门单向函数是一个单向函数 f:X→Yf: X \to Yf:X→Y，并附加一条性质：给定一些额外信息（陷门信息），则给定任意 y∈Yy \in Yy∈Y 求 xxx 使 f(x)=yf(x)=yf(x)=y 由计算困难变得容易。

三个概念的关系：

普通函数：     正向容易，反向也容易
单向函数：     正向容易，反向难
陷门单向函数： 正向容易，反向难，但【有陷门的人】反向容易

陷门信息：

方案 函数 陷门信息
RSA f(x,n,e)=xe mod nf(x, n, e) = x^{e} \bmod nf(x,n,e)=xemodn ppp 和 qqq、或 φ\varphiφ、或 ddd（三者互相可推，所以任一个都行）
Rabin f(x,n)=x2 mod nf(x, n) = x^{2} \bmod nf(x,n)=x2modn ppp 和 qqq（只有这一样，因为 Rabin 没有 eee、ddd）

为什么只能叫"候选函数"：因为没人能在对"容易"和"计算困难"合理定义的前提下，明确证明陷门单向函数的存在性。事实上单向函数的存在性本身就是未知问题（它的存在蕴含 P≠NP\mathrm{P} \ne \mathrm{NP}P=NP，而后者是千禧年未解问题），陷门单向函数的存在性自然也是未知的。所以我们找到的只是"看起来像"的候选者。

这个措辞的意义（诚实而准确）：

所有实际使用的密码学，安全性都建立在"某个未被证明的假设"上\text{所有实际使用的密码学，安全性都建立在"某个未被证明的假设"上}所有实际使用的密码学，安全性都建立在"某个未被证明的假设"上
  • RSA 假设大整数分解困难（PPT 用词是"相信分解 nnn 是困难的"）；
  • Rabin 假设模合数开平方困难（但已证明它等价于分解）；
  • AES 假设没有比穷举更好的攻击（连归约都没有）。

"没人能证明它安全"和"它不安全"是两件事——一个方案可以"未被证明安全"但"在实践中极其可靠"。所以评估任何新方案时的正确追问是："你假设了什么难题是困难的？这个假设被检验了多久？"

为什么数字签名必须要它（两个理由）：

  1. 效率：对整个文件做签名要跑几秒的模幂；对固定长度的摘要（如 256 比特）签名每次都很快；
  2. 抗碰撞（更关键）：签名者只对摘要负责。如果攻击者能找到碰撞（两份不同文件 x≠x′x \ne x'x=x′ 但 h(x)=h(x′)h(x) = h(x')h(x)=h(x′)），他就可以先让签名者签一份无害文件，再把内容换成恶意文件——签名依然有效。

——所以数字签名必须用 CRHF（抗强碰撞），OWHF 是不够的。 这也正是 1.2 节"由不可信方控制输入内容 → 需要 CRHF，如数字签名"那条判据的由来。
