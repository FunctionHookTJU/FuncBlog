2　基本构造

对应 PPT 第 17–20 页。这一节只有 4 页，但它是整讲最值钱的一节——第 3 节的 MDC-2、SHA-1、MD5 全都在用同一个骨架。

2.1 迭代结构的一般模型（PPT 第 17–19 页）

高级视图（PPT 第 17 页）

PPT 用一张很简的框图给出了 Hash 函数的高层结构：

任意长度输入
     │
     ↓
┌─────────────────────┐
│  迭代压缩函数        │
└─────────────────────┘
     │
     ↓
  可选输出变换
     │
     ↓
固定长度输出

大白话：Hash 函数就是一台"压缩机器"——你把任意长的东西喂进去，它反复压、反复压，最后吐出一个固定长度的小块。

补这张图里最值得注意的三个字是"迭代"。为什么不直接用一个大函数把整个输入一次压完？因为：

  1. 输入长度不确定，没法设计一个固定规模的函数来处理任意长的输入；
  2. 就算设计得出来，每换一个输入长度就要换一套算法，不现实。

所以工程上统一采用迭代：把长输入切成固定大小的块，一块一块地吃，用一个固定规模的压缩函数反复处理。这样只需要设计那一个压缩函数就够了。

详细视图（PPT 第 18 页）

PPT 的详细框图（下图按原图的流程重排成 ASCII 版，逻辑完全一致）：

这个框图拆成"三大块"，每一块都要能自己讲出来：

块 名字 干什么 PPT 第 18 页的原话
第一块 预处理 把输入整理成固定长度的分组 "附加填充比特"、"附加长度分组"
第二块 迭代处理 用压缩函数 fff 一块一块地吃 "压缩函数 fff"、Hi−1H_{i-1}Hi−1​、HiH_iHi​、xix_ixi​
第三块 输出变换 把最后的链变量变成最终结果 "ggg"、"输出 h(x)=g(Ht)h(x) = g(H_t)h(x)=g(Ht​)"

补预处理里那两小步为什么必须有？

  1. 附加填充比特：输入的长度千奇百怪，必须把它补到分组长度的整数倍，才能"一块一块地吃"。关键细节：填充必须可逆地能确定原长度——如果填充规则有歧义，"消息 + 填充"就可能和"另一条消息 + 填充"长得一模一样，Hash 值也就一样了，这会直接导致碰撞。所以填充规则通常是"先补一个 1，再补一堆 0"（PPT 第 27 页 SHA-1、第 36 页 MD5 都是这么做的）。
  2. 附加长度分组：把原始消息的长度（不是填充后的长度）编成一个固定长度的字段附在末尾。它的作用有两个：一是让"哪些比特是填充的"变得无歧义，二是让总长度把消息长度也编进去了——两条长度不同的消息，填充后结构必然不同，这就挡住了"用长度差异制造碰撞"的一类攻击。

补"即使原始消息已满足要求，仍要填充"——这句 PPT 在第 27 页和第 36 页都说了一遍，是重要考点。 意思是不管输入长度是不是已经是分组长度的整数倍，都必须再填一整块（一个 1 + 若干 0 + 长度字段）。如果允许"刚好整除就不填"，那么"不填的 MMM"和"填了但恰好长得像不填的 M′M'M′"就会撞车。

迭代结构的一般公式（PPT 第 19 页）

PPT 原文：

HiH_iHi​ 表示第 iii 步的部分结果，输入为 x=x1x2⋯xtx = x_1 x_2 \cdots x_tx=x1​x2​⋯xt​ 的迭代函数的一般模型为

H0=IV;Hi=f(Hi−1,xi), 1≤i≤t;h(x)=g(Ht)。H_0 = IV; \quad H_i = f(H_{i-1}, x_i),\ 1 \le i \le t;\quad h(x) = g(H_t)。H0​=IV;Hi​=f(Hi−1​,xi​), 1≤i≤t;h(x)=g(Ht​)。
Hi−1H_{i-1}Hi−1​ 表示第 i−1i-1i−1 步和第 iii 步之间的 nnn 比特链变量，H0H_0H0​ 是预定义的开始值或初始值（IV）。最后一步用可选的输出变换 ggg 将 nnn 比特链变量映射为 mmm 比特结果 g(Ht)g(H_t)g(Ht​)，通常 g(Ht)=Htg(H_t) = H_tg(Ht​)=Ht​。

这个公式是全讲最该背下来的一行：

H0=IV,Hi=f(Hi−1,xi) (1≤i≤t),h(x)=g(Ht)H_0 = IV, \qquad H_i = f(H_{i-1}, x_i)\ (1 \le i \le t), \qquad h(x) = g(H_t)H0​=IV,Hi​=f(Hi−1​,xi​) (1≤i≤t),h(x)=g(Ht​)

逐项翻译：

符号 中文名 含义
x=x1x2⋯xtx = x_1 x_2 \cdots x_tx=x1​x2​⋯xt​ 格式化输入 预处理之后的输入，切成 ttt 块，每块是"一个分组"那么长
xix_ixi​ 第 iii 个消息分组 当前这一步要吃进去的数据块
Hi−1H_{i-1}Hi−1​ 链变量 上一步留下来的 nnn 比特中间结果
H0=IVH_0 = IVH0​=IV 初始值 一笔"启动资金"，预定义好的常量（Initialization Vector）
fff 压缩函数 整个 Hash 函数的核心；吃一个 nnn 比特链变量 + 一个分组，吐出一个新的 nnn 比特
HtH_tHt​ 最终链变量 吃完全部 ttt 块之后的链变量
ggg 输出变换（可选） 把 nnn 比特链变量变成 mmm 比特输出结果

大白话：像一个滚动的雪球。H0H_0H0​ 是手里那团雪球的初始大小；每滚过一块地（吃进一个分组 xix_ixi​），雪球就换一个新形状 HiH_iHi​；滚完全部 ttt 块，雪球最后的形状就是 HtH_tHt​；如果嫌雪球太大，最后再捏一下（ggg），得到最终大小。

补为什么这个结构被称为"迭代压缩"（iterated compression）？ 注意 fff 的输入是 n+n +n+ 分组长度 比特，输出只有 nnn 比特——它每走一步都在丢信息（这就是"压缩"）。信息只进不出，所以不可能从 HtH_tHt​ 反推出 xxx，这是单向性的来源。

补"链变量"这个词的来源：HiH_iHi​ 依赖于 Hi−1H_{i-1}Hi−1​，Hi−1H_{i-1}Hi−1​ 又依赖于 Hi−2H_{i-2}Hi−2​，一直连锁到 H0H_0H0​。这条链条意味着：改动输入的任何一个比特，都会沿着链条影响后面所有的 HiH_iHi​——这就是香农说的扩散（diffusion）。上一册讲 DES 时多次提到扩散，这里是同一件事在 Hash 函数里的体现。

补关于 ggg 的取值：PPT 说"通常 g(Ht)=Htg(H_t) = H_tg(Ht​)=Ht​"，也就是不做输出变换。SHA-1 和 MD5 都是这样（第 3 节）。什么时候需要 ggg 呢？当"链变量的长度"和"想要的输出长度"不一致时。比如 MDC-2（3.1 节）的链变量是 128 比特（两个 64 比特），而它输出 128 比特，就不需要 ggg。

补一个极易忽略但很重要的性质：这个迭代结构不保证抗碰撞，它只是"把问题归约下去"。也就是说：

如果压缩函数 fff 是抗碰撞的，那么整个迭代 Hash 函数 hhh 就是抗碰撞的。

这是一个**"归约"式命题**：它把"整个 Hash 函数抗碰撞"这个难以直接验证的性质，转化成了"那一个 fff 抗碰撞"这个可以逐条分析的性质。这就是为什么第 3 节后面所有的篇幅都在分析那一个压缩函数——MDC-2 的 fff、SHA-1 的 HSHAH_{SHA}HSHA​、MD5 的 HMD5H_{MD5}HMD5​。

（严格证明的思路：如果整个 hhh 出现碰撞，那么沿链条回溯，必然在某一步 Hi−1∥xiH_{i-1} \| x_iHi−1​∥xi​ 这一对上出现碰撞，或者最终 HtH_tHt​ 相同；两种情况都能构造出压缩函数 fff 的碰撞。这就把 hhh 的碰撞归约成 fff 的碰撞。）

2.2 实际安全需要的输出比特大小（PPT 第 20 页）

这一节回答一个非常实际的问题：nnn 要取多大才够用？

事实 5（PPT 第 20 页）

PPT 原文：

一个 nnn 比特输出的不带密钥 Hash 函数是理想安全的，如果：（1）给定一个 Hash 输出，产生一个原像和第二原像需要大约 2n2^n2n 次操作规模；（2）产生一个碰撞需要大约 2n/22^{n/2}2n/2 次操作规模。

（勘误：PPT 原文把 2n2^n2n 和 2n/22^{n/2}2n/2 印成了 2n 和 2n/2，是上标丢失的排版问题。含义是 222 的 nnn 次方与 222 的 n/2n/2n/2 次方，也就是第 0.8 节生日悖论算出来的那两个数。）

大白话：这是一个"标尺"。它说：

  • 一个理想的 nnn 比特 Hash 函数，找原像/第二原像该花的代价是 ≈2n\approx 2^n≈2n（除了一次次试，没有别的办法）；
  • 找碰撞该花的代价是 ≈2n/2\approx 2^{n/2}≈2n/2（生日效应免费帮你把指数砍了一半）。

补"理想安全"这个词的分量：这句话真正的意思不是"它很安全"，而是"它已经安全到不能再安全了"。因为不管你怎么设计，nnn 比特的输出空间里就只有 2n2^n2n 个值，随便乱试 2n2^n2n 次必然能撞上一个原像；而要找碰撞，2n/22^{n/2}2n/2 次也是躲不过的下界。所以任何 nnn 比特的 Hash 函数最多也就这个强度。

有了这把标尺，任何 Hash 函数的"好坏"就可以量化了——把它的实际攻击代价和 2n2^n2n、2n/22^{n/2}2n/2 比，差多少就说明它漏了多少。第 3 节的 MD5（输出 128 比特，理想强度 2642^{64}264）之所以被淘汰，就是因为实际攻击已经能突破这个下界了。

事实 6（PPT 第 20 页）

PPT 原文：

假定 nnn 比特输出的 Hash 函数，2802^{80}280 次操作在计算上不可能，则有： （1）OWHF 要求 n≥80n \geq 80n≥80； （2）CRHF 要求 n≥160n \geq 160n≥160； （3）MAC 对大部分环境要求 n≥64n \geq 64n≥64 以及 64–80 比特的密钥，如果有特别控制，可小到 n=32n = 32n=32 或 404040。

（勘误：PPT 原文写作"280次操作"，同样是上标丢失，应为 2802^{80}280 次操作。）

这三条数字的推导过程值得自己推一遍，推完就再也不会忘：

（1）OWHF 要求 n≥80n \geq 80n≥80

OWHF 要挡的是"抗原像 / 抗第二原像"，代价是 2n2^{n}2n。要求这个代价达到 2802^{80}280（假定的安全门槛）：

2n≥280⟹n≥802^{n} \geq 2^{80} \quad \Longrightarrow \quad n \geq 802n≥280⟹n≥80

（2）CRHF 要求 n≥160n \geq 160n≥160

CRHF 要挡的是"抗碰撞"，代价是 2n/22^{n/2}2n/2。要求它达到 2802^{80}280：

2n/2≥280⟹n2≥80⟹n≥1602^{n/2} \geq 2^{80} \quad \Longrightarrow \quad \frac{n}{2} \geq 80 \quad \Longrightarrow \quad n \geq 1602n/2≥280⟹2n​≥80⟹n≥160

（3）MAC 要求 n≥64n \geq 64n≥64，密钥 64–80 比特

MAC 的情形特殊：它的攻击者手上已经有合法样本（1.1 节定义 5 性质（3）的"给定 0 个或多个消息-MAC 值对"），所以它不需要那么长的输出。

  • 输出 n≥64n \geq 64n≥64：因为 MAC 输出本身可能有 2−n2^{-n}2−n 的"随机猜中"概率（攻击者瞎猜一个 MAC 值，碰巧对上的概率是 2−n2^{-n}2−n），n≥64n \geq 64n≥64 意味着猜中的概率低到 2−642^{-64}2−64，可以接受。
  • 密钥 64–80 比特：密钥要挡住穷尽搜索。
  • "如果有特别控制，可小到 n=32n=32n=32 或 404040"：如果这个 MAC 的使用频率很低（比如每天只认证几次），那么 2−322^{-32}2−32 的猜中概率乘以使用次数，总风险依然可以接受。这是一个典型的"安全是一个成本权衡"的例子。

补把这张表放到一起就是"安全强度 ↔ Hash 长度"对照表，考试和工程里都用得上：

（注：这张表按 PPT 的公式外推。可以看出 MD5 的 128 比特输出只对应 64 比特的抗碰撞强度，SHA-1 的 160 比特只对应 80 比特——这两个数字在后面 3.2、3.3 节会反复出现，因为它们正是这两种算法被淘汰的数量级原因。）

补为什么"2802^{80}280 次操作在计算上不可能"这个假定是合理的？ 做个粗算：假设一台机器每秒算 10910^9109 次，那么 280≈1.2×10242^{80} \approx 1.2 \times 10^{24}280≈1.2×1024 次需要 ≈1.2×1015\approx 1.2 \times 10^{15}≈1.2×1015 秒 ≈3.8×107\approx 3.8 \times 10^{7}≈3.8×107 年——三千八百万年。哪怕有一百万台这样的机器并行，也要 38 年，而且这是"平均"情形下的中值，最坏情况还要翻倍。这就是密码学里"安全门槛"的由来：不是数学上做不到，而是物理上不划算。

补门槛会随着算力上升而变。2802^{80}280 是 1990 年代的标准；今天（尤其考虑到专用硬件和 GPU 集群）许多场合已经按 21282^{128}2128 来要求了。这也解释了为什么 SHA-1（160 比特）在 2017 年被 Google 找到实际碰撞（SHAttered 攻击，用了约 2632^{63}263 的计算量，远低于理论上的 2802^{80}280），因为它的实际强度本来就只在 80 比特上下——算力一涨，就守不住了。

补第 2 节的总结：这两页 PPT 给出了三件东西：

  1. 一个通用的结构（迭代压缩），所有实际 Hash 函数都长这样；
  2. 一个理想强度的标尺（2n2^n2n 和 2n/22^{n/2}2n/2）；
  3. 一组具体的安全参数（n≥80/160n \geq 80 / 160n≥80/160，MAC 的 64 等）。

后面第 3、4 节的所有算法，都可以在这三个坐标上被定位：它用什么压缩函数？它的实际强度离理想值有多远？它的参数选得对不对？
