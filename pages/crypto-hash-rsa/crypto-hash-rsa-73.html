D.1 第四讲（密码 Hash 函数）

1. 两条：(1) 压缩——hhh 把任意有限长度的输入 xxx 映射为固定长度 nnn 的输出 h(x)h(x)h(x)；(2) 容易计算——给定 hhh 和 xxx，容易算出 h(x)h(x)h(x)。说它"太弱"是因为编程里的哈希表函数全都满足：输入有无穷多个、输出只有 2n2^n2n 个，按抽屉原理必然有碰撞；而这两条对"碰撞能不能找到"毫无要求。真正让它成为密码学 Hash 函数的是定义 2（MDC 的三条性质）和定义 5（MAC 的计算抵抗）。

2. 三者的区别就在"攻击者已经固定了什么、要找什么"：

性质 已经有什么 要找什么
抗原像 一个 Hash 值 yyy（没给输入） 任意一个 x′x'x′ 使 h(x′)=yh(x') = yh(x′)=y
抗第二原像 一个指定的输入 xxx 另一个 x′≠xx' \ne xx′=x 使 h(x′)=h(x)h(x') = h(x)h(x′)=h(x)
抗碰撞 什么都没有 任意两个 x≠x′x \ne x'x=x′ 使 h(x)=h(x′)h(x) = h(x')h(x)=h(x′)

自由度依次升高，所以难度依次降低（代价分别是 2n2^n2n、2n2^n2n、2n/22^{n/2}2n/2）。

3. 归约式的证明：假设存在算法 AAA 能攻破抗第二原像（输入 xxx，输出 x′≠xx' \ne xx′=x 且 h(x′)=h(x)h(x') = h(x)h(x′)=h(x)）。那么攻破抗碰撞可以这样做：随便挑一个 xxx，调用 AAA 得到 x′x'x′，于是 (x,x′)(x, x')(x,x′) 就是一对碰撞。所以"能抗碰撞"必然"能抗第二原像"。

反过来不行：抗碰撞的场景里攻击者连第一个输入都能自己挑（自由度更大、更难满足），所以"抗第二原像"不能推出"抗碰撞"。

4. OWHF = 定义 1 + 定义 2 的（1）（2）——即抗原像 + 抗第二原像。CRHF = 定义 1 + 定义 2 的（2）（3）——即抗第二原像 + 抗碰撞。

定义 4 没写"抗原像"是因为**"技术原因"**：不能从"抗碰撞"推出"抗原像"（这正是事实 2）。如果定义 4 把抗原像也写进去，那就不是"定义"而是"猜测"了。实践中几乎所有在用的 CRHF 都恰好具有抗原像性，所以工程上无影响。

5. 攻击步骤（利用碰撞伪造签名）：(1) 攻击者先准备一份无害的文件 xxx（比如普通合同），让签名者签它，拿到签名 sss；(2) 攻击者用碰撞攻击找到另一份恶意文件 x′x'x′（比如把房子送出去的合同），使 h(x′)=h(x)h(x') = h(x)h(x′)=h(x)；(3) 因为摘要相同，签名 sss 对 x′x'x′ 也有效。攻击者成功把"无害文件的签名"挪用到"恶意文件"上。

注意这里攻击者是自己挑两个输入去撞——正是定义 2 性质（3）的场景，所以必须抗强碰撞。OWHF 只保证"给定 xxx 找不到 x′x'x′"（性质 2），挡不住这种攻击。

6. n=256n = 256n=256：抗原像/第二原像 ≈2256\approx 2^{256}≈2256；抗碰撞 ≈2256/2=2128\approx 2^{256/2} = 2^{128}≈2256/2=2128。要同时达到 128 比特强度，需要 2n/2≥21282^{n/2} \ge 2^{128}2n/2≥2128，即 n≥256n \ge 256n≥256——256 正好够。（顺带：如果只想让抗原像达到 128 比特，n≥128n \ge 128n≥128 就够。）

8. 输入有无穷多个（任意有限长度），输出只有 2n2^n2n 个，按抽屉原理必然存在两个不同输入给出同一输出。所以密码学不可能要求"没有碰撞"，只能要求"找到碰撞在计算上不可行"——这就是"抗碰撞"这条性质的精确含义。处理方式就是把"不存在"这个不可能的目标，换成"难以找到"这个可达成的目标。

9. ggg 和 g′g'g′ 的作用是把 64 比特链变量"有选择地映射"成 56 比特的 DES 密钥（保留部分比特 + 插入两个固定比特，ggg 插 10、g′g'g′ 插 01）。如果直接用 64 比特链变量当 DES 密钥，那 8 个校验位对加密结果毫无影响——攻击者可以随意改动这 8 个位置而 Hash 值不变，这等于免费送上一堆碰撞。

10. 交叉交换是把两条链"绑在一起"：HiH_iHi​ 取左链的左半 + 右链的右半，Hi′H'_iHi′​ 取右链的左半 + 左链的右半。

去掉它的话，两条链就完全独立了——攻击者只要攻破其中一条就够了。输出虽然是 128 比特，但强度只剩约 2642^{64}264（一条链的抗碰撞强度），另一半输出长度白白浪费。加上交叉交换之后，要制造碰撞必须让两条链同时回到相同状态，强度才抬到 2642^{64}264 量级（对应 128 比特输出的理想值）。

11. 分组 512 比特，输出 160 比特，总步数 80 步（4 轮 × 20 步）。

选 160 比特而不是 128 比特，是因为事实 6：CRHF 要挡住"抗碰撞"（代价 2n/22^{n/2}2n/2），要达到 80 比特安全门槛就需要

2n/2≥280⟹n≥1602^{n/2} \ge 2^{80} \Longrightarrow n \ge 1602n/2≥280⟹n≥160

——160 是"按 2.2 节的要求反推出来的"，不是随便定的。（对比 MD5 的 128 比特，只对应 2642^{64}264 的抗碰撞强度，从出生起就偏低。）

它利用的是 Hash 的"抗碰撞"这条性质（即"抗碰撞不够——MAC 需要的是抗伪造，两者的安全目标不能直接互换"）。

23. 因为 MAC 要求"同一条消息永远给出同一个 MAC 值"（否则接收方无法验证），所以 IVIVIV 必须是双方约定的固定值。用全零只是最自然的选择。

这不会带来不安全，因为 CBC-MAC 不需要"同明文不同密文"这个性质（那是 CBC 加密的需求）。确认这一点的方法就是回到安全目标：CBC-MAC 要的是"抗伪造"，而随机 IVIVIV 对防伪造没有帮助（反而会破坏可验证性）。

（顺便：CBC-MAC 确实有弱点，但弱点在别处——见下一题。）

24. 证明只需把 CBC-MAC 的递推走两步：

设 H1=Ek(x1)H_1 = E_k(x_1)H1​=Ek​(x1​)、H2=Ek(x2)H_2 = E_k(x_2)H2​=Ek​(x2​)（两条单分组消息的 MAC），M=Ek(H1⊕z)M = E_k(H_1 \oplus z)M=Ek​(H1​⊕z)（2 分组消息 x1∥zx_1\|zx1​∥z 的 MAC）。

计算 X=x2∥(H1⊕z⊕H2)X = x_2 \| (H_1 \oplus z \oplus H_2)X=x2​∥(H1​⊕z⊕H2​) 的 MAC：

  • 第二块输入：新状态 = Ek(x2)=H2E_k(x_2) = H_2Ek​(x2​)=H2​；
  • 第二块：输入值 = H2⊕(H1⊕z⊕H2)=H1⊕zH_2 \oplus (H_1 \oplus z \oplus H_2) = H_1 \oplus zH2​⊕(H1​⊕z⊕H2​)=H1​⊕z（H2H_2H2​ 异或自己，消掉了）；
  • 所以最终 MAC = Ek(H1⊕z)=ME_k(H_1 \oplus z) = MEk​(H1​⊕z)=M ✓

要害：CBC-MAC 的递推只依赖"上一状态异或当前块"，所以只要能让异或结果"回到"一个已知值，后面的计算就完全复现——攻击者做的调整就是"补一个异或项把差抵消掉"。

25. 因为可选处理把密钥 k′k'k′ 塞在最后：Ht′=Dk′(Ht)H'_t = D_{k'}(H_t)Ht′​=Dk′​(Ht​)，Ht=Ek(Ht′)H_t = E_k(H'_t)Ht​=Ek​(Ht′​)。

攻击者不知道 k′k'k′，所以：

  • 他无法预测 Dk′D_{k'}Dk′​ 会输出什么——拼接就断了；
  • 他要"补一个异或项抵消差"这个做法，需要知道 XXX 的第一块运算结果在同一体系下是什么，而现在末尾多了一次不可预测的解密，这条路被封死。

它挡住的是"存在性伪造"（不能控制消息内容的伪造，如上一题那个 XXX），而不是"选择性伪造"。但正如 1.1 节说过的，存在性伪造在实际中通常无害，所以这个防护已经足够让 CBC-MAC 实用。

26. ppp 的作用是把密钥 kkk 填充成一个完整的分组长度，从而保证内部至少进行两次分组计算（PPT 原话）。

去掉 ppp 会发生"密钥位移攻击"：如果 kkk 不足一个分组，那么 k∥xk\|xk∥x 的第一块里"密钥还没填满就被消息补上了"，攻击者可以把 kkk 的一部分"推"到下一个分组去，从而在"消息 xxx"和"另一个消息 x′x'x′"之间建立对应关系。

用 ppp 把 kkk 撑满一个整分组之后，第一个分组就是"纯密钥分组"，不掺任何消息比特——"密钥"和"消息"在结构上被彻底分开。

27. 三个位置：

位置 用哪个子密钥 防住了什么
初始寄存器（IVIVIV） K0K_0K0​ 替代 A,B,C,DA, B, C, DA,B,C,D 攻击者无法预计算任何中间状态（他不知道起始状态）；这解决了 MD5 的"预计算攻击"隐患
轮常量 T[j]T[j]T[j] K1K_1K1​（一轮用一个子串）加到第 iii 轮的每个 T[j]T[j]T[j] 攻击者不知道常量，无法针对性构造消息让中间值达到特定状态（差分/模差分分析依赖"知道常量"）
消息末尾的附加块 K2K_2K2​ 构造 512 比特块 最后一块直接决定最终输出，密钥把关在最后一道；也挡住了长度扩展攻击（攻击者不知道 K2K_2K2​，没法预测"经过这一块之后状态会变成什么"）

三处覆盖了"起点、过程、终点"三段——"多点注入密钥"是设计带密钥 Hash 的通用手法。

28.

路线 优点 缺点
基于分组密码（CBC-MAC） 复用现有零件；零件已被长期信任；有硬件加速 需要分组密码的硬件/代码；有"可拼接"弱点（要用可选处理补救）
由 MDC 构造（h(k∥p∥x∥k)h(k\|p\|x\|k)h(k∥p∥x∥k)、HMAC） 最灵活（手头有什么 Hash 就能用什么）；HMAC 有可证明的安全性（归约到压缩函数的性质） 需要额外的安全性分析；朴素构造（h(k∥x)h(k\|x)h(k∥x)、h(x∥k)h(x\|k)h(x∥k)）很容易掉坑
定制（MD5-MAC） 性能最好（不必跑两遍、不必多个密钥） 专用性强——只能配 MD5，MD5 一弱它也跟着弱（所以 MD5-MAC 今天已不可用）
