附录 C　常见疑问 FAQ

Q1：Hash 函数又不加密，为什么值得单独讲一讲？

因为它出现在现代密码系统的每个角落，而且它是公钥密码的零件：数字签名要先对摘要签名（否则签名一份大文件要跑几秒的模幂）、RSA-OAEP 的 GGG 和 HHH 就是 Hash 函数、口令表存的是 Hash 值、消息认证码是"带密钥的 Hash"。第五讲里到处都在用第四讲的成果——先讲指纹、再讲公钥，顺序不是巧合。

Q2："抗原像"和"抗第二原像"看起来差不多，为什么要分两条？

差别在攻击者手里"已经固定了什么"：

  • 抗原像：输出是指定的（yyy 由别人给），攻击者要找任意一个 x′x'x′。这不是"还原原输入"，而是"找到一个能产生同样输出就行"（所以叫"原像不可逆"而不是"输入不可逆"）。
  • 抗第二原像：第一个输入是别人指定的（xxx），攻击者只能改第二个。

自由度不同，难度也不同。 这两条在逻辑上互不蕴含（事实 3）——所以必须分开列。

Q3：为什么说"抗碰撞"比"抗第二原像"强？

严格的证明是一个归约：假设存在算法 AAA 能攻破抗第二原像（给定 xxx 找到 x′x'x′），那么攻击抗碰撞就变成"先随便挑一个 xxx，调用 AAA 拿 x′x'x′"。所以"抗碰撞"能推出"抗第二原像"。 反过来推不出来——因为抗碰撞的场景里攻击者连"第一个输入"都能自己挑，自由度更大，所以更难满足。

Q4：为什么找碰撞只要 2n/22^{n/2}2n/2 次，找原像却要 2n2^{n}2n 次？

生日悖论。 找原像是"拿一个目标去撞"，2n2^n2n 个可能值里平均要试一半。找碰撞不是"撞一个指定目标"，而是"找任意一对互相撞上的"——而 kkk 个元素的配对数是 k(k−1)/2k(k-1)/2k(k−1)/2，按平方增长。当 k=2n/2k = 2^{n/2}k=2n/2 时，配对数 2n−12^{n-1}2n−1 就已经和 2n2^n2n 同量级了。

关键：人数是线性增长，配对数按平方增长——这就是"开方"的由来。

Q5：MD5 和 SHA-1 结构几乎一样，为什么被攻破的方式不同？

因为它们有三处关键差别：

MD5 SHA-1
逻辑函数 4 个各不相同 f2=f4f_2 = f_4f2​=f4​（重复）
循环移位 每步都变 固定 5 和 30
常量 64 个（每步不同） 4 个（每轮一个）

MD5 的"每步都变"（函数、常量、移位、消息字全都变）抵抗"对称性攻击"的能力更强，所以它被攻破靠的是"输出只有 128 比特（强度 64 比特）+ 大整数差分分析"；而 SHA-1 的"静态结构"给了攻击者更稳定的把手（尤其是 f2=f4f_2 = f_4f2​=f4​ 和固定移位），所以它被攻破时用的是另一条路线。结构相似不等于安全性相似。

Q6：为什么 PPT 说"MD5 发现了弱点"，但后面又有很多系统继续用它？

因为**"有理论弱点"和"能被实际攻击"之间有一个时间差**：

  • 1993 年就发现了"伪碰撞"；1996 年找到压缩函数的碰撞；
  • 2004 年王小云等才给出完整的 MD5 碰撞（约 2402^{40}240）；
  • 2007 年才有"预测前缀碰撞"（能造出一个正常文件 + 一个恶意文件共享 MD5）；
  • 2008 年才出现"Rogue CA"（实际伪造证书）。

从"警告"到"实际危害"隔了 11 年，很多系统在明知有风险的情况下继续用了很多年。 教训是："发现弱点"要立刻处理，不要等"实际攻击出现"。

Q7：CBC-MAC 为什么要把 IVIVIV 固定成全零？这样不就没有随机性、不安全了吗？

因为 CBC-MAC 和 CBC 加密的安全目标完全不同：

  • CBC 加密要的是"同一条明文两次加密结果不同"（所以才需要随机 IVIVIV）；
  • CBC-MAC 要的是"同一条消息永远给出同一个 MAC"（否则接收方没法验证！）。

所以去掉 IVIVIV 不是"疏忽"，而是"目标变了"。 这也解释了为什么 CBC-MAC 只输出最后一块（加密要输出全部密文块）——"只留最后一块"提供了不可逆的压缩，这是单向性的来源。

Q8：为什么 M=h(k∥x)M = h(k\|x)M=h(k∥x) 不行，M=h(x∥k)M = h(x\|k)M=h(x∥k) 也不行，非要 h(k∥p∥x∥k)h(k\|p\|x\|k)h(k∥p∥x∥k)？

因为两个朴素的构造各中一个坑：

构造 漏洞 原因
h(k∥x)h(k\|x)h(k∥x) 长度扩展 M=h(k∥x)M = h(k\|x)M=h(k∥x) 就是内部链变量状态，攻击者拿它当新起点继续往前跑，就得到 h(k∥x∥y)h(k\|x\|y)h(k∥x∥y)
h(x∥k)h(x\|k)h(x∥k) 碰撞 攻击者花 O(2n/2)O(2^{n/2})O(2n/2) 找到一对"内部状态相同"的 x,x′x, x'x,x′，加上同一个 kkk 后缀之后仍然相同

所以密钥必须"两头都放"——开头的 kkk 挡住碰撞（攻击者算不出 k∥pk\|pk∥p 之后的内部状态），末尾的 kkk 挡住扩展。那个 ppp 也有用：把 kkk 填满一个完整分组，避免"密钥位移攻击"。 这正是 HMAC 采用的思路。

Q9：RSA 的"安全性没被证明"到底是什么意思？

意思是只知道一个方向的蕴含：

分解 n  ⟹  攻破 RSA（成立）\text{分解 } n \;\Longrightarrow\; \text{攻破 RSA} \quad \text{（成立）}分解 n⟹攻破 RSA（成立）
攻破 RSA  ⟹  分解 n（未证明）\text{攻破 RSA} \;\Longrightarrow\; \text{分解 } n \quad \text{（未证明）}攻破 RSA⟹分解 n（未证明）

换个说法：我们只证明了"分解 nnn 是一条能攻破 RSA 的路"，没有排除"还有别的路（不分解 nnn 也能攻破）"。

Rabin 就不一样：它证明了两个方向都成立——任何攻破 Rabin 的方法都能被转换成"分解 nnn"的方法。所以 Rabin 的安全性是完全"可证明"的。

Q10：既然"知道 ddd 就能分解 nnn"，那"分解 nnn 困难"这个假设还有什么用？

很有用，而且正是它保证了 ddd 不可求。 逻辑链是这样的：

想求 d  ⟹  需要 φ  ⟹  等价于分解 n  ⟹  假设做不到\text{想求 } d \;\Longrightarrow\; \text{需要 } \varphi \;\Longrightarrow\; \text{等价于分解 } n \;\Longrightarrow\; \text{假设做不到}想求 d⟹需要 φ⟹等价于分解 n⟹假设做不到

"知道 ddd 就能分解 nnn"这条事实的作用是"把 ddd 和分解绑在一起"——它说明 ddd 的保密性和分解的困难性是同一个问题的两面。所以这条事实不是削弱了 RSA，而是加强了"必须保守 ddd"这个要求。

Q11：eee 可以取 3，为什么 ddd 不能取小？

因为**eee 是公开的，ddd 是秘密的**，这个差别决定了它们承受攻击的能力：

  • eee 小的问题（小消息、群发）靠的是"取模失效"——攻击者看到的是"没被取模的 mem^eme"。加随机填充就能破坏这个条件（让 mmm 变大、每次不同）。
  • ddd 小的问题靠的是"ed≡1(modφ)ed \equiv 1 \pmod \varphied≡1(modφ) 这个方程可以被解"——Wiener 用连分数、Boneh–Durfee 用格基约化，从 en≈kd\frac{e}{n} \approx \frac{k}{d}ne​≈dk​ 里把 ddd 挖出来。这个问题没有"填充"能帮上忙，因为它是密钥本身的性质。

所以工程上：eee 可以小（推荐 65537），ddd 必须 >n0.292> n^{0.292}>n0.292。

Q12：为什么"共模"设计（一个 nnn 配多个密钥对）绝对不能用？

因为每个合法用户本身就是一台"分解 nnn 的机器"：

  1. 他手里有自己的 (ei,di)(e_i, d_i)(ei​,di​)；
  2. 由事实 2，eidi−1e_i d_i - 1ei​di​−1 是一个通用指数；
  3. 套用"通用指数分解方法"，他以约 1/2 的概率就能分解 nnn；
  4. 拿到 p,qp, qp,q 就有 φ\varphiφ，于是能算出所有人的私钥 djd_jdj​。

——每个用户都能解密所有人的消息、伪造所有人的签名，整个信任体系崩溃。 顺便注意：真正的"共模攻击"（同一个 nnn 配不同的 eee、同一条消息）是另一个攻击，用扩展 Euclidean 算法线性组合两个指数即可恢复明文，连分解都不需要。

Q13：定时攻击听起来像是"物理攻击"，为什么要在密码课上学？

因为它门槛最低、场景最普遍：

  • 不需要物理接触——测一次次网络响应的时间就够了；
  • 不需要特殊仪器——一个高精度计时器即可；
  • 攻击的是"实现"，而不是"数学"——所以它不会因为"算法被证明安全"而消失。

它的教学价值在于"提醒你"："算法安全"和"系统安全"之间隔着"实现"这道鸿沟。 这就是为什么"用标准实现（OpenSSL 等）"这么重要——它们已经把这些坑填过了。

Q14：Rabin 明明"可证明安全"，为什么实际用得少？

三个工程原因：

  1. 解密有 4 个候选——必须靠冗余规则"猜"出唯一明文，多一道工序（RSA 的解密是唯一的）；
  2. 没有性能优势——加密只需 1 次模平方（比 RSA 的 17 次快），但 RSA 在混合加密里只加密几十字节的对称密钥，这点差别对整体速度没影响；而解密代价两者在同一量级；
  3. 签名同样麻烦——签名要做"开方"，也要处理"选哪个根"的问题。

所以"理论漂亮、工程麻烦"是准确的评价。 但它的价值不在实用，而在它是唯一一个"安全性可以严格证明"的公钥方案——给整个公钥密码指出了理论上的边界。

Q15：为什么这一讲的攻击几乎都不攻击"分解 nnn 困难"这个假设？

因为攻"设计"和"用法"比攻"数学"容易得多：

攻击 攻的是什么
3.3 小 eee 参数选择（小 eee + 群发同一消息）
3.4 小 ddd 参数选择
3.5 乘法特性 使用方式（有解密预言机 + 无格式校验）
3.6 共模 系统设计（共用模 nnn）
3.7 部分泄露 密钥管理（生成方式可预测）
3.10 前项搜索 使用方式（消息空间小 + 确定性加密）
3.12 定时攻击 实现细节

一个都没碰"分解 nnn 有多难"。 这就是为什么第 4 节（RSA 加密实践）和 3.11 节（OAEP）如此重要——RSA 的安全性有一大半取决于"怎么用"，而不是"算法本身"。

Q16：学完这两讲，最该记住的一句话是什么？

Hash 函数要抗碰撞，公钥密码要靠难题。

  • 第四讲的核心是"抗碰撞"——它决定了 Hash 值要多长（2n2n2n 的关系）、决定了数字签名能不能用、也决定了 MD5/SHA-1 为什么被淘汰；
  • 第五讲的核心是"靠难题"——RSA 靠"大整数分解被相信是困难的"（只是"相信"），Rabin 靠"模合数开平方被证明等价于分解"。而这两个讲的交点就是：所有实际密码学的安全性，都建立在"某个未被证明的假设"上。
