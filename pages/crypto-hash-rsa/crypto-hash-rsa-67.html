7　Rabin 加密的安全

补这一节是"Rabin 理论价值"的集中体现，也是整讲"证明最完整"的一节。

它的结论是：

攻破 Rabin⟺分解 n\text{攻破 Rabin} \quad \Longleftrightarrow \quad \text{分解 } n攻破 Rabin⟺分解 n

——即"安全性等价于大整数分解"。

第（1）条：类似 RSA 的问题（PPT 第 71 页）

PPT 原文：

（1） Rabin 公钥加密方案存在类似 RSA 加密中的小指数加密和前项搜索问题。前项搜索问题可以通过明文消息加盐来解决。

补这两条直接对应第 3.3 和 3.10 节：

问题 为什么 Rabin 也有
小指数加密问题 Rabin 的"指数"就是 2——比 RSA 的 e=3e=3e=3 还小！ 所以"m2<nm^2 < nm2<n 时取模失效"的问题更严重（只要 m<nm < \sqrt{n}m<n​，密文就没被取模）
前项搜索问题 因为 Rabin 也是确定性加密（同一条消息永远给出同一个 ccc），所以"预先算好字典"同样有效

补注意 Rabin 的"小指数问题"比 RSA 更严峻：

m2<n⟺m<n≈2k/2m^{2} < n \quad \Longleftrightarrow \quad m < \sqrt{n} \approx 2^{k/2}m2<n⟺m<n​≈2k/2

对 1024 比特的 nnn，"危险的 mmm" 达 25122^{512}2512 个——而 RSA 用 e=65537e = 65537e=65537 时，危险的 mmm 只有 2k/655372^{k/65537}2k/65537 量级（几乎不存在）。

所以 Rabin 更离不开"加盐/OAEP 类填充"。

补"前项搜索可以通过加盐解决"——措辞比 RSA 那一节更明确（第 3.10 节 PPT 说的是"给消息加盐是一种简单的阻止这类攻击的方法"，语气是"可以这样做"；这里说的是"可以通过……来解决"，语气是"这是解法"）。

本质上两处说的是同一件事：加随机数据，让"同一条消息"不再对应"同一个密文"。

第（2）条：被动攻击者的攻击等价于分解（PPT 第 71–72 页）

PPT 第 71 页原文：

（2） 作为被动攻击者的任务是从密文消息 ccc 恢复出明文消息 mmm。这就是平方根 SQROOT 问题。分解 nnn 和计算模 nnn 的平方根问题在计算上是等价的。 因此，假定分解 nnn 在计算上不可能，Rabin 公钥加密方案就可以证明能够抵抗被动攻击者的攻击。

补这条是整讲的"理论高峰"，要仔细读。

先明确"被动攻击者"是谁：他只能看（截获密文），不能问、不能改。所以他面临的唯一任务就是"给定 ccc，求 mmm"。

而"给定 ccc，求 mmm"恰好就是"给定 c≡m2(modn)c \equiv m^2 \pmod nc≡m2(modn)，求 mmm"——这就是 SQROOT 问题。

PPT 断言：

SQROOT⟺分解 n\text{SQROOT} \quad \Longleftrightarrow \quad \text{分解 } nSQROOT⟺分解 n

下面 PPT 给出证明（第 72 页）：

PPT 第 72 页原文：

理由. 假定有一个多项式时间的算法 RRR 可以解决 SQROOT 问题。这个算法就可以用来解决合数 nnn 的分解问题。随机选择一个整数 xxx 满足 (x,n)=1(x, n) = 1(x,n)=1，并计算 a≡x2(modn)a \equiv x^{2} \pmod na≡x2(modn)。接下来，算法 RRR 在输入为 aaa 和 nnn 的情况下运行，返回模 nnn 平方根 yyy。如果 y≡±x(modn)y \equiv \pm x \pmod ny≡±x(modn)，分解尝试失败，随机选择另一个整数 xxx 重复上述过程。否则，(x−y, n)(x - y,\ n)(x−y, n) 就可以得到 nnn 的一个非平凡因子 ppp 或 qqq。由于 aaa 有 4 个模 nnn 的平方根，每次尝试成功的可能性为 1/21/21/2。

补这个证明的结构是"归约（reduction）"，值得逐句读。

要证明的是：

能解 SQROOT⟹能分解 n\text{能解 SQROOT} \quad \Longrightarrow \quad \text{能分解 } n能解 SQROOT⟹能分解 n

（"⟸\Longleftarrow⟸"那个方向是显然的：知道 p,qp, qp,q 就能套第 6.1 节的公式算平方根。所以两个方向合起来才是"等价"。）

证明的做法是"把分解问题归约到 SQROOT"：

输入：要分解的合数 n
        ↓
①  随机选 x，满足 gcd(x, n) = 1
        ↓
②  计算 a ≡ x² (mod n)          ← 故意"造一个平方数"
        ↓
③  调用"SQROOT 算法 R"，输入 (a, n)
        ↓
    R 返回 a 的一个模 n 平方根 y
        ↓
④  检查：y ≡ ±x (mod n) 吗？
        │
   ┌────┴────┐
   ↓         ↓
  是         否
   ↓         ↓
 失败，      成功！
 换个 x     gcd(x − y, n) 给出 n 的非平凡因子
 重试

补第④步为什么成立？看这个推理：

yyy 是 aaa 的平方根，而 a=x2a = x^2a=x2，所以：

y2≡a≡x2(modn)⟹y2−x2≡0(modn)y^2 \equiv a \equiv x^2 \pmod n \quad \Longrightarrow \quad y^2 - x^2 \equiv 0 \pmod ny2≡a≡x2(modn)⟹y2−x2≡0(modn)
⟹(y−x)(y+x)≡0(modn)\Longrightarrow \quad (y - x)(y + x) \equiv 0 \pmod n⟹(y−x)(y+x)≡0(modn)

又因为 y≢±x(modn)y \not\equiv \pm x \pmod ny≡±x(modn)（这是第④步判定的"否"分支），所以：

  • y−xy - xy−x 不是 nnn 的倍数，也不是 0；
  • y+xy + xy+x 也不是 nnn 的倍数；
  • 但它们的乘积是 nnn 的倍数 —— 这就意味着 nnn 的因子被"分配"在 y−xy-xy−x 和 y+xy+xy+x 两者之间了。

于是 gcd⁡(y−x,n)\gcd(y - x, n)gcd(y−x,n) 必然给出一个非平凡因子。 ✓

补这和 3.2.1 节的"基本原理 1"是同一个论证：

x2≡y2(modn)且x≢±y(modn)⟹gcd⁡(x−y,n) 给出非平凡因子x^2 \equiv y^2 \pmod n \quad \text{且} \quad x \not\equiv \pm y \pmod n \quad \Longrightarrow \quad \gcd(x - y, n) \text{ 给出非平凡因子}x2≡y2(modn)且x≡±y(modn)⟹gcd(x−y,n) 给出非平凡因子

——这里只是把"找一对 x,yx, yx,y"的动作，变成了"用 RRR 从 x2x^2x2 反推一个 yyy"。

补"每次尝试成功的可能性为 1/21/21/2"这个数字的来历：

a=x2a = x^2a=x2 在模 nnn 下有 4 个平方根（第 5.1 节讲过）：

{x, −x, z, −z}\{x,\ -x,\ z,\ -z\}{x, −x, z, −z}

其中 xxx 和 −x-x−x 是"平凡的"（因为算法 RRR 如果返回这两个，第④步判定为"是"，就失败了）。

另外两个 z,−zz, -zz,−z 是"非平凡的"（返回它们，第④步判定为"否"，就成功了）。

RRR 返回哪一个是"随机的"（从攻击者的角度看），所以：

Pr⁡(成功)=24=12\Pr(\text{成功}) = \frac{2}{4} = \frac{1}{2}Pr(成功)=42​=21​

补——所以"多试几次必然成功"：试 kkk 次全部失败的概率是 2−k2^{-k}2−k。试 20 次失败的概率是百万分之一；试 100 次是 10−3010^{-30}10−30。

补这个证明的"严谨性"值得注意，它和 RSA 的处境对比一下：

RSA Rabin
证明"知道 p,qp,qp,q 就能解密" ✅ 有（第 1.1 节的正确性证明） ✅ 有（第 6.1 节的公式）
证明"能解密就能分解 nnn" ❌ 没有 ✅ 有（本节的归约）
结论 安全性只在一个方向成立 两个方向都成立 → 等价

补所以 PPT 说"就可以证明能够抵抗被动攻击者的攻击"——"证明"这两个字是这一节的重量所在。

注意这里的"证明"是针对"被动攻击者"的。主动攻击者（能提问的）见第（3）（4）条。

第（3）条：对主动攻击者的选择密文攻击（PPT 第 73 页）

PPT 原文：

（3） 对于主动攻击者，Rabin 公钥加密存在选择密文攻击问题。这样的攻击可以按如下步骤进行。攻击者选择一个随机整数 mmm 并计算 c≡m2(modn)c \equiv m^{2} \pmod nc≡m2(modn)。攻击者提交 ccc 给 AAA 的解密机，它将解密 ccc 并返回某个明文消息 yyy。由于 AAA 不知道明文消息 mmm，并且 mmm 为随机选择，明文消息 yyy 未必就是同一个消息 mmm。如果随机返回，将有 1/21/21/2 可能性，yyy 不等于 ±m(modn)\pm m \pmod n±m(modn)，在这种情况下，(m−y, n)(m - y,\ n)(m−y, n) 就是 nnn 的一个素数因子。否则，攻击可以换新的 mmm 重复以上过程。

补这个攻击"照搬了第（2）条的证明，把方案本身变成了攻击工具"——非常精彩。

看它的做法：

攻击者要分解 n：

①  自己随机选一个 m
        ↓
②  算 c ≡ m² (mod n)          ← 这和"第（2）条证明里的第②步"一模一样！
        ↓
③  把 c 交给 A 的解密机（当作一条正常的密文）
        ↓
    A 解密，返回"某个"明文 y
    （注意：A 不知道真实的 m，因为 m 是攻击者自己造的！
     而 c 有 4 个根，A 只能"挑一个它认为对的"）
        ↓
④  检查 y ≡ ±m (mod n) 吗？
        ↓
   ┌────┴────┐
   ↓         ↓
  是         否（概率 1/2）
   ↓         ↓
 换个 m      gcd(m − y, n) 给出 n 的一个素因子
 重试

补关键在第③步：为什么 AAA 会返回"不一定是 mmm"的东西？

因为 ccc 有 4 个平方根，而 AAA 只知道 ccc、不知道"攻击者原本想的是哪一个根"。

  • 如果 AAA 恰好选中了 ±m\pm m±m → 攻击者第④步判定为"是"，这次白问，换 mmm 重试；
  • 如果 AAA 选中了另外两个根之一 → 攻击者立刻拿到一对"y2≡m2(modn)y^2 \equiv m^2 \pmod ny2≡m2(modn) 但 y≢±my \not\equiv \pm my≡±m"→ gcd⁡(m−y,n)\gcd(m-y, n)gcd(m−y,n) 给出因子。

补——所以攻击者"不需要做任何数学工作"，他只是"用方案自己的解密机，替自己完成第（2）条证明里的"调用算法 R"那一步"。

这个攻击的聪明之处在于：

方案的正确性依赖"知道 (p,q) 就能算出 4 个根"\text{方案的正确性依赖"知道 } (p,q) \text{ 就能算出 4 个根"}方案的正确性依赖"知道 (p,q) 就能算出 4 个根"
而攻击者正是让「知道 (p,q) 的那一方」帮他算一个根！\text{而攻击者正是让「知道 } (p,q) \text{ 的那一方」帮他算一个根！}而攻击者正是让「知道 (p,q) 的那一方」帮他算一个根！

——"解密机就是那个算法 RRR"。

补注意 Rabin 比 RSA 在这件事上更"脆弱"：

RSA Rabin
解密结果唯一吗 唯一（m=cdm = c^dm=cd） 4 个候选
攻击者能否"让解密机返回一个≠原值的根" 不能（唯一） 能（概率 1/2）
结果 3.5 节那个攻击需要"同态 + 无格式校验"两个条件 只要"解密机肯回答"就够了

补所以 Rabin 的"4 个根"这个特性，既是"解密不确定"的原因，也是"选择密文攻击更容易"的原因——同一个性质的两面。

第（4）条：用冗余规则挡住选择密文攻击（PPT 第 74 页）

PPT 原文：

（4） 如果将冗余规则用于以上情况，则 Rabin 公钥加密方案将不再存在选择密文攻击问题。如果攻击者选择一条消息 mmm 并具有规定的冗余并将 c≡m2(modn)c \equiv m^{2} \pmod nc≡m2(modn) 提交给 AAA 的加密机，加密机将以非常高的概率返回消息 mmm 本身给攻击者（由于其它 3 个 ccc 的模平方根有非常大的概率不包含规定的冗余），则将不会提供给攻击者任何信息。另一方面，如果攻击者选择不包含冗余的消息 mmm，则有非常高的可能性 4 个模平方根都不具有需要的冗余形式。在这种情况下，解密机将认为对 ccc 的解密失败并对攻击者不做答复。因此，Rabin 公钥加密通过增加适当的冗余规则将提高其实用价值。

（勘误：PPT 原文"提交给 AAA 的加密机"按上下文应为"解密机"——这一段的场景是攻击者拿密文去问解密结果，不是加密。）

补这一段把"冗余规则怎么挡住上面的攻击"说清楚了。分两种情况看：

        ↓
攻击者拿不到任何信息 ✓

补这就把两条路都堵死了：

攻击者的选择 会发生什么 攻击者得到什么
提交含冗余的 mmm A 返回 mmm 本身 什么也没得到（mmm 是他自己造的）
提交不含冗余的 mmm A 拒绝、不回应 什么也没得到

补所以 PPT 的结论"不再存在选择密文攻击问题"是有条件的：

"解密机在解密失败时不返回任何信息"——这个条件必须成立\text{"解密机在解密失败时不返回任何信息"——这个条件必须成立}"解密机在解密失败时不返回任何信息"——这个条件必须成立

补这一点在工程上非常重要：

如果解密机在拒绝时返回"错误信息"（比如"解密失败：格式不正确"），那么攻击者仍然能区分"含冗余"和"不含冗余"两种 ccc——这个"能区分"本身就是信息泄露（在密码学里叫**"预言机式的信息泄露"**）。

正确的做法是：统一返回一个模糊的错误（或者固定延迟后返回），让攻击者无法区分"格式错"和"其他错"。

补这就是为什么"解密失败时怎么响应"是一个需要认真设计的工程问题（历史上 Bleichenbacher 攻击针对 PKCS#1 v1.5 就是利用了这类"错误响应的时间/内容差异"）。

补第 7 节的总结：Rabin 安全性的三段式

把四层结论串起来：

（1）Rabin 也有 RSA 的那些"使用层面"的问题（小指数、前项搜索）
      → 用加盐/填充解决

（2）对被动攻击者：安全性 ⟺ 分解 n
      → 这是可证明的（归约：能开方 ⇒ 能分解）

（3）对主动攻击者：存在选择密文攻击
      → 攻击者用方案的解密机来"替代"分解算法

（4）加冗余规则之后：选择密文攻击被挡住
      → 前提是"解密失败时不返回信息"

补这段"三段式"其实是一个通用模式：

裸方案的数学安全性  ⟶  主动攻击者带来的新威胁  ⟶  用填充/冗余补救\text{裸方案的数学安全性} \;\longrightarrow\; \text{主动攻击者带来的新威胁} \;\longrightarrow\; \text{用填充/冗余补救}裸方案的数学安全性⟶主动攻击者带来的新威胁⟶用填充/冗余补救

——和 RSA 的路径一模一样（RSA 是"分解困难 → 乘法特性的选择密文攻击 → OAEP"）。

所以第 3 节和第 7 节的结构是对称的：任何"裸的公钥加密方案"都不够用，必须加一层"编码/填充"。

补这一节的"理论价值"落到哪里？

落到一个很实在的结论上：

Rabin 的安全性有严格的数学保证（等价于分解），但"保证"只覆盖被动攻击者。要挡住主动攻击者，仍然要靠工程手段（冗余规则 + 谨慎的错误响应）。

——"可证明安全"不是万能的，它需要一个"正确划定的攻击模型"。 这个认识比记住"Rabin 等价于分解"这个结论更有价值。
