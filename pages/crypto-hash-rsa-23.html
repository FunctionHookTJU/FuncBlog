3.3 定制的 Hash 函数：MD5（PPT 第 34–43 页）

MD5 的来历与地位（PPT 第 34 页）

PPT 原文：

MD5 是 1992 年由 Rivest 提出的无密钥 Hash 函数。MD5 是 MD4（1990 年提出）的增强版本。MD5 对任意长度的消息产生 128 比特的 Hash 值。MD4 在 2802^{80}280 次压缩函数计算下已经找到了碰撞，因此，不再被推荐用做抗碰撞的 Hash 函数。近年来，MD5 也发现了一些弱点。

这段话里有三个名字要分清：

算法 年份 作者 输出 状态
MD4 1990 Rivest 128 比特 已被攻破（2802^{80}280 次压缩函数计算下找到碰撞），不推荐
MD5 1992 Rivest 128 比特 本节的算法；"也发现了一些弱点"
SHA-1 1995 NIST 160 比特 上面 3.2 节讲过

补Rivest 就是第五讲 RSA 里的那个 R（Rivest–Shamir–Adleman 的 R）。同一个人既设计了 RSA，也设计了 MD4/MD5——这两条线在第五讲会汇合（RSA-OAEP 用 Hash 函数当零件，而 Rivest 两边都参与了）。

【注】关于"MD4 在 2802^{80}280 次压缩函数计算下已经找到碰撞"这句：要小心读——它的意思是"用 2802^{80}280 次压缩函数计算这个规模的代价就能找到碰撞"，也就是 MD4 的实际抗碰撞强度只有约 80 比特。而按 2.2 节事实 5，128 比特输出理想情况下应该有 2128/2=2642^{128/2} = 2^{64}2128/2=264 的抗碰撞强度。

等一下——2802^{80}280 比 2642^{64}264 大，这不应该算"太弱"啊？这里要说清楚一个重要的坑：

第 2.2 节的 2n/22^{n/2}2n/2 是"理想下界"，也就是说"任何 128 比特的 Hash 函数都不如比 2642^{64}264 更难挡住碰撞"——因为攻击者总能靠生日效应在 2642^{64}264 次内撞上。所以 2802^{80}280 次找到碰撞意味着"攻破了理想下界"：一个 128 比特的 Hash 函数，本来只需要 2642^{64}264 就能被生日攻击撞上，而"有结构的攻击"按理不该比这个更便宜。

补这里要区分两种"攻破"的含义：

攻击类型 代价 含义
生日攻击（通用、对任何算法都有效） 2642^{64}264 不是"攻破"，只是"达到了理论下界"
结构性攻击（针对算法缺陷） 2802^{80}280？2602^{60}260？ 如果低于 2642^{64}264，才算真正"攻破"

实际上 MD4 的攻击代价远低于 2642^{64}264（后来的实际结果甚至低于 2402^{40}240）。PPT 里这个 2802^{80}280 大概是引用了一个早期结果。记住结论就行：MD4 的碰撞已经被找到，所以不能用。

补对 MD5 的那句"近年来，MD5 也发现了一些弱点"要特别重视。 这句轻描淡写的话在 1990 年代是"预警"，在今天是结论：

时间 事件 代价
1993 den Boer & Bosselaers 找到"伪碰撞" —
2004 王小云等给出 MD5 的实际碰撞（两份不同消息同一个 MD5） 约 2402^{40}240
2007 可构造"预测前缀碰撞"，能做出一个正经文件 + 一个恶意文件共享同一个 MD5 秒级
2008 Rogue CA 事件：实际伪造了一个微软签名的 CA 证书 实际攻击

结论：MD5 绝对不能用于数字签名、证书这类需要抗碰撞的场景。它今天唯一的正当用途是"校验下载文件有没有传坏"（这类场景不担心有人恶意构造碰撞）。
