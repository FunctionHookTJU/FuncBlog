7.1.4 RSA 签名的执行

这一小节全是工程问题。PPT 一共列了五个（1.4.1 到 1.4.5），每个都对应真实系统里踩过的坑。

7.1.4.1 分块问题

问题的来源（PPT 第 14 页）

一种对 RSA 的常用方法是签名一条消息再对签名结果加密。必须考虑在执行这一过程时两个模的长度。假定 A 希望签名再加密一条消息给 B。假定 (nA,eA)(n_A,e_A)(nA​,eA​) 和 (nB,eB)(n_B,e_B)(nB​,eB​) 分别是 A 和 B 的公开密钥。如果 nA>nBn_A>n_BnA​>nB​，则 B 有可能不能正确恢复出消息。

翻译成人话：A 要给 B 发"签名+加密"的消息（这是通信中常见需求：既要保密又要能认证）。流程是：

  1. A 用自己的私钥签名：s=mdA mod nAs=m^{d_A}\bmod n_As=mdA​modnA​（结果 sss 是"模 nAn_AnA​ 世界"里的数，可能很大）；
  2. A 再用 B 的公钥加密 sss：c=seB mod nBc=s^{e_B}\bmod n_Bc=seB​modnB​。

问题出在第 2 步：sss 可能比 nBn_BnB​ 大，取模之后信息丢了——B 拿到的不是原来的 sss，最后解出来的自然不是 mmm。

  • s=59847900s=59847900s=59847900，而 nB=55465219n_B=55465219nB​=55465219 —— s>nBs>n_Bs>nB​！

  • B 解密拿到的是 438268143826814382681（正是 s^\hat ss^），而不是 598479005984790059847900；

三种解决办法（PPT 第 16–19 页）

(1) 调换顺序。 如果先做小模操作再做大模操作，不正确解密的问题将不会出现。也就是说，如果 nA>nBn_A>n_BnA​>nB​，则实体 A 应该先使用 B 的公开密钥加密消息，再用自己的秘密密钥签名加密的消息。当然，最好的操作顺序通常是先签名消息再加密签名，原因是如果 A 先加密再签名，攻击者可以移除该签名而换上自己的签名。虽然攻击者并不知道具体签名的内容，这仍然是对攻击者十分有利的情形。因此，调换顺序并不是最好的解决方法。

翻译成人话：先加密再签名，等于"把一封信装进信封、再把信封口封上"——任何人都能换掉信封（把 A 的签名剥掉换成自己的）。虽然攻击者看不懂信，但他能声称"这封信是我发出去的"。所以 (1) 不可取。

(2) 每个实体两个模。 每个实体把用于签名的模和加密的模分开。如果每个实体的签名的模都小于系统中所有用来加密的模，则不正确解密的情况将不再会发生。这种方法可以通过要求加密的模使用 t+1t+1t+1 比特的数，而签名模使用 ttt 比特的数来实现。

翻译成人话：既然出问题是因为"签名用的模比加密用的模大"，那就干脆立法规定：签名模一律比加密模小（差一个比特就够）。这样"先签名后加密"就永远安全。代价是每个实体要维护两对密钥，而且要保证"签名模 < 所有人加密模"这个全局约束（实践中用固定长度区间来实现）。

(3) 预先设定模的形式。 这种方法是仔细选择素数 ppp 和 qqq，以使它们的乘积 nnn 具有特殊的形式：最高位为 1 接下来的连续 kkk 位都是 0。具有这种形式的 ttt 比特的模 nnn 可以这样产生：对于 nnn 具有需要形式应该满足

2t−1<n<2t−1+2t−k−12^{t-1}<n<2^{t-1}+2^{t-k-1}2t−1<n<2t−1+2t−k−1

(3)（续） 对模 nnn 的这一选择并不能完全解决不正确解密问题，但是可使出现不正确解密情况的概率可以忽略。假定 nAn_AnA​ 是模并且 s≡mdA(modnA)s\equiv m^{d_A}\pmod{n_A}s≡mdA​(modnA​) 是对消息 mmm 的签名。进一步假定 sss 在最高的 k+1k+1k+1 比特位中有一位为 1，而不是首位。由于 sss 应该小于 nAn_AnA​，sss 的最高位必须为 0，因此，sss 小于一般形式模产生的结果。在 sss 最高的 k+1k+1k+1 比特位中首位为 1 的概率不超过 1/(2k)1/(2^{k})1/(2k)。当 kkk 选择 100 的时候，这一概率可以忽略。

翻译成人话：

  • 让模 nnn 的二进制形式长得像 1 000...0 xxx...x（最高位 1，紧接着 kkk 个 0）；
  • 签名 s<ns<ns<n，所以 sss 的最高位也是 0，也就是说 sss 和 nnn 相比"头部还有一段空隙"；
  • 只要 sss 落在 nnn 里而不"超出头部那段空隙"，就不会发生"s>nBs>n_Bs>nB​ 被折叠"的事；
  • 只有 sss 在最高 k+1k+1k+1 位里出现了 1（也就是 sss 太接近 nnn）才出问题，这个概率不超过 1/2k1/2^{k}1/2k。取 k=100k=100k=100，概率约 10−3010^{-30}10−30，可以忽略。

7.1.4.2 短消息与长消息

（PPT 第 20 页）

由于签名和消息的规模相当，这在消息长的情况下非常不利。为了解决这一问题，通常采用 Hash 函数。签名方案只作用于消息的 Hash 函数值，而不是消息的本身。在这种情况下，使用冗余函数 RRR 保障签名方案安全就不再需要。

翻译成人话：RSA 的签名长度和模长一样（比如 2048 比特 = 256 字节）。如果消息有 10 MB，直接对消息签名根本装不下（而且慢得可怕）。所以标准做法是：先算 Hash，再对 Hash 值签名。

顺带一个重要结论：改用 Hash 之后，冗余函数 RRR 就可以不要了——因为 Hash 值本身就已经把消息"压缩 + 打乱"了，随机伪造的难度由 Hash 的抗第二原像性来保证。

（PPT 第 21 页）为什么 Hash 更划算（一道简单的算术题）

假定 nnn 是 RSA 用于算法 2 的 2⋅k2\cdot k2⋅k 比特的模，算法用于签名 kkk 比特的消息。假定实体 A 期望签名 k⋅tk\cdot tk⋅t 比特的消息。一种办法就是将消息分成 kkk 比特的分组 m=m1∥m2∥⋯∥mtm=m_1\|m_2\|\cdots\|m_tm=m1​∥m2​∥⋯∥mt​，然后分别对每一块进行签名。这样产生的签名数据是 2⋅k⋅t2\cdot k\cdot t2⋅k⋅t 比特。另一种办法是 A 对消息 mmm 进行 Hash 计算得到比特长度为 l≤kl\le kl≤k 的 Hash 值，再对 Hash 值签名。这样产生的签名数据是 k⋅t+2⋅kk\cdot t+2\cdot kk⋅t+2⋅k 比特，这里 k⋅tk\cdot tk⋅t 是原始消息的长度。由于在 t≥2t\ge2t≥2 时，k⋅t+2⋅k≤2⋅k⋅tk\cdot t+2\cdot k\le2\cdot k\cdot tk⋅t+2⋅k≤2⋅k⋅t，最有效的办法是使用 RSA 数字签名对 Hash 值签名。而当消息的长度小于 kkk 比特时，不使用 Hash 的 RSA 数字签名更好。

翻译成人话（把两种方案的"总带宽"算出来对比）：

方案 传输的总数据量 说明
分组逐块签名 消息 ktktkt + 签名 ktktkt = 2kt2kt2kt 每 kkk 比特消息配一个 2k2k2k 比特签名，签名量 = 消息量
先 Hash 再签名 消息 ktktkt + 签名 2k2k2k = kt+2kkt+2kkt+2k 无论消息多长，只多一个签名的长度

t≥2t\ge2t≥2 时 kt+2k≤2ktkt+2k\le2ktkt+2k≤2kt 恒成立，所以消息越长，Hash 越划算。而消息本来就短于 kkk 比特时，直接签名更省事（不必多算一次 Hash）。

7.1.4.3 签名产生和认证的执行特征

（PPT 第 22 页）

令 n=p⋅qn=p\cdot qn=p⋅q 是 2⋅k2\cdot k2⋅k 比特的 RSA 模，这里 ppp 和 qqq 都是 kkk 比特的素数。对消息 mmm 计算一个签名 s≡md(modn)s\equiv m^{d}\pmod ns≡md(modn)，需要 O(k3)O(k^{3})O(k3) 次比特操作。如果认证操作选择小的公开指数，那么认证操作将明显快于签名操作，而仅需要 O(k2)O(k^{2})O(k2) 次比特操作。建议公开指数 eee 在实践中选择 3 或 216+12^{16}+1216+1。 因此，RSA 签名方案非常适合于签名操作可以预先完成，而仅需要认证在线完成的情况。例如，可信第三方为实体 A 产生公钥证书，这个证书只要一次签名产生，而签名则可以反复为各个实体多次认证。

翻译成人话：

  • 签名慢、认证快：签名要用大的 ddd（O(k3)O(k^3)O(k3)），认证用小的 eee（O(k2)O(k^2)O(k2)）；k=1024k=1024k=1024 时差了几百倍。
  • eee 要选小：e=3e=3e=3 最省（两次乘法），但太小的 eee 在某些协议里有风险（低指数攻击、Håstad 广播攻击），所以工程上普遍选 e=216+1=65537e=2^{16}+1=65537e=216+1=65537（只要 17 次乘法，安全性好得多）。
  • 这个"不对称"正好匹配证书场景：CA 签一次证书（慢，但只做一次），之后全世界无数客户端反复验证（快，每次都很轻）。

7.1.4.4 参数选择

（PPT 第 23 页）

当需要的签名有长的生命周期或关系到整个网络安全时，模的长度应该至少为 1024 比特。慎重的态度是关注分解整数的进展，以便随时调整相应参数的选择。 目前，没有 RSA 签名方案选择小公开指数 eee，如 3 或 216+12^{16}+1216+1 存在安全漏洞的报道。但不推荐通过限制秘密指数 ddd 来达到改善签名操作效率的方法。

翻译成人话：

  • 模长是安全底线，1024 比特是最低要求（现在普遍推荐 2048 或 3072）。而且要从"计算能力进步"的角度定期上调。
  • eee 选小（3 / 65537）是安全的、推荐的。
  • ddd 选小是危险的（"低解密指数攻击"Wiener 攻击：如果 ddd 小于 n0.25n^{0.25}n0.25 左右，ddd 可以被高效恢复）——所以别为了提速去动 ddd。

7.1.4.5 关于系统参数

（PPT 第 24 页）

每个实体必须使用不同的 RSA 模进行签名；在整个系统中使用一个模的方法不安全。 但是，在很多应用中，整个系统可以选择相同的公开指数 eee。

翻译成人话：nnn 绝不能共用。这跟第六讲"共用 ppp 会让指数积分的数据复用"是同一类问题，只是这里更直接：共用 nnn 等于共用 φ\varphiφ，于是：

  • 你的公钥是 (n,e1)(n,e_1)(n,e1​)、我的公钥是 (n,e2)(n,e_2)(n,e2​)，只要 gcd⁡(e1,e2)=1\gcd(e_1,e_2)=1gcd(e1​,e2​)=1，攻击者用"共模攻击"就能把明文/签名还原出来；
  • 更糟的是知道 φ\varphiφ 就能分解 nnn（第五讲有讲），于是知道一个人的私钥就能算出所有人的。

而 eee 可以共用（比如全系统都用 65537），因为它只是公开参数。
