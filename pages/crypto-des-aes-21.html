4　解密

对应 PPT 第 31–34 页。AES 的解密不像 DES 那样"用同一套流程"，而是每个层都要用它的逆层。但 PPT 做了一件很聪明的事：通过重新组织顺序，让解密流程的结构和加密完全对称。

4.1 四个逆层（PPT 第 31–32 页）

PPT 原文：

字节转换、移动行变换、混合列变换、轮密钥加密变换都存在相应的逆变换：

（1）字节转换的逆变换可以通过查另一个表来完成，我们称之为逆字节转换（IBS）。 （2）移动行变换的逆变换可以通过字节右移来实现，我们称之为逆移动行变换（ISR）。 （3）逆混合列变换（IMC）通过乘上另一个矩阵实现。 （4）轮密钥加密变换实际上是自身的逆。

补逐个说明：

① IBS（逆字节转换）：需要另一张表——就是"把 S-盒的输入输出对调"得到的那张表（逆 S-盒）。

补为什么不能"用同一个 S-盒再查一次"就算出逆？ 因为 S-盒（求逆 + 仿射变换两次组合）虽然是个一一映射，但不是自己的逆。所以必须单独存一张逆 S-盒表。这一点是 IBS 独有的麻烦（ARK 和 IMC 都没这个问题）。

② ISR（逆移动行变换）：右移。

加密 SR： 第 0 行左移 0，第 1 行左移 1，第 2 行左移 2，第 3 行左移 3
解密 ISR：第 0 行右移 0，第 1 行右移 1，第 2 行右移 2，第 3 行右移 3

（把"左移 k 位"反过来就是"右移 k 位"，就这么简单。）

③ IMC（逆混合列变换）：乘上 PPT 给出的另一个矩阵（十六进制写法）：

┌ 0E 0B 0D 09 ┐
│ 09 0E 0B 0D │
│ 0D 09 0E 0B │
└ 0B 0D 09 0E ┘

也就是 PPT 上那串二进制 00001110, 00001011, 00001101, 00001001, … 排成的矩阵。

补动手验算一个元素，确认这确实是逆矩阵：

加密矩阵的第一行是 [02, 03, 01, 01]。用 IMC 矩阵的第一列 [0E, 09, 0D, 0B] 做内积：

02·0E ⊕ 03·09 ⊕ 01·0D ⊕ 01·0B

在 GF(28)GF(2^{8})GF(28) 上算（02 表示乘 X，0E 是 00001110）：

02·0E  = 左移 00001110 → 00011100 = 1C
    （检查：最高位是 0，不用归约 ✓）
03·09  = 02·09 ⊕ 01·09 = 00010010 ⊕ 00001001 = 00011011 = 1B
    （02·09：09 = 00001001，左移 → 00010010，最高位 0，不用归约 ✓）
01·0D  = 0D
01·0B  = 0B

1C ⊕ 1B ⊕ 0D ⊕ 0B
= 00011100 ⊕ 00011011 = 00000111
⊕ 00001101            = 00001010
⊕ 00001011            = 00000001   ✓ = 01（乘法单位元）

结果正好是 01（乘法单位元），所以这两个矩阵确实是互逆关系 ✓

④ ARK（轮密钥加密变换）"实际上是自身的逆"

因为 (X⊕K)⊕K=X(X \oplus K) \oplus K = X(X⊕K)⊕K=X——异或两次等于没做（这就是第 0 章讲的异或自反性）。

补这里有个坑要注意：虽然 ARK 作为运算是自己的逆，但解密时"用到第几轮的轮密钥"必须倒着来。也就是说，如果要"撤销第 i 轮的 ARK"，你不需要一个新的逆运算，但你得用同一个 KiK_iKi​。PPT 第 33 页给这个"配合倒序轮密钥使用的异或"专门起了个名字叫 IARK（InvAddRoundKey）。

4.2 机械倒着做会得到什么（PPT 第 33 页）

如果只是机械地把加密倒过来跑，得到的是：

Rijndael 加密 → Rijndael 解密（机械倒序版）
ARK → ARK, ISR, IBS
BS, SR, MC, ARK → ARK, IMC, ISR, IBS
⋮ → ⋮
BS, SR, MC, ARK → ARK, IMC, ISR, IBS
BS, SR, ARK。 → ARK。

看起来"加密顺、解密倒"，两头一对比很不整齐。 于是 PPT 做了一次重新改写。

4.3 关键改写：让解密和加密结构一致

PPT 原文（这一段是全节的精华）：

我们重新改造解密过程使其与加密过程相一致。很明显，ISR 和 IBS 的次序可以颠倒。对矩阵 (ci,j)(c_{i,j})(ci,j​) 先使用 MC 再使用 ARK 可以表示为：

(c_{i,j}) → (m_{i,j})(c_{i,j}) → (e_{i,j}) = (m_{i,j})(c_{i,j}) ⊕ (k_{i,j})。

实际上，它的逆就是解 (ei,j)=(mi,j)(ci,j)⊕(ki,j)(e_{i,j}) = (m_{i,j})(c_{i,j}) \oplus (k_{i,j})(ei,j​)=(mi,j​)(ci,j​)⊕(ki,j​)。由于 (ci,j)=(mi,j)−1((ei,j)⊕(ki,j))=(mi,j)−1(ei,j)⊕(mi,j)−1(ki,j)(c_{i,j}) = (m_{i,j})^{-1}((e_{i,j}) \oplus (k_{i,j})) = (m_{i,j})^{-1}(e_{i,j}) \oplus (m_{i,j})^{-1}(k_{i,j})(ci,j​)=(mi,j​)−1((ei,j​)⊕(ki,j​))=(mi,j​)−1(ei,j​)⊕(mi,j​)−1(ki,j​)，这一过程可以表示为

(e_{i,j}) → (m_{i,j})⁻¹(e_{i,j}) → (m_{i,j})⁻¹(e_{i,j}) ⊕ (k'_{i,j})，  这里 (k'_{i,j}) = (m_{i,j})⁻¹(k_{i,j})。

第一个箭头就是 IMC。令 InvAddRoundKey（IARK）表示异或 XOR 矩阵 (ki,j′)(k_{i,j}')(ki,j′​)。我们现在就可以用"IMC 和 IARK"来代替"ARK 和 IMC"。

补这段推导到底在干什么？用大白话讲一遍：

问题：加密时是 先 MC 再 ARK。解密时就得反过来，先撤 ARK 再撤 MC（记作 IMC ∘ ARK）——顺序正好和加密拧着，看着不舒服。

PPT 的技巧：把"先异或密钥、再做 IMC"这一步换个写法，改成"先做 IMC、再异或一个改过的密钥"。推导只有四行：

① 加密：  e = m·c ⊕ k            （m 是 MC 矩阵，k 是轮密钥）
② 求逆：  c = m⁻¹·(e ⊕ k)        （两边先异或 k，再乘 m⁻¹）
③ 展开：  c = m⁻¹·e ⊕ m⁻¹·k      （矩阵乘法对异或满足分配律：m⁻¹(a ⊕ b) = m⁻¹a ⊕ m⁻¹b）
④ 令 k' = m⁻¹·k，则  c = m⁻¹·e ⊕ k'   ← 这就是"先 IMC，再异或 k'"

结果：解密的这一步变成了 "IMC 然后 IARK"，顺序和加密的"MC 然后 ARK"完全一致！ 只不过：

  • 用 IMC 代替了 MC；
  • 用改过的轮密钥 k′=m−1⋅kk' = m^{-1}\cdot kk′=m−1⋅k 代替原来的 k（PPT 给它起了名字 IARK，InvAddRoundKey）。

补为什么要费这个劲？收益是什么？

原本解密是 ARK → IMC → ISR → IBS（和加密的 BS → SR → MC → ARK 顺序拧着）； 改写之后变成 IARK → IMC → ISR → IBS，再配合"ISR 和 IBS 的次序可以颠倒"，就能整理成 IBS → ISR → IMC → IARK——和加密的 BS → SR → MC → ARK 一一对应！

工程收益：加解密可以共用同一套电路/代码框架，只是把每个层的实现换成"加密版或解密版"，用一个开关切换。硬件设计成本直接减半。

代价：需要额外预先算出那些"改过的轮密钥" k′=m−1⋅kk' = m^{-1}\cdot kk′=m−1⋅k。这是纯计算成本，一次性算好，比多设计一套电路便宜得多。

4.4 最终的 Rijndael 解密流程（PPT 第 34 页）

PPT 原文：

现在，解密过程可以写成：

Rijndael 解密
ARK, ISR, IBS
ARK, IMC, ISR, IBS
⋮
ARK, IMC, ISR, IBS
ARK。

PPT 给出的标准描述：

Rijndael 解密 （1）使用第 10 轮密钥执行 ARK 操作。 （2）依次使用第 9 轮到 1 轮密钥，按顺序执行 IBS、ISR、IMC 和 IARK 操作。 （3）使用第 0 轮密钥，按顺序执行 IBS、ISR 和 ARK 操作。 # 为了保持结构的一致性，在最后一轮加密中忽略了 MC 操作。

补把加密和解密并列起来看，对称性一目了然（强烈建议把这张表抄在笔记本上）：

步骤 加密 解密
第 0 步 第 0 轮密钥 → ARK 第 10 轮密钥 → ARK
中间的轮 第 1→9 轮密钥：BS → SR → MC → ARK 第 9→1 轮密钥：IBS → ISR → IMC → IARK
最后一轮 第 10 轮密钥：BS → SR → ARK 第 0 轮密钥：IBS → ISR → ARK

看出规律了吗？

  1. 加密从第 0 轮密钥开始、第 10 轮结束；解密从第 10 轮密钥开始、第 0 轮结束。（密钥顺序完全倒过来——和 DES 一样。）
  2. 中间那 9 轮的四个层顺序完全一致，只是每个层换成了它的逆层（BS→IBS，SR→ISR，MC→IMC，ARK→IARK）。
  3. 两头的特殊轮也完全对应：加密开头只做一个 ARK，解密开头也只做一个 ARK；加密结尾少一个 MC，解密结尾也少一个 IMC（只做 IBS、ISR、ARK）。

补最后回答那个问题："为什么加密最后一轮要砍掉 MC？"

因为只有砍掉它，解密流程的末尾才能和它严丝合缝地对称。

如果加密末尾保留 MC，那么解密开头的第一步就得是 IMC，而加密开头的第一步是纯 ARK——一头是"逆混合"，一头是"纯异或"，结构不对称，硬件就得写两套逻辑分支。

砍掉最后一轮的 MC，代价几乎为零（前面说过，最后一轮的 MC 后面没有 BS 来非线性化它，它只是个可被攻击者自行撤销的已知线性变换），换来的是加解密结构的完全对称。这是 AES 设计中"工程优雅"的一个典型体现。
