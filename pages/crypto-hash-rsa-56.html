3.7 部分密钥泄露攻击（PPT 第 38–39 页）

补这一节的标题是"部分密钥泄露"，问题很直接：

如果攻击者只知道 ddd（或 ppp）的"一部分"，还有救吗？

PPT 的答案是"没救"——只要知道四分之一就够。这两页是这一节最"反直觉"的内容。

事实 3：知道 ppp 的 l/4l/4l/4 位就能分解 nnn（PPT 第 38 页）

PPT 原文：

事实 3 令 n=p⋅qn = p \cdot qn=p⋅q 有 lll 个十进制位。如果我们知道了 ppp 的前或后 l/4l/4l/4 个十进制位，我们就可以有效地分解 nnn。

评述. 如果 ppp 和 qqq 各有 100 个十进制位，而我们知道了 ppp 的前 50 个十进制位或后 50 个十进制位，我们就可以分解 nnn。因此，如果从一个随机起点开始选择我们的素数 ppp，则这个随机的起点一定应该不可预测且生成的方式也要不可预测。例如，假定我们随机选择一个 50 个十进制位的数 NNN 并对 N+1050⋅kN + 10^{50} \cdot kN+1050⋅k，k=1,3,5,…k = 1, 3, 5, \ldotsk=1,3,5,…，做素性测试直到找到素数 ppp（这通常在 k<1000k < 1000k<1000 时就会结束）。如果攻击者知道了这种产生素数的方法，他实际就知道了 ppp 的最后 50 位中的 47 位。因此，他可以在 k<1000k < 1000k<1000 时重复使用事实 3 中的方法最终分解整数 nnn。

补先理解这条事实的"分量"：

n=p⋅q 有 l 位十进制⟹p 约有 l/2 位n = p \cdot q \text{ 有 } l \text{ 位十进制} \quad \Longrightarrow \quad p \text{ 约有 } l/2 \text{ 位}n=p⋅q 有 l 位十进制⟹p 约有 l/2 位
p 有 l/2 位，其中知道 l/4 位⟹就知道了 p 的一半p \text{ 有 } l/2 \text{ 位，其中知道 } l/4 \text{ 位} \quad \Longrightarrow \quad \text{就知道了 } p \text{ 的一半}p 有 l/2 位，其中知道 l/4 位⟹就知道了 p 的一半

也就是说：知道 ppp 的一半比特（十进制一半），就足以把 nnn 分解了。

补为什么"知道一半"就够？直觉是这样的：

设 p=p高⋅10l/4+p低p = p_{\text{高}} \cdot 10^{l/4} + p_{\text{低}}p=p高​⋅10l/4+p低​，其中高 l/4l/4l/4 位已知、低 l/4l/4l/4 位未知。

那么未知的部分只有 10l/410^{l/4}10l/4 种可能（l/4l/4l/4 位十进制的范围）。这看起来还是很大的数（l=200l = 200l=200 时是 105010^{50}1050），光靠穷举仍然不可行。

但关键洞察是：n=pqn = pqn=pq，而 qqq 也是未知的。"ppp 的高位已知"这个约束，配合 pq=npq = npq=n，会大幅缩小 qqq 的可能范围——因为 q≈n/pq \approx n / pq≈n/p，而已知 ppp 的高位就等于大致知道了 ppp 的大小。

更精确地说（Coppersmith 的方法）：这类问题可以化成"求一个模 nnn 的多项式的小根"——而 Coppersmith 定理告诉我们，当未知部分小于 n1/4n^{1/4}n1/4 量级时，可以用格基约化（LLL）算法在多项式时间内求出来。

这就是"l/4l/4l/4"这个数字的来历：不是"试出来的经验值"，而是 Coppersmith 定理给出的严格界限。

补"前 l/4l/4l/4 位或后 l/4l/4l/4 位都行"这件事值得注意：

  • 知道后 l/4l/4l/4 位：ppp 的低位已知，等价于"p mod 10l/4p \bmod 10^{l/4}pmod10l/4 已知"——可以直接套 Coppersmith；
  • 知道前 l/4l/4l/4 位：ppp 的高位已知，等价于"知道 ppp 的一个近似值"，精度到 103l/410^{3l/4}103l/4——同样可以套 Coppersmith（换个多项式）。

两个方向都能用，因为 Coppersmith 对不同形式的多项式都有效。

补关于 PPT 那个例子里"47 位"的说明：

PPT 说"他实际就知道了 ppp 的最后 50 位中的 47 位"。按上文给出的构造（p=N+1050kp = N + 10^{50}kp=N+1050k，NNN 是 50 位十进制数，k<1000k < 1000k<1000）：

  • 1050⋅k10^{50} \cdot k1050⋅k 只影响 ppp 的第 51 位及以上；
  • 所以 ppp 的最后 50 位十进制数字恰好就是 NNN——攻击者是完整知道这 50 位的（因为 NNN 是他按方法"随机"选的，方法一旦泄露，NNN 也就暴露了）。

所以这里的"47 位"与上文构造的推算（应为 50 位）不一致，疑为原课件数字上的笔误。 不管具体是 47 还是 50，结论完全一样：攻击者掌握了足够多的低位（远超 l/4l/4l/4 的门槛），足以用事实 3 的方法分解 nnn。记住这个例子的教训就够了，不必纠结这个数字。

补这个例子真正的教训，值得单独强调：

"随机"不等于"不可预测"。

看 PPT 这个生成方法错在哪：

一个"看起来随机"的素数生成方法：

   ① 随机取一个 50 位十进制数 N
   ② 测试 N + 10⁵⁰k（k = 1, 3, 5, …）是不是素数，直到找到素数 p

从"随机性"的角度看：N 是随机的、k 也是变化的
       ↓
但这里藏着一个致命的结构：
       ↓
   10⁵⁰·k 只改变"高位"，低 50 位永远是 N  ← 一个确定的结构！

一旦攻击者知道了生成方法，他立刻就能推出：

  • 这个素数的低 50 位是确定的（就是 NNN）；
  • 而且 kkk 很小（<1000<1000<1000，且是奇数，所以只有约 500 种可能）。

于是攻击者不需要"穷举所有可能的素数"，只需要"试 500 个候选 kkk"——这就是"可预测"带来的灾难。

补"随机"和"不可预测"的差别，用一个比喻说清：

  • 随机：结果在某个分布里取值，看起来杂乱；
  • 不可预测：别人无法通过任何计算把结果算出来。

一个数可以"看起来很随机"但"完全可预测"——PPT 这个例子就是：N+1050kN + 10^{50}kN+1050k 确实看起来像随机的大素数，但它的生成规律是公开可算的（只要你知道了"用的是什么方法"）。

补正确的做法是什么？

错误做法 正确做法
从一个已知的起点出发，加个小偏移找素数 用密码学安全的随机源生成候选，每一位都不可预测
让 ppp 和 qqq 的生成方式有规律（比如相近、同起点） ppp 和 qqq 独立生成，生成过程不使用任何可预测的模式
依赖"攻击者不知道我的方法" 假定攻击者知道一切，除了真正的随机种子

补最后一条是密码学的一条基本原则（Kerckhoffs 原则的延伸）：

安全性不能依赖"算法的保密"，只能依赖"密钥的保密"。

PPT 这个例子的"方法"就相当于一种"隐式的密钥"——一旦泄露，安全性立刻归零。而正确的做法是：把安全性完全建立在"那个真正的随机种子"上，因为那个种子是无法从任何公开信息推导出来的。

事实 4：知道 ddd 的 l/4l/4l/4 位就能算出 ddd（PPT 第 39 页）

PPT 原文：

Coppersmith 给出如下结论： 事实 4 假定 (n,e)(n, e)(n,e) 是 RSA 的公开密钥并且 nnn 有 lll 个十进制位。令 ddd 为解密指数。如果我们已经知道了 ddd 的 l/4l/4l/4 个十进制位，我们就能以 e⋅log⁡2ee \cdot \log_2 ee⋅log2​e 的时间复杂度找出 ddd。

评述. 这意味着找到 ddd 的时间复杂度与 e⋅log⁡2ee \cdot \log_2 ee⋅log2​e 成线性关系，如果 eee 十分小，则当我们知道了部分 ddd 的情况下，找出 ddd 的速度十分快。如果 eee 十分大，则当我们知道了部分 ddd 的情况下，并不能给我们得到 ddd 带来多大帮助。

补先把"e⋅log⁡2ee \cdot \log_2 ee⋅log2​e"这个复杂度读清楚：

部分 含义
e⋅log⁡2ee \cdot \log_2 ee⋅log2​e 这是一个关于 eee 的多项式（严格说是 O(elog⁡e)O(e \log e)O(eloge)）
与 nnn 无关！ 这才是最要命的——正常分解 nnn 的代价是亚指数级（关于 nnn），而这里是关于 eee 是多项式的

补用数字感受一下这个差别：

eee 的取值 elog⁡2ee \log_2 eelog2​e 量级 说明
e=3e = 3e=3 3×1.58≈4.83 \times 1.58 \approx 4.83×1.58≈4.8 几乎瞬间
e=65537e = 65537e=65537 65537×16=1.05×10665537 \times 16 = 1.05 \times 10^{6}65537×16=1.05×106 毫秒级，仍然很快
eee 是 1024 比特的随机数 ≈21024\approx 2^{1024}≈21024 天文数字，这条路走不通了

所以 PPT 那句评述的完整含义是：

  • eee 小 → 知道 ddd 的一部分 → 几毫秒内恢复 ddd → 系统彻底崩溃；
  • eee 大 → 知道 ddd 的一部分 → 没什么帮助（因为 elog⁡ee\log eeloge 本身就大到不可行）。

补这段评述有一个非常重要的"设计启示"，注意它和第 4.3 节的冲突：

第 4.3 节说：为了加密快，要用小的 e（比如 3 或 65537）
        ↕  ← 这里出现了张力
事实 4 说：e 小的时候，"部分 d 泄露"会迅速导致 d 全泄露

补冲突怎么解决？ 关键看**"ddd 的一部分会不会泄露"这个前提**。

  • 正常使用下，ddd 是完整保密的——那 eee 小就没有额外风险；
  • 只有在"ddd 已经部分泄露"的场景下，小 eee 才是致命的——而这种场景本身已经很糟了（ddd 部分泄露通常意味着实现有侧信道漏洞，比如 3.12 节的定时攻击会泄露 ddd 的比特）。

所以结论是：

小 eee 本身没问题；但小 eee 会让"ddd 的泄露"变得"一点都不能容忍"。

补事实 3 和事实 4 的共同教训，一句话总结：

密钥的任何"部分泄露"，都可能等于"全部泄露"\boxed{\text{密钥的任何"部分泄露"，都可能等于"全部泄露"}}密钥的任何"部分泄露"，都可能等于"全部泄露"​

这对密钥管理有直接影响：

做法 是否安全
把私钥 ddd 分成几片存，每片单独泄露没危险 错误——知道 l/4l/4l/4 就完了
用固定的模式生成素数（"我的素数总是从某个值开始找"） 错误——事实 3 一攻就破
让实现的时间、功耗等与密钥无关（常数时间实现） 正确——这样才不会有"部分泄露"

补这一节把"部分泄露"这件事讲透了，也就自然地引向了本节最后两节（3.11 OAEP、3.12 定时攻击）——它们分别处理"攻击者能控制输入"和"攻击者能测量执行"这两种现实的攻击者能力。
