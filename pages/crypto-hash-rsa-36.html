4.3 定制的 MAC：MD5-MAC（PPT 第 50–52 页）

MD5-MAC 的输入输出与三个常量（PPT 第 50 页）

PPT 原文：

假定输入为任意长度的 bbb 比特串 xxx，b≥0b \ge 0b≥0，长度不大于 128 比特的密钥 kkk；输出为 xxx 的 64 比特 MAC 值。

定义常量

T0=97ef45ac290f43cd457e1b551c801134,T_0 = \mathtt{97ef45ac290f43cd457e1b551c801134},T0​=97ef45ac290f43cd457e1b551c801134,
T1=b177ce962e728e7c5f5aab0a3643be18,T_1 = \mathtt{b177ce962e728e7c5f5aab0a3643be18},T1​=b177ce962e728e7c5f5aab0a3643be18,
T2=9d21b421bc87b94da29d27bdc75bd7c3。T_2 = \mathtt{9d21b421bc87b94da29d27bdc75bd7c3}。T2​=9d21b421bc87b94da29d27bdc75bd7c3。
TiT_iTi​ 的下标 mod 3，可定义 96 字节的 U0,U1,U2U_0, U_1, U_2U0​,U1​,U2​ 为：
Ui=Ti∥Ti+1∥Ti+2∥Ti∥Ti+1∥Ti+2。U_i = T_i \| T_{i+1} \| T_{i+2} \| T_i \| T_{i+1} \| T_{i+2}。Ui​=Ti​∥Ti+1​∥Ti+2​∥Ti​∥Ti+1​∥Ti+2​。

补先看输入输出规格：

项目 值
输入 任意长度 b≥0b \ge 0b≥0 比特的消息 xxx
密钥 kkk 长度不超过 128 比特
输出 64 比特 MAC 值

补注意到两个"不对称"：

  1. 密钥可以是任意长度（≤128 比特），但消息长度不限——所以算法必须先把密钥"规整"成固定长度（这就是下一步"密钥扩充"要干的事）；
  2. 输出只有 64 比特，而 MD5 的压缩函数输出是 128 比特——所以要"砍一半"（第（5）步会讲）。

三个常量 T0,T1,T2T_0, T_1, T_2T0​,T1​,T2​：

每个是 128 比特（16 字节）× 3 个 = 48 字节。它们是固定的、公开的常量，作用是"把密钥扩散成更多比特"（下面会看到怎么用）。

补注意 UiU_iUi​ 的定义：

Ui=Ti∥Ti+1∥Ti+2∥Ti∥Ti+1∥Ti+2U_i = T_i \| T_{i+1} \| T_{i+2} \| T_i \| T_{i+1} \| T_{i+2}Ui​=Ti​∥Ti+1​∥Ti+2​∥Ti​∥Ti+1​∥Ti+2​

每个 UiU_iUi​ 是 6 个 TTT 拼起来的，96 字节（768 比特）。而"TiT_iTi​ 的下标 mod 3"意思是：T3=T0T_3 = T_0T3​=T0​、T4=T1T_4 = T_1T4​=T1​、T5=T2T_5 = T_2T5​=T2​。

所以三个 UUU 展开写就是：

U₀ = T₀ ‖ T₁ ‖ T₂ ‖ T₀ ‖ T₁ ‖ T₂
U₁ = T₁ ‖ T₂ ‖ T₀ ‖ T₁ ‖ T₂ ‖ T₀
U₂ = T₂ ‖ T₀ ‖ T₁ ‖ T₂ ‖ T₀ ‖ T₁
     └────── 前 3 个 ──────┘└────── 后 3 个 ──────┘

补为什么要"每个 TTT 重复两遍"？ 因为重复能增加冗余：如果攻击者想通过操纵 UiU_iUi​ 的某一部分来影响输出，重复的结构让"改了这边没改那边"这类操作更容易被发现（或者说，让 UiU_iUi​ 的每一个 TTT 都被"用两次"）。这类"重复一次"的手法在密码设计里常见，作用通常是"让每个输入比特对输出的影响更均匀"。

补这三个 TTT 常量的来历：和 MD5 的 T[i]T[i]T[i] 一样，它们也是从2,3,5\sqrt{2}, \sqrt{3}, \sqrt{5}2​,3​,5​ 之类的无理数取出来的（具体是哪几个数的哪几位，不同文献记法不一），目的还是那个"nothing-up-my-sleeve"——证明设计者没往里埋陷门。

密钥扩充（PPT 第 51 页）

PPT 原文：

（1）密钥扩充。 （1.1） 若 kkk 不足 128 比特长，则把 kkk 与自身级联足够多次，重新定义 kkk 为最左边的 128 比特。 （1.2） 令 MD5‾\overline{\mathrm{MD5}}MD5 表示省略了填充和附加长度的 MD5 操作。按照如下方法将 kkk 扩展成三个 16 字节的子密钥 K0,K1,K2K_0, K_1, K_2K0​,K1​,K2​：对 iii 从 0 到 2，令

Ki←MD5‾(k∥Ui∥k)。K_i \leftarrow \overline{\mathrm{MD5}}(k \| U_i \| k)。Ki​←MD5(k∥Ui​∥k)。
（1.3） 分别分割 K0K_0K0​ 和 K1K_1K1​ 为四个 32 比特的子串 Kj[i]K_j[i]Kj​[i]，0≤i≤30 \le i \le 30≤i≤3。

第一步（1.1）：把密钥"抻"到 128 比特。

如果 k 是 40 比特：  k ‖ k ‖ k ‖ k ‖ (取前128位)
                    └── 级联足够多次 ──┘
如果 k 恰好 128 比特：不动

大白话：密钥短了就反复拼接自己，凑够 128 比特。

补为什么要做这个？ 因为后面几步要用 128 比特的密钥去替代 MD5 的四个寄存器（128 比特），所以密钥必须是 128 比特长。

但要注意这里的"扩展"并不增加熵：如果原始密钥只有 40 比特，那么级联之后虽然长度是 128 比特，实际的密钥空间还是 2402^{40}240。所以这一步是"格式归一"，不是"强度提升"。 这也是为什么 MD5-MAC 规定"密钥长度不大于 128 比特"——鼓励你用够长的密钥（用满 128 比特才有 128 比特的强度）。

第二步（1.2）：把 128 比特的密钥"炸"成三个 16 字节的子密钥。

Ki←MD5‾(k∥Ui∥k),i=0,1,2K_i \leftarrow \overline{\mathrm{MD5}}(k \| U_i \| k), \qquad i = 0, 1, 2Ki​←MD5(k∥Ui​∥k),i=0,1,2

补注意那个 MD5‾\overline{\mathrm{MD5}}MD5 的横线——它代表"省略了填充和附加长度的 MD5"。这个细节很重要：

完整的 MD5 MD5‾\overline{\mathrm{MD5}}MD5
填充（1 + 0…0） 有 省略
附加长度字段 有 省略
用途 算通用 Hash 值 只做内部密钥派生，输入长度我们已知，不需要填充

为什么要省略？ 因为这里k∥Ui∥kk \| U_i \| kk∥Ui​∥k 的长度是固定的（128 + 768 + 128 = 1024 比特）且由我们自己控制，没有"变长输入"的安全问题。省掉填充可以减少计算量，也让派生过程更简单。

补而"kkk 出现在两头"（k∥Ui∥kk \| U_i \| kk∥Ui​∥k）这个写法，正是 4.2 节那个"密钥要放在两头"的原则在这里的应用。 看出来了吗？同一个设计原则，在算法内部也被遵守了。

第三步（1.3）：把 K0,K1K_0, K_1K0​,K1​ 切成 4 个 32 比特的子串。

Kj=Kj[0]∥Kj[1]∥Kj[2]∥Kj[3],j=0,1K_j = K_j[0] \| K_j[1] \| K_j[2] \| K_j[3], \qquad j = 0, 1Kj​=Kj​[0]∥Kj​[1]∥Kj​[2]∥Kj​[3],j=0,1

注意：只有 K0K_0K0​ 和 K1K_1K1​ 被切分使用，K2K_2K2​ 后面另有用途（第（4）步）。

补这三个子密钥的用途，先给一张"预告表"，后面几步会逐个展开：

子密钥 用途 对应 MD5 的哪个零件
K0K_0K0​ 替代 MD5 的四个初始寄存器 A,B,C,DA, B, C, DA,B,C,D 相当于"换了 IVIVIV"
K1K_1K1​ 加到 MD5 的常量 T[j]T[j]T[j] 上 相当于"换了轮常量"
K2K_2K2​ 拼进消息末尾，作为附加的 512 比特分组 相当于"加了一个消息块"

补这个设计思路非常值得记住： 与其重新设计一个带密钥的 Hash 函数，不如把密钥"注入"到原算法的三个关键位置——

位置①  初始化（IV）      → 让不同的密钥从不同的起点开始
位置②  轮常量（T[j]）    → 让不同的密钥有不同的"搅拌方式"
位置③  消息末尾（附加块） → 让密钥成为消息的一部分

这三处注入点覆盖了"起点、过程、终点"三段，攻击者无论从哪一头下手都有密钥挡着。"多点注入密钥"是设计带密钥 Hash 的通用手法，你可以在几乎所有成熟的 MAC 算法里看到类似结构。

密钥注入的三个位置（PPT 第 51–52 页）

PPT 第 51 页原文（续）：

（2） K0K_0K0​ 替代 MD5 的四个 32 比特

A=K0[0],B=K0[1],C=K0[2],D=K0[3]。A = K_0[0], \quad B = K_0[1], \quad C = K_0[2], \quad D = K_0[3]。A=K0​[0],B=K0​[1],C=K0​[2],D=K0​[3]。
（3） 将 K1[i]K_1[i]K1​[i] 与在 MD5 中的第 iii 轮的每个常量 T[j]T[j]T[j] 进行模 2322^{32}232 加，1≤j≤641 \le j \le 641≤j≤64。

位置①（第（2）步）：用 K0K_0K0​ 替换 MD5 的 IVIVIV。

A=K0[0],B=K0[1],C=K0[2],D=K0[3]A = K_0[0],\quad B = K_0[1],\quad C = K_0[2],\quad D = K_0[3]A=K0​[0],B=K0​[1],C=K0​[2],D=K0​[3]

大白话：MD5 原本有固定的 IVIVIV（A=01234567A = \mathtt{01234567}A=01234567 那四个数），MD5-MAC 把它换成了由密钥派生出来的四个数。

补这一步把"IVIVIV 是什么"变成了密钥的一部分，效果是：

  • 不同的密钥 → 完全不同的起始状态；
  • 攻击者无法预计算任何中间状态（因为他不知道起始状态）。

这正好堵住了 3.2 节末尾提到的"预计算攻击"——那个危险在 MD5 里是靠"IVIVIV 取非平凡值"来缓解的，而 MD5-MAC 把它彻底解决了（IVIVIV 由密钥决定，攻击者完全不知道）。

位置②（第（3）步）：用 K1K_1K1​ 扰动 MD5 的常量 T[j]T[j]T[j]。

T[j]←T[j]+K1[第 j 步所在的轮号](mod232)T[j] \leftarrow T[j] + K_1[\text{第 } j \text{ 步所在的轮号}] \pmod{2^{32}}T[j]←T[j]+K1​[第 j 步所在的轮号](mod232)

这一句 PPT 表达得比较绕，展开解释一下。

MD5 共有 64 个常量 T[1…64]T[1 \ldots 64]T[1…64]，分布在 4 轮里（第 1 轮用 T[1…16]T[1\ldots 16]T[1…16]，第 2 轮用 T[17…32]T[17\ldots 32]T[17…32]，…\ldots…）。而 K1K_1K1​ 被切成了 4 个子串 K1[0],K1[1],K1[2],K1[3]K_1[0], K_1[1], K_1[2], K_1[3]K1​[0],K1​[1],K1​[2],K1​[3]——一轮一个。

第 1 轮的 16 个常量：T[1]  … T[16]   各加上 K₁[0]
第 2 轮的 16 个常量：T[17] … T[32]   各加上 K₁[1]
第 3 轮的 16 个常量：T[33] … T[48]   各加上 K₁[2]
第 4 轮的 16 个常量：T[49] … T[64]   各加上 K₁[3]

补为什么"一轮用一个子串"而不是"每个 T[j]T[j]T[j] 各自扰一下"？ 因为一轮内部的 16 步是同构的（回顾 3.3 节说的"MD5 每一轮结构一样"）。既然同构，就没有必要给每一轮内部 16 个常量分别加不同的值——加同一个值，效果就足够打乱常量了。

这样的好处是：K1K_1K1​ 只需要 4 × 32 = 128 比特就够了，和 K1K_1K1​ 的长度（16 字节）刚好对上。这是"参数格式和算法需求互相咬合"的例子——K1K_1K1​ 之所以被切成 4 份，正是因为 MD5 有 4 轮。

补为什么要扰动常量？ 因为常量也是算法的一个"把柄"：

如果不改常量，那么攻击者知道 T[j]T[j]T[j] 的确切值，就可以针对性地构造消息让某些中间值达到特定状态（差分分析、模差分分析都依赖"知道常量"）。把常量变成"由密钥决定的秘密值"之后，这种构造就失效了——攻击者不知道他在跟什么数打交道。

位置③（第（4）步）：用 K2K_2K2​ 拼出一个 512 比特的附加分组。

PPT 第 52 页原文：

（4） 先将 MD5 定义的方法对输入 xxx 进行规则填充，添加长度分组，然后附加用 K2K_2K2​ 构造的下列 512 比特分组：

K2∥K2⊕T0∥K2⊕T1∥K2⊕T2。K_2 \| K_2 \oplus T_0 \| K_2 \oplus T_1 \| K_2 \oplus T_2。K2​∥K2​⊕T0​∥K2​⊕T1​∥K2​⊕T2​。
（5） MAC 值是 128 比特输出的最左边的 64 比特，这 128 比特的输出是使用上面修改的 MD5 来计算（4）的扩展消息输入串得到的。

先看这 512 比特附加分组：

K2∥(K2⊕T0)∥(K2⊕T1)∥(K2⊕T2)K_2 \| (K_2 \oplus T_0) \| (K_2 \oplus T_1) \| (K_2 \oplus T_2)K2​∥(K2​⊕T0​)∥(K2​⊕T1​)∥(K2​⊕T2​)

长度核对：K2K_2K2​ 是 16 字节（128 比特），T0,T1,T2T_0, T_1, T_2T0​,T1​,T2​ 各是 16 字节——所以是 4 × 16 = 64 字节 = 512 比特，正好一个 MD5 分组。✓

大白话：在"正规填充 + 长度字段"之后，再挂上一个由 K2K_2K2​ 和三个常量拼出来的完整分组。

补为什么这个附加分组长得是"K2K_2K2​ 和 K2⊕TiK_2 \oplus T_iK2​⊕Ti​"这种形式？

因为这样可以让这个分组里同时包含"密钥"和"已知常量"的混合：

分组布局：
┌────────────┬─────────────────┬─────────────────┬─────────────────┐
│    K₂      │   K₂ ⊕ T₀       │   K₂ ⊕ T₁       │   K₂ ⊕ T₂       │
│  (128比特) │    (128比特)    │    (128比特)    │    (128比特)    │
└────────────┴─────────────────┴─────────────────┴─────────────────┘
      │              │                 │                 │
      └──────────────┴─────────────────┴─────────────────┘
             全部由 K₂ 参与构成（但两两不同）

这个设计符合 1.1 节评论（4）说的"阻止了存在性伪造"的目标：

  • K2K_2K2​ 是秘密的，攻击者算不出这一块；
  • 四个子块两两不同（因为 T0,T1,T2T_0, T_1, T_2T0​,T1​,T2​ 各不相同），所以这个分组不会退化成"四个相同的块"——如果写死成 K2∥K2∥K2∥K2K_2 \| K_2 \| K_2 \| K_2K2​∥K2​∥K2​∥K2​，那么"重复四次"这个规律性可能被利用。

补再想一步：这个附加分组为什么放在"填充 + 长度之后"？ 因为这样它就变成了"消息的最后一块"。回顾 2.1 节的迭代结构：

Ht=f(Ht−1,xt)H_t = f(H_{t-1}, x_t)Ht​=f(Ht−1​,xt​)

最后一块的输入直接决定最终输出。所以把密钥块放在最后，等于让密钥"最后一次"参与运算——攻击者想在前面做任何调整，都会经过这一块的"密钥把关"。

补这也解释了为什么"MD5-MAC 的第（4）步"和 3.2 节的长度扩展攻击正好相对：长度扩展攻击之所以能成立，是因为攻击者知道最后的状态，可以在后面接着接东西。而 MD5-MAC 的做法是把密钥放在最后一整块里——攻击者不知道 K2K_2K2​，就没法预测"经过这一块之后状态会变成什么"，扩展的路就断了。

最后是第（5）步：砍出 64 比特。

MAC=「128 比特输出的最左边 64 比特」MAC = \text{「128 比特输出的最左边 64 比特」}MAC=「128 比特输出的最左边 64 比特」

为什么砍一半？ 回顾 2.2 节事实 6：

MAC 对大部分环境要求 n≥64n \geq 64n≥64 以及 64–80 比特的密钥。

64 比特的 MAC 输出正好达标。而输出越短，传输和存储越省。所以"砍一半"是"刚好够用"的选择——这和 HMAC 通常也截断到 8 字节、16 字节是同一个思路。

补注意"最左边 64 比特"里的字节序问题：MD5 是小端算法（3.3 节讲过），所以"最左边"在实现层面指的是"按 MD5 报告格式的最左 64 比特"。不同实现要统一约定，否则同一消息在不同实现下算出的 MAC 会不一致——这类"字节序陷阱"在 3.3 节已经提醒过一次了。

补读这张表要看出"三条路线的成本差异"：

  • 基于分组密码（CBC-MAC）：需要分组密码的硬件/代码，好处是"复用现有零件"、"有硬件加速"；
  • 由 MDC 构造（h(k∥p∥x∥k)h(k\|p\|x\|k)h(k∥p∥x∥k) 等）：最灵活，手头有什么 Hash 就能用什么 Hash；代价是安全性的论证要靠额外的分析（或者直接用 HMAC，它有现成的证明）；
  • 定制（MD5-MAC）：性能最好（不用跑两遍、不用多个密钥），但专用性强——它只能配 MD5，MD5 一弱它也跟着弱（这也正是 MD5-MAC 今天不能再用的原因）。
