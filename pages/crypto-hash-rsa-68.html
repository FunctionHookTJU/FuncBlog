8　公钥加密的总结

对应 PPT 第 75–80 页。这一节把整讲"收口"——从两个具体方案（RSA、Rabin）上升到"公钥加密"这个抽象的框架。

8.1 公钥加密的要求（PPT 第 75–77 页）

PPT 原文：

在一个公钥系统中，消息集合 MMM，密钥集合 KKK，和加/解密函数 E/DE/DE/D，必须满足如下要求： （1） 对于任何消息 m∈Mm \in Mm∈M，满足 Dk(Ek(m))=mD_k(E_k(m)) = mDk​(Ek​(m))=m。 （2） 对于每一个消息 m∈Mm \in Mm∈M 和密钥 k∈Kk \in Kk∈K，值 Ek(m)E_k(m)Ek​(m) 和 Dk(m)D_k(m)Dk​(m) 容易计算。 （3） 给定密钥 k∈Kk \in Kk∈K，很容易找到函数 EkE_kEk​ 和 DkD_kDk​。 （4） 对于几乎所有密钥 k∈Kk \in Kk∈K，如果仅仅知道函数 EkE_kEk​，不可能发现一个算法有效计算函数 DkD_kDk​。

补把这四条逐条翻译，并且对上 RSA 和 Rabin。

第（1）条：正确性。

Dk(Ek(m))=mD_k(E_k(m)) = mDk​(Ek​(m))=m

——"加密再解密得回原文"。这是一切密码系统的底线。

方案 是否满足 但要注意
RSA ✅ 严格满足 第 1.1 节的证明
Rabin ⚠️ 不完全 解密有4 个候选——严格说 Dk(Ek(m))D_k(E_k(m))Dk​(Ek​(m)) 可能是 ±m\pm m±m 或另一个根。第 6.3 节的冗余规则就是为了让它"实际满足"这一条

补这一条对照揭示了一个重要事实：Rabin 的"裸方案"其实不严格满足"公钥加密的要求"——它需要冗余规则"补"上这个性质。这是一个很少被注意到的细节，但它解释了"为什么 Rabin 必须配冗余才能用"。

第（2）条：容易计算。

Ek(m) 和 Dk(m) 都要能"容易"算出来E_k(m) \text{ 和 } D_k(m) \text{ 都要能"容易"算出来}Ek​(m) 和 Dk​(m) 都要能"容易"算出来

"容易"= 多项式时间（第 0.7 节的定义）。

方案 加密 解密
RSA 一次模幂（算法 4） 一次模幂（算法 4）
Rabin 一次模平方 求平方根——但因为解密者知道 (p,q)(p,q)(p,q)，所以第 6.1 节的公式让它是多项式时间的

补注意第（2）条里那个容易忽略的细节：它要求 Dk(m)D_k(m)Dk​(m) 也容易算。

这对"公钥密码"是一个实质性的要求——"难"的只应该是"没有私钥的人去算 DkD_kDk​"（这是第（4）条）。

第（3）条：给定密钥，容易找到函数。

大白话：生成密钥之后，加密和解密函数就自动确定了（不需要额外的"搜索"）。

方案 说明
RSA 有了 (n,e)(n, e)(n,e) 就是 Ek(m)=me mod nE_k(m) = m^e \bmod nEk​(m)=memodn；有了 ddd 就是 Dk(m)=md mod nD_k(m) = m^d \bmod nDk​(m)=mdmodn
Rabin 有了 nnn 就是 Ek(m)=m2 mod nE_k(m) = m^2 \bmod nEk​(m)=m2modn；有了 (p,q)(p,q)(p,q) 就是第 6.1 节的公式

第（4）条：这是最关键的一条，也是"公钥"之所以能"公开"的根据。

只知道 Ek  ⟹  算不出 Dk\text{只知道 } E_k \;\Longrightarrow\; \text{算不出 } D_k只知道 Ek​⟹算不出 Dk​

补逐句拆这条：

措辞 含义
只知道 EkE_kEk​ 攻击者拿不到任何关于 DkD_kDk​ 的额外信息（连"DkD_kDk​ 是怎么算的"都不知道）
不可能发现一个算法 不是"这一个攻击者算不出来"，而是"任何人都造不出这样的算法"
有效计算 多项式时间
对于几乎所有密钥 允许有极少数"坏密钥"（但那些不该被生成出来）

补"对于几乎所有密钥"这个措辞很重要——它给了"存在少量弱密钥"以容错空间。这和上一册讲 AES 时"不存在弱密钥"是同类思路：只要坏密钥的比例可忽略，就不影响安全性。

例子 5：RSA 如何满足这四条（PPT 第 77 页）

PPT 原文：

例子 5 让我们观察 RSA 加密是如何满足这些条件的。正如我们提到的，RSA 的密钥是一个三元组 k=(e,d,n)k = (e, d, n)k=(e,d,n)。加密函数是 Ek(m)≡me(modn)E_k(m) \equiv m^{e} \pmod nEk​(m)≡me(modn)。解密函数是 Dk(m)≡md(modn)D_k(m) \equiv m^{d} \pmod nDk​(m)≡md(modn)。 一旦一个公钥系统建立，每个用户产生一个密钥 kkk 并确定对应加密函数 EkE_kEk​ 和解密函数 DkD_kDk​。EkE_kEk​ 公开，而 DkD_kDk​ 保密。如果存在密钥冒充问题，就使用可信第三方认证密钥。

补逐条对照：

要求 RSA 的满足情况
（1）正确性 Dk(Ek(m))=(me)d=med≡m(modn)D_k(E_k(m)) = (m^e)^d = m^{ed} \equiv m \pmod nDk​(Ek​(m))=(me)d=med≡m(modn)（第 1.1 节证明）
（2）容易计算 加解密各一次模幂（算法 4）
（3）给定密钥易找到函数 k=(e,d,n)k = (e,d,n)k=(e,d,n) 一确定，两个函数就确定了
（4）只知道 EkE_kEk​ 算不出 DkD_kDk​ 需要知道 ddd；而求 ddd 需要 φ\varphiφ，求 φ\varphiφ 等价于分解 nnn（事实 1、2）

补注意 PPT 说"RSA 的密钥是一个三元组 k=(e,d,n)k = (e, d, n)k=(e,d,n)"——这是把"公钥 + 私钥"合起来叫"一个密钥"。后面那句"EkE_kEk​ 公开，而 DkD_kDk​ 保密"就是在说"三元组里 (e,n)(e,n)(e,n) 公开、ddd 保密"。

补最后一句"如果存在密钥冒充问题，就使用可信第三方认证密钥"非常重要——它把导言里 PPT 第 5 页讲的那个"公钥真实性"问题，正式写进了"公钥系统的要求"里。

"密钥冒充问题"就是导言里讲的中间人攻击：攻击者把自己的公钥冒充成别人的。

"可信第三方认证密钥" = CA（Certificate Authority）——也就是现代 PKI 体系的雏形。

补所以第 8.1 节实际上给出了"公钥加密的完整清单"：

纯数学层面（第 1–4 条）：
    正确性 + 容易算 + 容易构造 + 只有公钥算不出私钥函数

系统层面（例子 5 最后那句）：
    公钥的真实性（需要可信第三方）

—— 两层都要满足，缺一不可

补这是整讲唯一一次明确把"系统层面"和"数学层面"并列写出来，值得重视。

8.2 关于认证和不可否认（PPT 第 78 页）

PPT 原文：

（1） 在对称密码系统中，认证是容易的，但不存在不可否认问题。 （2） 在公钥密码系统中，认证和不可否认都不能自然成立。但是，这些目标容易实现。例如，在 RSA 系统中计算并发送消息

Ekb(Ska(m))=Ekb(Dka(m))。E_{k_b}(S_{k_a}(m)) = E_{k_b}(D_{k_a}(m))。Ekb​​(Ska​​(m))=Ekb​​(Dka​​(m))。

补先解释这两个词：

术语 含义 例子
认证（Authentication） 确认"这条消息确实来自某个特定的人" 接收方能确认"这是 A 发的"
不可否认（Non-repudiation） 发送方事后无法抵赖"我没发过" A 不能否认"这份合同不是我签的"

补第（1）条：为什么对称密码里"认证容易、不可否认不成立"？

认证容易：因为双方共享同一把密钥。接收方能用这把密钥正确解密（或者验证 MAC），就说明"发送方也知道这把密钥"——基本可以认定是对方发的。

不可否认不成立：因为双方共享同一把密钥。所以：

A 说："这条消息不是我发的，是 B 自己伪造的！"
        ↓
B 能反驳吗？——很难，因为 B 自己也有那把密钥，他确实能造出这条消息
        ↓
结果：无法判断到底是谁发的   ← 这就是"不可否认"失败

补根本原因在于"对称密码里双方的能力完全对等"：

A 能做的事=B 能做的事⟹无法区分"谁做的"\text{A 能做的事} = \text{B 能做的事} \quad \Longrightarrow \quad \text{无法区分"谁做的"}A 能做的事=B 能做的事⟹无法区分"谁做的"

补第（2）条：为什么公钥密码里"两者都不能自然成立"？

认证不能自然成立：因为公钥是公开的——任何人都能用 A 的公钥加密一条消息，所以"能加密"不能证明"是 A 发的"。

不可否认不能自然成立：同理，光有"公钥加密、私钥解密"这个方向，解决不了"谁发的"这个问题。

补但 PPT 说"这些目标容易实现"，并且给了一行式子：

Ekb(Ska(m))=Ekb(Dka(m))E_{k_b}(S_{k_a}(m)) = E_{k_b}(D_{k_a}(m))Ekb​​(Ska​​(m))=Ekb​​(Dka​​(m))

把它拆开看：

第 1 层（内层）：D_{k_a}(m)
        ↑
   用 A 的【私钥】对 m 做"解密"运算

第 2 层（外层）：E_{k_b}(...)
        ↑
   再用 B 的【公钥】加密

补注意内层那个操作很"反直觉"：用私钥做"解密"。

为什么这样做就能"认证"？ 因为：

谁能算出 Dka(m)⟺谁有 A 的私钥\text{谁能算出 } D_{k_a}(m) \quad \Longleftrightarrow \quad \text{谁有 } A \text{ 的私钥}谁能算出 Dka​​(m)⟺谁有 A 的私钥

而只有 A 有 A 的私钥。所以谁算出了 Dka(m)D_{k_a}(m)Dka​​(m)，谁就是 A。

补于是这行式子同时实现了四件事：

目标 靠哪一层实现
机密性 外层 EkbE_{k_b}Ekb​​——只有 B 能解开
认证 内层 DkaD_{k_a}Dka​​——只有 A 能做出这个
不可否认 内层 DkaD_{k_a}Dka​​——因为只有 A 能做，所以 A 事后无法抵赖
完整性 （这个式子本身不提供，实际要配合 Hash 函数——这就是数字签名）

补所以这一页实际上是在讲"数字签名 + 加密"的雏形。

PPT 的记号 Ska(m)S_{k_a}(m)Ska​​(m) 里的 SSS 就是 Sign（签名），而它等于 Dka(m)D_{k_a}(m)Dka​​(m)——即"签名"操作在 RSA 里就是"用私钥做解密运算"。

补这里和第四讲形成了完美的呼应：数字签名不能对整个消息做，要先做 Hash（第 1.2 节讲过"数字签名必须用 CRHF"）。所以实际的数字签名是：

Ekb(Ska(h(m)))其中 h 是 Hash 函数E_{k_b}\big(S_{k_a}(h(m))\big) \quad \text{其中 } h \text{ 是 Hash 函数}Ekb​​(Ska​​(h(m)))其中 h 是 Hash 函数

——第四讲造的 Hash 函数，在这里被用上了。

补把两讲的关系画成一张图，整个课程就串起来了：

第四讲：Hash 函数（做"指纹"）
   │
   │  h(m) 把任意长的消息压成定长摘要
   │  且抗碰撞（防止签名被"偷换"）
   ↓
第五讲：公钥密码（做"密钥分发"与"认证"）
   │
   ├─ 加密：E_{k_b}(m)        ← 保密性
   ├─ 签名：S_{k_a}(h(m))     ← 认证 + 不可否认（需要 Hash！）
   └─ 混合加密：E_{k_b}(对称密钥) + AES(消息)   ← 实际系统

补最后提醒一个"不可否认"的工程现实（PPT 没细说）：

"不可否认"在技术上是可以实现的（用签名），但它在法律和管理层面才是真正的难点：

  • 私钥可能被盗用（那"不是我签的"就有道理了）；
  • 私钥可能在胁迫下被使用；
  • 需要"时间戳服务"才能确定签名的时间。

——所以"不可否认"是一个"技术 + 管理 + 法律"的综合问题，不是单靠密码学就能解决的。 这一点 PPT 只提了一句"这些目标容易实现"，但"容易实现"指的是技术层面。

8.3 陷门单向函数（PPT 第 79–80 页）

补这一节把整讲的数学内核抽象出来——"公钥密码"本质上就是"陷门单向函数"的应用。

定义 2　陷门单向函数（PPT 第 79 页）

PPT 原文：

定义 2 一个陷门单向函数是一个单向函数 f:X→Yf: X \to Yf:X→Y 并附加一条性质就是：给定一些额外信息（称为陷门信息），则给定任意 y∈Yy \in Yy∈Y，发现 x∈Xx \in Xx∈X 满足 f(x)=yf(x) = yf(x)=y 将由计算困难变得容易。

补把定义拆成两部分：

部分 含义
单向函数 正向算 f(x)f(x)f(x) 容易；反向求 xxx 困难
+ 陷门 但如果有人给你"额外信息"（陷门），反向求 xxx 就变容易了

补把三个概念摆在一起，你就看出"陷门"是多了什么：

普通函数：     正向容易，反向也容易          （比如 y = 2x）
单向函数：     正向容易，反向难              （只能"单向"用）
陷门单向函数： 正向容易，反向难，
               但【有陷门的人】反向容易      ← 多了这一个条件

补"陷门（trapdoor）"这个比喻很贴切：

  • 没有陷门（钥匙）的人：能进去（正向），出不来（反向）；
  • 有陷门的人：可以随时打开暗门，自由进出。

在 RSA 里，"陷门信息"就是 ppp 和 qqq（以及 φ\varphiφ、ddd）：

有陷门（知道 p,q,dp,q,dp,q,d） 没陷门（只有 n,en,en,e）
加密 Ek(m)=meE_k(m) = m^eEk​(m)=me 容易 容易（这就是为什么公钥能公开）

补PPT 那个带 # 的注释说了一件很"哲学"的事：

# 没有人能够在对"容易"和"计算困难"合理定义下明确证明陷门单向函数的存在性。事实上，单向函数的存在性仍然未知，陷门单向函数的存在性自然也是未知问题。但是，我们还是找到了一些性能很好的单向和陷门单向候选函数。

补这段话有三个层次，值得逐个理解。

层次一：单向函数存在吗？——不知道。

这不只是一个"技术难题"，而是一个"复杂性理论的核心开放问题"：

单向函数存在⟹P≠NP\text{单向函数存在} \quad \Longrightarrow \quad \mathrm{P} \neq \mathrm{NP}单向函数存在⟹P=NP

（如果单向函数存在，那么 P 一定不等于 NP——因为单向函数的存在意味着"有一个容易验证但难以逆向的问题"，这正是 P≠NP 的一种表现。）

而 P≠NP\mathrm{P} \neq \mathrm{NP}P=NP 是理论计算机科学最重要的未解问题之一（千禧年七大问题之一，悬赏 100 万美元）。

所以严格来说：

"单向函数存在" 至今未被证明，也未被否定"\text{单向函数存在}" \text{ 至今未被证明，也未被否定}"单向函数存在" 至今未被证明，也未被否定

补层次二：所以所有这些密码学都是建立在"假设"上。

这是整门课最该记住的一句话：

所有实际使用的密码学，其安全性都建立在"某个未被证明的假设"上\text{所有实际使用的密码学，其安全性都建立在"某个未被证明的假设"上}所有实际使用的密码学，其安全性都建立在"某个未被证明的假设"上
  • RSA 假设 分解大整数困难；
  • Rabin 假设模合数开平方困难（但已证明它等价于分解）；
  • AES 假设没有比穷举更好的攻击（这是"经验性"的，连归约都没有）。

补这不是"密码学不严谨"，而是"密码学只能这样"：

如果哪天有人证明了单向函数不存在，那么所有公钥密码一下子全部失效——但那天也意味着 P=NP，整个计算机科学都会重写。

用一句更实在的话说："没人能证明它安全"和"它不安全"是两件事。一个方案可以"未被证明安全"但"在实践中极其可靠"（因为全世界几十亿人试了几十年都没攻破）。

补层次三：所以 PPT 用的是"候选函数"（candidate）这个词。

注意 PPT 最后一句的措辞：

但是，我们还是找到了一些性能很好的单向和陷门单向候选函数。

——"候选"两个字是诚实而准确的：

它们不是"被证明的陷门单向函数"，而是"看起来像"的候选者\text{它们不是"被证明的陷门单向函数"，而是"看起来像"的候选者}它们不是"被证明的陷门单向函数"，而是"看起来像"的候选者

补理解这个措辞的严谨性，对你评估任何"新的密码方案"都很重要：当有人宣称"我的方案是安全の"时，正确的追问是"你假设了什么难题是困难的？这个假设被检验过多久？"

陷门单向候选函数（PPT 第 80 页）

PPT 原文：

补注意第（1）条里 PPT 用了"相信分解整数 nnn 是困难的"——"相信"这个词和第（2）条没有用这个词，形成了微妙的对比：

  • RSA：单向性建立在"相信"上（一个未被证明的假设）；
  • Rabin：单向性可以证明等价于分解（第 7 节的归约）。

——这就是为什么第 1 节说"Rabin 的工作在理论上具有重要价值"。

补第（1）条里"陷门信息是 ppp 和 qqq、φ\varphiφ、或 ddd"这个列举，回顾了第 3.1 节的两条事实：

三样东西任一样都是"陷门信息"——因为它们互相可推（第 3.1 节那张"一破全破"的图）。

补而 Rabin 的陷门信息"只有 ppp 和 qqq"：

因为 Rabin 没有 eee 和 ddd（指数固定是 2），所以陷门就只剩下"nnn 的分解"这一件事。

这个"更少的陷门信息"也说明了 Rabin 的"更纯粹"：它的单向性完全、且仅仅依赖于"分解困难"这一个假设。

        │
        ├─ 正向容易 → 可以"公开"（这就是公钥能公开的原理）

——所有公钥密码（RSA、Rabin、ElGamal、ECC……）都只是"不同形式的陷门单向函数"。
