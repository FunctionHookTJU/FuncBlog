4.2 由 MDC 构造的 MAC（PPT 第 48–49 页）

朴素想法与它的两个致命缺陷（PPT 第 48 页）

PPT 原文：

由 MDC 算法构造 MAC 算法的一个建议是简单地把秘密密钥 kkk 作为 MDC 的输入的一部分。但因为 MDC 和 MAC 的定义并不完全一致，因此这种设计必须细致分析。

（1） 消息为 x=x1x2⋯xtx = x_1 x_2 \cdots x_tx=x1​x2​⋯xt​ 和使用迭代函数 fff 的迭代 MDC hhh：定义

H0=IV;Hi=f(Hi−1,xi), 1≤i≤t;h(x)=Ht。H_0 = IV; \quad H_i = f(H_{i-1}, x_i),\ 1 \le i \le t; \quad h(x) = H_t。H0​=IV;Hi​=f(Hi−1​,xi​), 1≤i≤t;h(x)=Ht​。
（1.1） 如果建议的 MAC 对 xxx 的值是 M=h(k∥x)M = h(k \| x)M=h(k∥x)，则攻击者可以计算 M′=h(k∥x∥y)=f(M∥y)M' = h(k \| x \| y) = f(M \| y)M′=h(k∥x∥y)=f(M∥y) 作为 x∥yx \| yx∥y 的 MAC 值。 （1.2） 如果建议的 MAC 对 xxx 的值是 M=h(x∥k)M = h(x \| k)M=h(x∥k) 输出是 nnn 比特，则产生 xxx 和 x′x'x′ 满足 M=h(x′∥k)=h(x∥k)M = h(x' \| k) = h(x \| k)M=h(x′∥k)=h(x∥k) 的复杂度为 O(2n/2)O(2^{n/2})O(2n/2)，nnn 是 hhh 函数的输出比特长度。

补先明确这一节的"朴素想法"是什么：既然 MAC 和 MDC 都叫"Hash 函数"，那最省事的做法就是把密钥当成消息的一部分塞进去：

方案 A：M=h(k∥x)（密钥拼在消息前面）\text{方案 A：} \quad M = h(k \| x) \qquad \text{（密钥拼在消息前面）}方案 A：M=h(k∥x)（密钥拼在消息前面）
方案 B：M=h(x∥k)（密钥拼在消息后面）\text{方案 B：} \quad M = h(x \| k) \qquad \text{（密钥拼在消息后面）}方案 B：M=h(x∥k)（密钥拼在消息后面）

PPT 的结论是：两个都不行，但"坏"的方式不同。

补（1.1）方案 A 被击穿——这就是长度扩展攻击的具体版本。

回忆 2.1 节的迭代结构：

Hi=f(Hi−1,xi)H_i = f(H_{i-1}, x_i)Hi​=f(Hi−1​,xi​)

注意：这个递推式不需要知道 H0H_0H0​ 是什么！ 只要有人告诉你"当前状态是 MMM"，你就能接着往下跑任何东西。

所以攻击者的操作是：

合法 MAC 值 M = h(k ‖ x) = 处理完 (k‖x) 之后的链变量

攻击者把 M 当作新的"起始状态"，继续喂进 y：

   M ──→ f(M, y) = M'

于是 M' 就是 h(k ‖ x ‖ y) 的值  ✓

攻击者成功伪造了消息 (x ‖ y) 的合法 MAC ！

大白话："密钥在前"的构造，相当于把 MAC 值本身当成了一个"可继续使用的中间状态"。攻击者不需要知道 kkk，只需要知道 MMM，就能"接着往下滚"。

补这正是 3.2 节末尾讲的"长度扩展攻击"。"M=h(k∥x)M = h(k \| x)M=h(k∥x)" 是教科书上最经典的错误 MAC 构造。记住这个反面教材：任何把密钥放在消息前面的 Hash-MAC 构造都是坏的。

补（1.2）方案 B 也没好到哪去——但它坏的方式不同。

方案 B 的漏洞是"碰撞"：如果 hhh 是 nnn 比特输出，那么按 2.2 节事实 5，找碰撞的代价是

O(2n/2)O\left(2^{n/2}\right)O(2n/2)

一旦攻击者找到两个消息 xxx 和 x′x'x′ 满足 h(x∥k)=h(x′∥k)h(x \| k) = h(x' \| k)h(x∥k)=h(x′∥k)，他就有了一对"碰撞的 MAC"——于是他可以拿 x′x'x′ 冒充 xxx。

补注意（1.2）里那个 O(2n/2)O(2^{n/2})O(2n/2) 是两个都要撞到 kkk 前面吗？ 不是。攻击者的做法是"构造 xxx 和 x′x'x′ 让它们在"x∥kx\|kx∥k"这个整体上产生同样的 Hash 值"。严格地说，攻击者需要找到 h(x∥k)=h(x′∥k)h(x\|k) = h(x'\|k)h(x∥k)=h(x′∥k)——他不知道 kkk，但他可以做的是：

利用 Hash 的碰撞性，构造出一对"在某个共同后缀下会碰撞"的消息（也就是所谓的"碰撞块"），然后把 kkk 当成那个后缀。因为 Hash 的碰撞是由中间状态决定的，如果两个消息在某个位置之后的内部状态相同，那么无论后面接什么（包括 kkk），最终的 Hash 值都相同。

所以攻击者只要找到一对"内部状态相同"的消息 xxx 和 x′x'x′ 就行了——代价 O(2n/2)O(2^{n/2})O(2n/2)。

补这个坑的教训是："密钥在后"虽然挡住了长度扩展，但没挡住碰撞。这就是 4.2 节开头那句"因为 MDC 和 MAC 的定义并不完全一致，因此这种设计必须细致分析"的含义——MDC 要求的是"抗碰撞"，MAC 要求的是"抗伪造"，这两个目标不能直接互换。

补把两个方案的失败原因并排看，一目了然：

构造 失败原因 攻击代价
M=h(k∥x)M = h(k \| x)M=h(k∥x) 长度扩展：MMM 就是内部状态，可以接着往下跑 攻击者知道 MMM 就够了，几乎零成本
M=h(x∥k)M = h(x \| k)M=h(x∥k) 碰撞：两个消息内部状态相同，加什么都不变 O(2n/2)O(2^{n/2})O(2n/2)

两个方案"一前一后"，正好各中一个坑。 所以正确做法必然要把密钥同时用在两头（下面的（2）和（3））。

两个可行的构造（PPT 第 49 页）

PPT 原文：

（2） 对密钥为 kkk 和 MDC 为 hhh，可按如下方式计算消息 xxx 的 MAC 值

hk(x)=h(k∥p∥x∥k)。h_k(x) = h(k \| p \| x \| k)。hk​(x)=h(k∥p∥x∥k)。
其中 ppp 将用于将 kkk 填充为一个分组长度，从而保证内部至少进行两次分组计算。

（3） 对密钥为 kkk 和 MDC 为 hhh，另一种计算消息 xxx 的 MAC 值的方式是

hk(x)=h(k∥p1∥h(k∥p2∥x))。h_k(x) = h(k \| p_1 \| h(k \| p_2 \| x))。hk​(x)=h(k∥p1​∥h(k∥p2​∥x))。
其中 p1,p2p_1, p_2p1​,p2​ 用于将 kkk 填充为一个分组长度。

补先看（2）：密钥在两头

hk(x)=h(k∥p∥x∥k)h_k(x) = h(k \| p \| x \| k)hk​(x)=h(k∥p∥x∥k)

这个构造同时堵住了两个坑：

坑 为什么被堵住
长度扩展（密钥在前） 末尾那个 kkk 挡住了。攻击者想接着往下跑，但"跑完之后还要不要异或/再处理 kkk"他不知道，也就没法预判结果
碰撞（密钥在后） 开头那个 kkk 挡住了。攻击者想构造"内部状态相同的 xxx 和 x′x'x′"，但他算不出开头 k∥pk\|pk∥p 之后的内部状态

再注意那个 ppp：PPT 说 ppp 是"用于将 kkk 填充为一个分组长度"的填充串。为什么必须要有它？

补ppp 的作用是"保证内部至少进行两次分组计算"——PPT 自己解释了。这句解释背后的攻击是：

如果 kkk 不足一个分组长度，那么 k∥xk \| xk∥x 的第一块里"密钥还没填满就被消息补上了"。这时候攻击者可以做一件很讨厌的事：把 kkk 的一部分"推"到下一个分组去，从而在"消息 xxx"和"另一个消息 x′x'x′"之间建立对应关系（这叫"密钥位移攻击"）。

用 ppp 把 kkk 撑满整整一个分组之后，第一个分组就是"纯密钥分组"，不掺任何消息比特。这样"密钥"和"消息"在结构上被彻底分开了，攻击者没法在边界上做文章。这是"长度对齐"能带来安全性的一个典型例子。

补再看（3）：把 hhh 嵌套起来

hk(x)=h(k∥p1∥h(k∥p2∥x))h_k(x) = h\big(k \| p_1 \| h(k \| p_2 \| x)\big)hk​(x)=h(k∥p1​∥h(k∥p2​∥x))

这是"内外两层"的结构：

内层：h(k ‖ p₂ ‖ x)     ← 先对"密钥 + 消息"算一次，得到一个固定长度的摘要
          │
          ↓（这个摘要是定长的！）
外层：h(k ‖ p₁ ‖ 内层结果)  ← 再把"密钥 + 那个摘要"算一次

补这个构造的巧妙之处在于"内层输出是定长的"。

回想 hhh 的弱点：它的输入长度是可变的，而"变长"正是长度扩展攻击和碰撞构造可乘之机（攻击者可以在变长的部分做调整）。

内层先压成定长之后，外层看到的是一个固定长度的东西——攻击者的"调整空间"被压没了。这和第 3 节"填充 + 长度字段"的思路一致：把可变性先消掉，再做安全处理。

补这个嵌套结构就是 HMAC 的思路雏形。 HMAC（RFC 2104）的标准形式是：

HMAC(k,x)=h((k⊕opad)∥h((k⊕ipad)∥x))\mathrm{HMAC}(k, x) = h\big((k \oplus \mathrm{opad}) \| h((k \oplus \mathrm{ipad}) \| x)\big)HMAC(k,x)=h((k⊕opad)∥h((k⊕ipad)∥x))

看出来了吗？ 它和 PPT 的（3）结构完全一样——"内外两层、密钥各用一次"，区别只在于 HMAC 用固定的填充常量 ipad/opad（0x36 和 0x5C 重复）异或到密钥上，而不是用变长的 p1,p2p_1, p_2p1​,p2​。

补HMAC 为什么比（3）更受欢迎？因为用了固定的 ipad/opad 之后，有两个好处：

  1. 不需要"填充到分组长度"这个额外步骤——因为 k⊕ipadk \oplus \mathrm{ipad}k⊕ipad 的长度天然就是 max⁡(k,分组长度)\max(k, \text{分组长度})max(k,分组长度)，工程上更好处理；
  2. 有可证明的安全性：HMAC 的安全性可以被归约到"底层压缩函数抗碰撞 + 伪随机"这两个性质上（Bellare–Canetti–Krawczyk 的结果），这是（3）这种"随手设计"的构造给不出的。

补一句总结 4.2 节：密钥塞进 Hash 里是有讲究的。

✗  M = h(k ‖ x)              密钥在前 → 长度扩展
✗  M = h(x ‖ k)              密钥在后 → 碰撞
✓  M = h(k ‖ p ‖ x ‖ k)      两头都放，还要长度对齐
✓  M = h(k‖p₁‖ h(k‖p₂‖ x))   内外嵌套（HMAC 的雏形/本尊）

记住这张表，就掌握了"为什么不能随便把密钥拼进 Hash 值"的全貌。
