4　带密钥密码 Hash 函数：MAC

对应 PPT 第 44–52 页。第 3 节讲的是"谁都能算的指纹"（MDC），这一节讲"只有自己人能算的指纹"（MAC）。核心区别就一个字：密钥。

这一节也有两条路线，和第 3 节完全对应：

  • 4.1 基于分组密码：CBC-MAC（用任意分组密码 EkE_kEk​ 搭）
  • 4.2 由 MDC 构造：把密钥塞进无密钥 Hash 函数里
  • 4.3 定制：MD5-MAC（从 MD5 改出来的带密钥版本）

4.1 基于分组密码的 Hash 函数：CBC 的 MAC（PPT 第 44–47 页）

CBC-MAC 算法（PPT 第 44 页）

PPT 原文：

令 EkE_kEk​ 为分组密码。消息 MMM 被分成 nnn 比特的段 M=[M1,M2,⋯ ,Mt]M = [M_1, M_2, \cdots, M_t]M=[M1​,M2​,⋯,Mt​]，这里 nnn 是分组密码 EkE_kEk​ 的分组长度。基于 CBC 的 MAC 算法按如下步骤进行：

（1）CBC 处理。 按如下公式计算段 HiH_iHi​：

H1=Ek(M1);Hi=Ek(Hi−1⊕Mi), 2≤i≤t。H_1 = E_k(M_1); \qquad H_i = E_k(H_{i-1} \oplus M_i),\ 2 \le i \le t。H1​=Ek​(M1​);Hi​=Ek​(Hi−1​⊕Mi​), 2≤i≤t。
（2）可选处理用于增加 MAC 的强度。使用另一个密钥 k′≠kk' \neq kk′=k，可选计算：
Ht′=Dk′(Ht),Ht=Ek(Ht′)。H'_t = D_{k'}(H_t), \qquad H_t = E_k(H'_t)。Ht′​=Dk′​(Ht​),Ht​=Ek​(Ht′​)。
（3）完成。 MAC 值是 nnn 比特的段 HtH_tHt​。

先看第（1）步：这就是 CBC 模式，只不过去掉了 IVIVIV。

上一册第三讲第 8.2 节讲过 CBC 模式：

CBC 加密：Ci=Ek(Ci−1⊕Mi),C0=IV\text{CBC 加密：} \quad C_i = E_k(C_{i-1} \oplus M_i), \qquad C_0 = IVCBC 加密：Ci​=Ek​(Ci−1​⊕Mi​),C0​=IV

对比一下：

CBC 加密（上一册）：        CBC-MAC（本节）：
C₀ = IV                    H₀ = 0   （也就是"IV = 全零"）
C₁ = E_k(C₀ ⊕ M₁)          H₁ = E_k(M₁)          ← 因为 H₀⊕M₁ = 0⊕M₁ = M₁
C₂ = E_k(C₁ ⊕ M₂)          H₂ = E_k(H₁ ⊕ M₂)
   ⋮                          ⋮
C_t = E_k(C_{t-1} ⊕ M_t)   H_t = E_k(H_{t-1} ⊕ M_t)
输出 C₁C₂…C_t（全部）      输出 H_t（只要最后一块！）

两个关键差别：

CBC 加密 CBC-MAC
初始值 IVIVIV（可随机、可变化） 固定为全零（等价于不用 IVIVIV）
输出 全部密文块 C1⋯CtC_1 \cdots C_tC1​⋯Ct​ 只有最后一块 HtH_tHt​
目的 保密（可逆） 认证（不可逆）

补为什么把 IVIVIV 去掉？ 因为 MAC 的验证方必须能重算出同一个值。如果 IVIVIV 每次随机，那么发送方和接收方算出的 MAC 就不同了，没法比对。

那"不随机"会不会不安全？ 这里不安全的点变了：CBC 加密需要随机 IVIVIV 来保证"同样的明文两次加密结果不同"；而 CBC-MAC 根本不需要这个性质——它要的就是"同样的消息永远给出同样的 MAC"。（如果同一条消息每次 MAC 都不同，接收方就没法验证了。）

补这是"同一个结构，不同的安全目标"的典型例子。 上一册讲 CFB 模式时也提过类似的事：同一个零件，换个接法，安全性就从"保密性"变成"认证性"。遇到这类"看起来是把老算法改了几笔"的东西，一定要重新想一遍它的安全目标是什么，不能照搬老结论。

第（2）步：可选的"解密再加密"处理

Ht′=Dk′(Ht),Ht=Ek(Ht′)H'_t = D_{k'}(H_t), \qquad H_t = E_k(H'_t)Ht′​=Dk′​(Ht​),Ht​=Ek​(Ht′​)

注意这里用了一个新的密钥 k′≠kk' \neq kk′=k，而且中间做了一次解密 Dk′D_{k'}Dk′​（这就是 PPT 说的"可选处理"，也叫 "三密钥变体" 或者俗称为 EMAC / 密文后处理）。

补为什么要"解密一下再加密回去"？ 关键在于 Dk′D_{k'}Dk′​ 引入了一个 EEE 的"逆"，从而打断了纯 CBC 迭代的结构。

前面说过 CBC-MAC 的弱点（下面"评论（3）"会具体展示）：攻击者可以从已有的合法样本推出新样本的 MAC。这些攻击之所以能成功，靠的就是"MAC 满足某种可组合的迭代规律"。插入一次 Dk′D_{k'}Dk′​ 之后：

  • 攻击者不知道 k′k'k′，没法在中间状态上做手脚；
  • Dk′D_{k'}Dk′​ 的输出看起来是随机的，把迭代规律打断了。

所以这一小步的作用就是"加一个攻击者无法穿透的黑盒"——这和第 4.2 节要讲的"把密钥 kkk 放在消息两头"是同一类思路（用密钥封住两端，让攻击者没法做结构性的拼接）。

补最后那句 PPT 的话很值得记：「由于没有在整个过程中使用三重加密，所以不会特别影响效率。」意思是这一步只多了"一次解密 + 一次加密"，不是把整个流程跑三遍。所以它几乎没有性能代价，却显著提高了安全性。这是"低成本的正确做法"的范例。

第（3）步：MAC 值就是最后那一段 HtH_tHt​。

MAC=HtMAC = H_tMAC=Ht​

长度是 nnn 比特（nnn = 分组长度）。如果用的是 DES，n=64n = 64n=64，所以 CBC-MAC 输出 64 比特；用 AES 则是 128 比特。对照 2.2 节事实 6 的"MAC 要求 n≥64n \geq 64n≥64"，DES 的 CBC-MAC 刚好达标。

补看图要抓住三件事：

  1. 第一条输入是 M1M_1M1​ 直接进 EkE_kEk​（因为前面异或的是 0）；
  2. 每一条之后的输入都是"上一块的输出 Hi−1H_{i-1}Hi−1​ 异或当前消息块 MiM_iMi​"；
  3. 只有最后一块的输出被取走，中间那些 H1,H2,…H_1, H_2, \ldotsH1​,H2​,… 全部丢弃。

第 3 点最容易被人忽略，但它是安全性的核心：

  • CBC 加密把全部密文块都发出去，所以攻击者能看到所有中间状态；
  • CBC-MAC 只输出最后一块，中间状态是内部的、攻击者看不到——这就是"不可求逆的数据压缩"（下面评论（1）会讲）。

补这也解释了为什么 MAC 的"输出长度"要求比 Hash 低（2.2 节事实 6：MAC 只要 n≥64n \geq 64n≥64）：因为攻击者看不到中间状态，他能利用的信息比攻击一个 MDC 时少得多，所以不需要那么长的输出就能达到同样的安全水平。

评论（PPT 第 46–47 页）

PPT 第 46 页原文：

（1） 很明显，在生成 CBC-MAC 值（由运行 CBC 模式的分组密码构造的 MAC）的计算中包括了不可求逆的数据压缩（本质上，CBC-MAC 是整个消息的"短摘要"），因此，CBC-MAC 是一个单向变换。所有的分组密码加密算法的混合变换性质为这个单向函数变换增加了一个杂凑特点（也就是说，将 MAC 分布到 MAC 空间与分组密码加密算法将密文分布到密文空间同样均匀）。

补这一段讲了 CBC-MAC 为什么有"单向性"：

  1. 不可逆的压缩：ttt 个 nnn 比特的块被压成 1 个 nnn 比特的块——信息被丢掉了 (t−1)×n(t-1) \times n(t−1)×n 比特。丢得越多越不可逆。
  2. 分组密码的"混合"性质被继承过来：因为 EkE_kEk​ 内部有 S-盒、置换、异或这些"搅拌"操作，它的输出在密钥未知时看起来均匀分布。CBC-MAC 把这个性质继承了——所以 MAC 值的分布也是"看起来均匀的"，攻击者无法从分布上区分出"哪些 MAC 值更可能出现"。

补"均匀分布"这一点在安全上很关键：如果 MAC 值的分布不均匀（比如某些值出现概率高），攻击者就可以优先猜那些高概率的值，从而把"猜 MAC"的成本从 2−n2^{-n}2−n 降下来。均匀分布保证了"每个值的机会一样"，攻击者只能瞎猜。

PPT 第 47 页原文（评论 2–4）：

（2） 如果考虑穷举密钥搜索攻击，可以考虑最后仅输出 nnn 比特中的 mmm 比特作为 MAC 数值。

（3） 单分组消息 x1x_1x1​，x2x_2x2​ 的两个文本消息-MAC 对 (x1,H1)(x_1, H_1)(x1​,H1​) 和 (x2,H2)(x_2, H_2)(x2​,H2​)。对一个 2 分组的第三个消息 x1∥zx_1 \| zx1​∥z 请求 MAC 值 MMM，产生文本消息-MAC 对 (x1∥z,M)(x_1 \| z, M)(x1​∥z,M)。由此，知新 2 分组的消息 X=x2∥(H1⊕z⊕H2)X = x_2 \| (H_1 \oplus z \oplus H_2)X=x2​∥(H1​⊕z⊕H2​) 的 MAC 值也是 MMM。

（4） 可选处理减少了穷举密钥搜索攻击的威胁，阻止了选择文本攻击的存在性伪造，由于没有在整个过程中使用三重加密，所以不会特别影响效率。

补评论（2）：为什么可以"只输出 mmm 比特"？

这是性能与安全的又一次权衡：

  • 输出越短，伪造越容易：攻击者猜中一个 mmm 比特 MAC 的概率是 2−m2^{-m}2−m；
  • 但输出越短，传输/存储开销越小。

所以如果应用场景允许"每天只认证几次"（比如某种一天一次的批处理），那么 2−322^{-32}2−32 的猜中概率乘以次数之后总风险仍然可接受——这正是 2.2 节事实 6 说的"如果有特别控制，可小到 n=32n = 32n=32 或 404040"。

补评论（3）：这是 CBC-MAC 最经典的攻击，务必自己推一遍。 它展示的就是"从两个合法样本伪造出第三个合法样本"，也就是存在性伪造。

攻击的目标：伪造出一个新的 2 分组消息 X≠x1∥zX \neq x_1 \| zX=x1​∥z，但它的 MAC 值等于已知的 MMM。

攻击者手里的三样东西：

  1. (x1,H1)(x_1, H_1)(x1​,H1​) —— 单分组消息 x1x_1x1​ 的 MAC。其中 H1=Ek(x1)H_1 = E_k(x_1)H1​=Ek​(x1​)。
  2. (x2,H2)(x_2, H_2)(x2​,H2​) —— 单分组消息 x2x_2x2​ 的 MAC。其中 H2=Ek(x2)H_2 = E_k(x_2)H2​=Ek​(x2​)。
  3. (x1∥z,M)(x_1 \| z, M)(x1​∥z,M) —— 2 分组消息 x1∥zx_1 \| zx1​∥z 的 MAC。其中
M=Ek(H1⊕z)M = E_k\big(H_1 \oplus z\big)M=Ek​(H1​⊕z)

（因为第一块 x1x_1x1​ 给出 H1H_1H1​，第二块 zzz 给出 Ek(H1⊕z)E_k(H_1 \oplus z)Ek​(H1​⊕z)。）

攻击者要构造的消息：

X=x2 ∥ (H1⊕z⊕H2)X = x_2 \ \big\|\ \big(H_1 \oplus z \oplus H_2\big)X=x2​ ​ (H1​⊕z⊕H2​)

验算 XXX 的 MAC 值（用自己的手把 CBC-MAC 走一遍）：

第一步：吃进 x₂
        H₁' = E_k(x₂) = H₂          ← 这一步就是"已知的样本 2"！

第二步：吃进 (H₁ ⊕ z ⊕ H₂)
        输入值 = H₁' ⊕ (H₁ ⊕ z ⊕ H₂)
               = H₂ ⊕ H₁ ⊕ z ⊕ H₂
               = H₁ ⊕ z              ← H₂ 异或自己，消失了！
        H₂' = E_k(H₁ ⊕ z)
            = M                  ← 这正是已知样本 3 的 MAC 值！

所以 XXX 的 MAC 值确实是 MMM。 ✓

补把攻击的"要害"说清楚：CBC-MAC 的迭代是"可拼接"的。因为每一步都满足

Hi=Ek(Hi−1⊕Mi)H_i = E_k(H_{i-1} \oplus M_i)Hi​=Ek​(Hi−1​⊕Mi​)

这个递推式只依赖"上一状态异或当前块"。所以只要攻击者能让某个状态的异或结果"回到"一个已知的值，后面的计算就完全复现已知结果——他做的调整就是"补一个异或项把差抵消掉"（这里补的是 H1⊕H2H_1 \oplus H_2H1​⊕H2​）。

补这类攻击的通用名字叫"扩展攻击"（extension attack），和第 3.2 节讲的 SHA-1 长度扩展攻击是同一个家族：都是因为"迭代结构可以被从中间接着往下跑"。区别是 SHA-1 是"知道 HtH_tHt​ 就能往后接"，CBC-MAC 是"知道两个中间状态的差，就能抵消掉"。

防御手段有两个，PPT 都提到了：

  1. 用"长度前缀"：把消息长度放在最前面一起算 MAC。这样攻击者改不了"总块数"，拼接就不成立了。（这是最常用的做法，叫 CMAC 的长度前缀变体。）
  2. 用 PPT 第（2）步的可选处理：把密钥 k′k'k′ 塞在最后。因为攻击者不知道 k′k'k′，他没法预测 Dk′D_{k'}Dk′​ 之后的结果，拼接就断了。

补评论（4）："阻止了选择文本攻击的存在性伪造"——这句话把可选处理的作用说得很准确，注意三个限定词：

词 含义
选择文本攻击 攻击者能指定要问哪些消息（1.1 节讲过的攻击者能力等级）
存在性伪造 只能造出"某个"消息 + 合法 MAC，控制不了内容（1.1 节的伪造分类）
阻止了 用了可选处理之后，这一档攻击被挡住了

所以可选处理不是"万能药"——它挡的是"存在性伪造"，而不是"选择性伪造"。但正如 1.1 节说过的，存在性伪造在实际中通常无害（攻击者造出来的是乱码消息），所以这个防护已经足够让 CBC-MAC 实用。

补另外注意 PPT 的用词："选择文本攻击"就是"选择消息攻击"，中文翻译不统一，指的是同一个东西（chosen-message attack）。
