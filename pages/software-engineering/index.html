如何使用这份笔记

这是一份按课件原有章节顺序重写的软件工程笔记，覆盖第 1–10 章共 869 页幻灯片。它不是把 PPT 抄一遍，而是把每章压缩成"这一章到底在讲哪几件事"，再把课件默认你会、其实没人给你讲过的东西补上。

这份笔记的三条使用建议

第一，先看第 0 章。 软件工程这门课最难的地方不是知识点多，而是它没有"可运行的证据"。你写不出一个程序来证明"我懂内聚耦合"，也没有编译器帮你检查"这个设计是不是可维护"。所以整门课靠的是概念之间的对应关系：需求对应设计，设计对应代码，代码对应测试，测试对应维护。第 0 章就是把这张对应关系图先铺好，后面每一讲都往里填。

第二，把每讲末尾的自测题当成"能不能合上书讲出来"的检验。 这门课的考试极少考背定义，绝大多数是给一个场景，问你该选哪个模型、哪种维护、哪个覆盖标准。能对着场景说出"因为……所以选……"才算会。

第三，凡是"要看形状才讲得清"的地方，图都配好了。 全书紧贴正文插了 76 张课件原图——生命周期、瀑布阶梯、增量与迭代的横向纵向、原型环路、螺旋四象限、需求来源、对象的三块（界面/状态/实现）、抽象的教师—李伟对照、用例图（含银行储蓄系统完整用例图）、ATM 的两版对象模型、状态图与事件跟踪图、内聚耦合七级阶梯、六种架构风格、界面设计类图、N-S 与 PAD、覆盖标准流程图、四类维护饼图、再工程示意图……每张图下面都有三段式图注：

  • 图号（如"图 3-1"是第 3 讲第 1 图，方便口头引用与互相指认）；
  • （PPT 第 N 页），可以直接翻课件对照；
  • 这张图和上下文的哪句话对应、看图该重点看哪一处——先看图理解形状，再回来看文字，比单向读文字快得多。

图片可以点击，在新标签页里看原尺寸（正文里是按栏宽缩放的）。如果只记得"有个阶梯图""有个饼图"却想不起细节，按 Ctrl+F 搜图号最快。

十讲之间的逻辑线

整门课其实只讲了一件事：软件规模一大，"一个人随手写"就不成立了，于是必须把它拆成阶段、约定产物、规定做法。 十讲就是这条链上的十个环节。

阶段 讲次 一句话任务 关键产物
认识对象 1–2 软件是什么、为什么需要工程 —
定做法 3 按什么顺序、什么节奏做 过程模型
问清楚 4–5 用户到底要什么 需求模型、需求规格说明书
想明白 6–7 用什么结构去实现 设计模型、设计文档
写出来 8 把设计翻译成代码 源代码、单元测试
验一遍 9 证明它确实能跑对 测试用例、测试报告
活下去 10 交付之后还得改十年 维护记录、演化版本

一句话串起整门课：软件工程 = 用工程化的手段，把"人脑里的想法"逐级翻译成"机器能执行、别人能维护的制品"，并在每一级翻译处留下可检查的证据。

考试重点清单（据《软件工程重点内容》）

老师给的《软件工程重点内容》只有条目名，下面把每一条都落到讲义的具体小节——点表格里的蓝字直达，那一节标题右侧会显示红色「重点」徽章，正文里也有一条 重点 说明「怎么考」。

说明：左两列来自老师给的清单（原文照录）；「怎么考」一列是笔记作者的判断，不是老师原话，只用来把每个条目转成一句可以自测的话。

教材章节 重点条目 怎么考
1.2 软件及其特点 软件的组成 程序 + 数据 + 文档缺一不可；判断题爱问「文档算不算软件的组成部分」。
软件的生命周期 六阶段各自回答 What 还是 How、产出什么制品。
软件的分类 应用 / 系统 / 支撑的划分标准；DBMS 属系统软件是常见陷阱。
开源软件的优势 三条优势能背；还要会答「开源 ≠ 免费」。
软件质量要素 质量 = 满足给定需求的程度；三个维度是可维护性、灵活性、可测试性。
2 软件工程概述 软件危机的表现 五个症状要能按顺序说，并解释各自后果。
软件工程的要素 过程 / 方法学 / 工具各自管什么、为什么都指向质量保证。
软件工程的原则 八条原则逐条说出并各举一例，最可能出简答。
3.1 软件过程模型 典型软件过程模型 五种模型的适用场景与区别；常给场景问「选哪个、为什么」。
3.2 敏捷开发方法 敏捷开发的概念和观点、敏捷准则、代表方法 敏捷宣言四组价值观 + 敏捷准则 + Scrum/XP 代表方法。
4 软件需求分析基础 利益相关方 谁能算 stakeholder、为何要全识别、需求冲突如何协商。
软件需求的类别 功能 / 非功能 / 设计约束三分法，给一句话判类别。
面向对象的需求分析方法 为什么用对象与类建模，OOA 与结构化分析的差别。
5 获取软件需求 获取软件需求的方法 六种获取方法各自的适用场景与局限。
用例图（包括用例的详细描述） 参与者、用例、系统边界，包含 / 扩展 / 泛化三种关系。
用例的详细描述 用例描述四字段：前置条件、基本路径、可选路径、后置条件。
6 分析软件需求 类图 类的三格 + 关联 / 聚合 / 组合 / 泛化 / 依赖五个关系。
顺序图 生命线、同步 / 异步 / 返回消息，按时间顺序读。
状态图 状态、事件、迁移、监护条件；何时该用状态图。
分析软件需求过程 理解—表达—验证三动作，分析阶段产出哪些模型。
软件需求文档 需求规格说明书的必备内容与好文档判据。
7 软件设计基础 软件设计的质量要求 高质量设计的判据，以及设计质量为什么难验证。
软件设计原则 七条原则 + 高内聚低耦合；第 6 讲最典型简答。
8 软件体系结构设计 常用软件体系结构风格 六种风格的优缺点与选型依据。
10 软件详细设计 详细设计过程 详细设计做什么；流程图 / N-S / PAD / PDL 怎么取舍。
活动图 活动、判定、并发分叉；用来细化用例内部步骤。
用例设计 / 类设计 / 数据设计 体系结构 → 界面 → 构件 → 用例 → 数据 → 类的顺序与产物。
13 软件测试 软件测试过程 计划 → 检查 → 单元 → 集成 → 确认 → 系统 → 验收的主链。
软件测试原则 十条测试原则要能背（穷举不可能、缺陷集群性等）。
软件测试技术（白盒） 五种覆盖的强弱次序与用例数。
软件测试技术（黑盒） 等价类、边界值、错误猜测、因果图四种方法。
15 软件维护和演化 软件维护的形式 四类维护的判别（给场景选类型）与比例。
软件维护技术 代码重组、逆向工程、设计重构、再工程的区别与条件。

共 12 个教材章节、24 条重点（其中几条在讲义里拆成了更细的小节，表中共 33 个可点击条目，落在 22 个页面、34 个标注点上）。其余小节是背景、案例与小结，不算重点。复习时按这张表逐条「合上书讲一遍」，比从头重读快得多。

清单之外的高频考点（老师清单没列，但综合题会考）

老师的《重点内容》只列到"章节 + 条目"这一级，有些画图题和计算题没写进去，复习时最容易漏。下面几个是看了历年综合题的题型后补的，位置都在讲义里：

考点 位置 一句话
N-S 图 ↔ PAD 图互转 26 详细设计四工具 同一棵树换排版：选择画三角、循环画竖线，三条规则机械转
McCabe 复杂性度量（环路复杂度） 31 基本路径测试 V(G)=E−N+2=V(G)=E-N+2=V(G)=E−N+2= 判定结点数 +1+1+1；条件分支与每个循环各算 1 个判定
活动图 vs 流程图 18 UML 九图 活动图支持并发分叉/泳道，流程图只有顺序、分支、循环
内聚七级 / 耦合七级 23 模块化 综合题常给一段模块描述，让你判断是哪一级
用例描述四字段、类图五种关系 16 用例描述、18 类图 需求建模类大题的两块地基

这类考点不意味着老师改了重点——只是提醒你：清单覆盖的是"知识点"，综合题还会考"把两个知识点串起来算一算"。遇到清单里没有、但 PPT 里画了图的工具（N-S、PAD、判定表、因果图），建议都至少练一道手算题。
