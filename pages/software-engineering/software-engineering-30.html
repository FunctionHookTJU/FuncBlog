3.1–3.4 白盒测试：逻辑覆盖与基本路径

3.1 白盒与黑盒的分界

课件第 58 页给的定义极简，但判据很清楚：

技术 依据 盒子里是什么
白盒测试 基于程序内部的执行流程设计测试用例 打开盒子，看结构
黑盒测试 基于程序的外在功能和接口设计测试用例 关上盒子，只看功能

这里的"盒子"对应基本模块单元（类方法、函数、过程）——这是测试的基本对象。

3.2 为什么要"覆盖"

课件第 60 页给了一段很有说服力的说理：

逻辑错误和不正确的假设都会和正确的路径执行成反比。 我们总是相信路径会被执行，但现实总是与直觉相悖。 排版印刷的错误是随机的，那么没有测试的路径偶尔也会被运行。

补这段话在说一件事：没被测试执行的代码 = 未知代码。它可能从来没跑过，也可能在某次真实使用中突然跑到并崩溃。更糟的是"偶尔跑到"——这种缺陷极难复现（第 8 讲的三类卡壳情形之一）。所以覆盖的目的不只是"验证这条路径对不对"，更是"确认这条路径至少能跑通"。

白盒测试的两个基本问题（PPT 第 61 页）：

  • 如何设计测试用例？→ 依据内部执行流程生成测试数据；
  • 设计多少测试用例？→ 遵循覆盖原则。

四种覆盖准则：语句覆盖、分支（判定）覆盖、路径覆盖、基本路径覆盖。

3.3 逻辑覆盖法：五种标准，逐级加严

课件第 62–77 页用一个统一的例子贯穿五种覆盖标准。这个例子必须能自己推一遍：

// 输入 A, B, X；输出 A, B, X
if ((A > 1) && (B == 0))   X = X / A;      // 判定（一）
if ((A == 2) || (X > 1))   X = X + 1;      // 判定（二）

流程图上的四个端点：a（入口）、b（判定一取假）、c（判定一取真，执行 X=X/A）、d（判定二取真，执行 X=X+1）、e（出口）。四条可能路径：L1 = a-c-e、L2 = a-b-d、L3 = a-b-e、L4 = a-c-d。

四个条件记作：判定（一）含 A>1、B==0；判定（二）含 A==2、X>1。

覆盖标准 要求 本例满足的用例 覆盖率局限
语句覆盖 每条语句至少执行一次 (2, 0, 4) —— 走 L1 最弱：判定为假的分支没测；若把判定一的"与"误写成"或"，此用例照样通过
判定（分支）覆盖 每个判定的真、假分支各至少一次 (2, 0, 4) 走 L1（两判定均真）+ (1, 1, 1) 走 L2（两判定均假） 不能保证每个条件都取到真假
条件覆盖 每个判定中每个条件的真、假各至少一次 (2, 0, 4)（A>1 真、B==0 真、A==2 真、X>1 真）+ (1, 1, 1)（四项全假） 不保证判定结果被覆盖（见下方反例）
判定/条件覆盖 同时满足判定覆盖与条件覆盖 同上两组 不保证条件组合被覆盖
条件组合覆盖 每个判定中所有条件取值组合至少一次 判定一有 (T,T)(T,F)(F,T)(F,F)；判定二同样 → 至少 4 组用例 组合数随条件数指数增长

条件覆盖不一定满足判定覆盖的反例（这个反例必须会）：

if (A && B) { ... }
// 用例 1：(A真, B假) → 判定为假
// 用例 2：(A假, B真) → 判定为假

两个用例把 A、B 的真假都取到了（满足条件覆盖），但判定结果只出现了"假"，真分支一次都没走（不满足判定覆盖）。这就是为什么还需要"判定/条件覆盖"这一层。

勘误课件第 71–72 页的"条件取值"表格中，"取真值"与"取假值"两列填写了相同的标记（如 T1 / T1），按上下文应为 T1 与 T̄1（非 T1）之类的对照；这属于课件排版笔误。判断标准应以文字定义为准（"每个条件的可能取值至少执行一次"），不要照抄表格。

五级严格性排序（后面不一定包含前面，只有"判定/条件"是并集）：

语句覆盖 < 判定覆盖 < 判定/条件覆盖 < 条件组合覆盖
                ↑
            条件覆盖（与判定覆盖互不包含）

补"覆盖率高 ≠ 程序正确"，这是白盒测试最容易被误解的地方。原因有三：①覆盖只说明"这段代码被执行过"，不说明"结果对不对"——它必须配合预期结果比对；②它测不出"该有的代码没写"（漏掉的需求根本不在流程图里）；③它测不出数据相关的错误（如 X/(A-2) 当 A=2 时的除零，除非用例恰好取到）。所以白盒用来保证内部逻辑被走遍，黑盒用来保证功能被满足，两者不可替代。

3.4 路径测试与基本路径

路径覆盖（PPT 第 79 页）：设计足够的用例，覆盖程序中每一条可能的执行路径至少一次；若含循环，则每个循环至少执行一次。

在同一个例子里，四条路径 L1–L4 各需一个用例：

路径 用例
L1 = a-c-e (2, 0, 4)
L2 = a-b-d (1, 1, 1)
L3 = a-b-e (1, 1, 2)
L4 = a-c-d (3, 0, 3)

点覆盖与边覆盖（PPT 第 80–82 页）：

  • 点覆盖：每个结点（语句）至少执行一次；
  • 边覆盖：每条边（分支）至少执行一次；
  • 路径覆盖：每条完整路径至少执行一次。

补路径数是会爆炸的。两个顺序 if → 4 条路径；十个顺序 if → 1024 条；加一个循环 → 理论上无限。所以实际工程用基本路径测试：不是覆盖所有路径，而是覆盖一组线性无关的路径，数量等于环路复杂度 V(G)。

环路复杂度怎么算（课件未给公式，属于补充）：

V(G)=E−N+2V(G) = E - N + 2V(G)=E−N+2

其中 E 是边数、N 是结点数；也可以直接用经验公式：

V(G)=判定结点数+1V(G) = \text{判定结点数} + 1V(G)=判定结点数+1

本例有两个判定结点，所以 V(G) = 3——意味着至少需要 3 条独立路径才能覆盖所有边。而全部组合路径是 2×2 = 4 条，其中只有 3 条是线性无关的。这个差别就是"基本路径测试"存在的理由：它用最少的用例数覆盖所有分支，而不追求覆盖所有组合。

四道选择题（课件第 78 页原题）

1. 软件测试的目的是（ ） A. 证明软件的正确性　B. 找出软件系统中存在的所有错误　C. 证明软件系统中存在错误　D. 尽可能多地发现软件系统中的错误 → D。A 做不到（不能穷举），B 做不到（不可能找全），C 是曲解（测试不是"为了证明有错"）。

2. 多选题：使用白盒测试方法时，确定测试数据应根据（ ） A. 程序的内部逻辑　B. 指定的覆盖标准　C. 程序的复杂程度　D. 使用说明书 → AB。白盒看内部逻辑，测多少看覆盖标准。D 是黑盒的依据。

3. 多选题：属于白盒测试的技术是（ ） A. 边界值分析　B. 语句覆盖　C. 判定覆盖　D. 条件覆盖 → BCD。边界值分析属于黑盒（等价类/边界值/错误猜测/因果图）。

4. 软件测试是保证软件质量的重要措施，它的实施应该在（ ） A. 程序编程阶段　B. 软件开发全过程　C. 软件运行阶段　D. 软件设计阶段 → B。课件第 19 页的对应表说得很清楚：需求阶段就定确认测试计划，概要设计定集成测试计划，详细设计定单元测试计划——测试计划从第一天就开始。
