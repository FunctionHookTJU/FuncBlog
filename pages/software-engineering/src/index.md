这是一份**按课件原有章节顺序重写**的软件工程笔记，覆盖第 1–10 章共 869 页幻灯片。它不是把 PPT 抄一遍，而是把每章压缩成"这一章到底在讲哪几件事"，再把课件默认你会、其实没人给你讲过的东西补上。

### 这份笔记的三条使用建议

**第一，先看第 0 章。** 软件工程这门课最难的地方不是知识点多，而是**它没有"可运行的证据"**。你写不出一个程序来证明"我懂内聚耦合"，也没有编译器帮你检查"这个设计是不是可维护"。所以整门课靠的是概念之间的**对应关系**：需求对应设计，设计对应代码，代码对应测试，测试对应维护。第 0 章就是把这张对应关系图先铺好，后面每一讲都往里填。

**第二，把每讲末尾的自测题当成"能不能合上书讲出来"的检验。** 这门课的考试极少考背定义，绝大多数是**给一个场景，问你该选哪个模型、哪种维护、哪个覆盖标准**。能对着场景说出"因为……所以选……"才算会。

**第三，凡是"要看形状才讲得清"的地方，图都配好了。** 全书紧贴正文插了 **76 张课件原图**——生命周期、瀑布阶梯、增量与迭代的横向纵向、原型环路、螺旋四象限、需求来源、对象的三块（界面/状态/实现）、抽象的教师—李伟对照、用例图（含银行储蓄系统完整用例图）、ATM 的两版对象模型、状态图与事件跟踪图、内聚耦合七级阶梯、六种架构风格、界面设计类图、N-S 与 PAD、覆盖标准流程图、四类维护饼图、再工程示意图……每张图下面都有三段式图注：

- **图号**（如"图 3-1"是第 3 讲第 1 图，方便口头引用与互相指认）；
- **（PPT 第 N 页）**，可以直接翻课件对照；
- **这张图和上下文的哪句话对应、看图该重点看哪一处**——先看图理解形状，再回来看文字，比单向读文字快得多。

图片可以点击，在新标签页里看原尺寸（正文里是按栏宽缩放的）。如果只记得"有个阶梯图""有个饼图"却想不起细节，按 Ctrl+F 搜图号最快。

### 十讲之间的逻辑线

整门课其实只讲了一件事：**软件规模一大，"一个人随手写"就不成立了，于是必须把它拆成阶段、约定产物、规定做法。** 十讲就是这条链上的十个环节。

| 阶段 | 讲次 | 一句话任务 | 关键产物 |
|---|---|---|---|
| 认识对象 | 1–2 | 软件是什么、为什么需要工程 | — |
| 定做法 | 3 | 按什么顺序、什么节奏做 | 过程模型 |
| 问清楚 | 4–5 | 用户到底要什么 | 需求模型、需求规格说明书 |
| 想明白 | 6–7 | 用什么结构去实现 | 设计模型、设计文档 |
| 写出来 | 8 | 把设计翻译成代码 | 源代码、单元测试 |
| 验一遍 | 9 | 证明它确实能跑对 | 测试用例、测试报告 |
| 活下去 | 10 | 交付之后还得改十年 | 维护记录、演化版本 |

一句话串起整门课：**软件工程 = 用工程化的手段，把"人脑里的想法"逐级翻译成"机器能执行、别人能维护的制品"，并在每一级翻译处留下可检查的证据。**

### 清单之外的高频考点（老师清单没列，但综合题会考）

老师的《重点内容》只列到"章节 + 条目"这一级，有些**画图题和计算题**没写进去，复习时最容易漏。下面几个是看了历年综合题的题型后补的，位置都在讲义里：

| 考点 | 位置 | 一句话 |
|---|---|---|
| N-S 图 ↔ PAD 图互转 | [26 详细设计四工具](software-engineering-26.html#kp-detailed-design) | 同一棵树换排版：选择画三角、循环画竖线，三条规则机械转；**课件 p61–67 的 7 张原图已配齐**（含 p65 嵌套 N-S、p67 数组排序 PAD 范例） |
| McCabe 复杂性度量（环路复杂度） | [31 基本路径测试](software-engineering-31.html#kp-mccabe) | $V(G)=E-N+2=$ 判定结点数 $+1$；条件分支与每个循环各算 1 个判定。**课件里没有这个公式**，是讲义补的，并配了 2019 真题「N-S → PAD → 算得 7」的原图与答案图 |
| 活动图 vs 流程图 | [18 UML 九图](software-engineering-18.html#kp-activity-diagram) | 活动图支持并发分叉/泳道，流程图只有顺序、分支、循环 |
| 内聚七级 / 耦合七级 | [23 模块化](software-engineering-23.html) | 综合题常给一段模块描述，让你判断是哪一级 |
| 用例描述四字段、类图五种关系 | [16 用例描述](software-engineering-16.html#kp-usecase-detail)、[18 类图](software-engineering-18.html#kp-class-diagram) | 需求建模类大题的两块地基 |

> 这类考点**不意味着老师改了重点**——只是提醒你：清单覆盖的是"知识点"，综合题还会考"把两个知识点串起来算一算"。遇到清单里没有、但 PPT 里画了图的工具（N-S、PAD、判定表、因果图），建议都至少练一道手算题。
