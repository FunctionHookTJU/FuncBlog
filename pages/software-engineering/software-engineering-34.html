一、软件与工程（第 1–2 讲）

英文 中文 一句话
Software 软件 程序 + 数据 + 相关文档的集合
Software Artifact 软件制品 开发过程中产生的可交付、可检查、可版本化的产物
Software Lifecycle 软件生命周期 从提出开发到最终退役的全过程
Software Crisis 软件危机 大规模软件开发中成本超支、进度失控、质量难保证等现象的总称
Software Engineering 软件工程 将系统化、规范化、可量化的方法应用于软件开发、运行和维护
Software Process 软件过程 一系列有序的开发与管理活动
Software Process Model 软件过程模型 定义具体开发活动及其逻辑关系
Waterfall Model 瀑布模型 六阶段严格串行的第一个过程模型
Incremental Model 增量模型 按功能分批交付，横向扩展
Iterative Model 迭代模型 整体流程重复多轮，纵向精细化
Prototype Model 原型模型 以可运行原型为媒介导出需求
Spiral Model 螺旋模型 迭代 + 原型 + 风险分析，风险驱动
Agile 敏捷 重视人、可运行软件、客户合作、响应变化
DevOps 开发运维一体化 打通开发与运维的综合策略
Open Source 开源软件 源代码可自由获取与传播，需遵循许可证
License 许可证 授权使用、修改、再分发软件的法律条款
Trustworthy 可信 安全 + 韧性 + 隐私 + 可靠可用的总称
Resilience 韧性 受攻击时保持运行并快速恢复的能力
SWEBOK 软件工程知识体系 IEEE 的软件工程知识域划分
CMM / SW-CMM 能力成熟度模型 评价组织软件开发过程成熟度的模型

二、需求（第 4 讲）

英文 中文 一句话
Requirement 需求 对软件功能、质量、环境、进度的期望与约束
Stakeholder 利益相关方 从系统受益或与之相关的人、组织或系统
Functional Requirement 功能性需求 系统能完成的功能与外部可见行为
Quality Requirement 质量需求 性能、可靠性、易用性等（分外部质量与内部质量）
Constraint 约束性需求 成本、进度、技术选型、遵循标准等限制
Requirement Engineering 需求工程 用工程手段支持需求的获取、分析、建模、文档化与管理
Elicitation 需求获取 通过访谈、问卷、观摩、原型等把需求挖出来
Ambiguity 二义性 同一描述可被理解为不同含义
Traceability 可追踪性 需求能追踪到源头，也能追踪到实现与测试
Baseline 基线 通过评审后冻结、变更须走流程的制品版本
Use Case 用例 参与者使用系统达成某目标的情节描述
Actor 执行者 / 参与者 与系统交互的人或其他系统，代表一种角色
System Boundary 系统边界 划定系统功能范围的方框边线
<<include>> 包含关系 必用的公共步骤（每次都会执行）
<<extend>> 扩展关系 特定条件下才插入的可选流程
Scenario 场景 用例的一条执行路径（用例实例）
Precondition 前置条件 用例开始前必须满足的状态
Postcondition 后置条件 用例结束后世界应处于的状态

三、分析与 UML（第 5 讲）

英文 中文 一句话
OOA 面向对象分析 抽取整理需求并建立问题域精确模型
Object Model 对象模型 描述静态结构，最核心
Dynamic Model 动态模型 描述交互次序与状态变化
Functional Model 功能模型 描述数据变换（数据流图）
Class Diagram 类图 类的属性、操作与类间关系
Object Diagram 对象图 类图在某一时刻的快照，名字带下划线
Package Diagram 包图 按逻辑分组并描述包间依赖
Statechart Diagram 状态图 对象的状态、事件与迁移
Activity Diagram 活动图 活动到活动的控制流（含泳道、对象流）
Sequence Diagram 顺序图 按时间顺序描述对象间消息交互
Communication Diagram 通信图 / 协作图 按空间结构描述对象间交互
Component Diagram 构件图 构件及其依赖关系
Deployment Diagram 部署图 物理节点、构件部署与连接协议
Generalization 泛化 一般—特殊（is-a），实线空心三角
Realization 实现 类实现接口，虚线空心三角
Composition 组合 整体—部分且同生共死，实心菱形
Aggregation 聚合 整体—部分但可分离，空心菱形
Association 关联 一个类知道另一个，实线
Dependency 依赖 临时使用，虚线箭头
Multiplicity 多重性 关联两端的数量约束（1、*、1..n）
Stereotype 构造型 <<...>> 形式的语义扩展标记

四、设计（第 6–7 讲）

英文 中文 一句话
Software Design 软件设计 综合约束，给出需求的实现方案
Software Architecture 软件体系结构 / 架构 高层抽象下的设计元素及其逻辑关联
Architectural Style 体系结构风格 系统级的结构化组织方式
Layered 分层风格 按抽象级别分层，层间请求—服务
Pipes and Filters 管道与过滤器 数据流依次经过处理步骤
Blackboard 黑板风格 共享数据 + 知识源 + 控制器
MVC 模型-视图-控制器 数据、显示、调度三者分离
SOA 面向服务的架构 服务注册、发现、绑定
Message Bus 消息总线 通过总线连接所有构件
Cohesion 内聚 模块内部联系的紧密程度（越高越好）
Coupling 耦合 模块之间联系的紧密程度（越低越好）
Modularity 模块化 分解为功能单一、接口简单的模块
Information Hiding 信息隐藏 只暴露必需信息，隐藏内部实现
Separation of Concerns 关注点分离 不同性质的问题分开处理再整合
Stepwise Refinement 逐步求精 从高层抽象逐步细化到实现
Design Pattern 设计模式 可复用的设计经验（名称+问题+方案+效果）
Creational / Structural / Behavioral 创建型 / 结构型 / 行为型 23 种模式的三大类
Refactoring 重构 不改变外部行为的前提下改善内部结构
N-S Chart 盒图 / N-S 图 只用三结构、无箭头，天然单入单出
PAD 问题分析图 二维树形，最接近可执行代码
PDL 程序设计语言 / 伪码 自然语言与程序语言混合描述

五、编码与测试（第 8–9 讲）

英文 中文 一句话
Structured Programming 结构化程序设计 自顶向下逐步细化 + 单入单出 + 三结构
Coding Style 程序设计风格 提升可读性与可维护性的编码约定
Defect 缺陷 制品中不正确的描述或实现（病根）
Error / Failure 错误 / 失效 缺陷在运行时表现出的不正确状态（症状）
Debugging 调试 定位缺陷原因与位置的过程
Software Testing 软件测试 设计用例、运行程序、比对预期以发现缺陷
Test Case 测试用例 输入数据 + 前提 + 步骤 + 预期输出
White-box Testing 白盒测试 基于内部执行流程设计用例
Black-box Testing 黑盒测试 基于外部功能与接口设计用例
Statement Coverage 语句覆盖 每条语句至少执行一次（最弱）
Decision Coverage 判定（分支）覆盖 每个判定的真、假分支各至少一次
Condition Coverage 条件覆盖 每个条件的真、假各至少一次
Condition/Decision Coverage 判定/条件覆盖 同时满足判定覆盖与条件覆盖
Multiple Condition Coverage 条件组合覆盖 每个判定的所有条件组合至少一次
Path Coverage 路径覆盖 每条可能路径至少一次
Cyclomatic Complexity 环路复杂度 V(G)=E−N+2=判定结点数+1
Equivalence Partitioning 等价类划分 按输入条件分成有效类与无效类
Boundary Value Analysis 边界值分析 在边界及其邻域取值
Error Guessing 错误猜测 凭经验猜测易错点设计用例
Cause-Effect Graphing 因果图 用逻辑图表达输入条件与输出的组合关系
Unit Testing 单元测试 测模块内部（白盒），需驱动与桩
Integration Testing 集成测试 测模块接口（黑盒），自顶向下/自底向上
Validation Testing 确认测试 验证是否满足用户需求，依据需求规格说明书
α / β Testing α/β 测试 内部模拟用户 / 用户现场使用
Driver 驱动模块 模拟主程序，调用被测模块（在上面）
Stub 桩模块 模拟被调用的下层模块（在下面）
Regression Testing 回归测试 修改后重跑用例，防引入新错误
Stress Testing 强度测试 不断加压，找瓶颈与最大服务能力

六、维护（第 10 讲）

英文 中文 一句话
Software Maintenance 软件维护 交付后为改错或满足新需求而修改软件
Logical Aging 逻辑老化 满意度下降、质量下降、变更成本上升
Corrective Maintenance 纠正性维护 修复测试阶段未发现的缺陷（约 25%）
Adaptive Maintenance 适应性维护 适应硬件、OS、编译系统等环境变化（约 21%）
Perfective Maintenance 完善性维护 扩充功能、增强性能、提高可维护性（约 50%）
Preventive Maintenance 预防性维护 为将来更好维护而修改，最难（约 4%）
Code Restructuring 代码重组 功能不变，重组代码组织
Reverse Engineering 逆向工程 从低抽象制品产出高抽象制品（设计/需求）
Design Recovery 设计重构 逆向工程的一种，产出设计文档
Re-engineering 再工程 分析并变更架构，含逆向 + 正向工程
Maintainability 可维护性 被理解、改正、调整、改进的程度
Side Effect 副作用 维护引入的意外损害（代码/数据/文档）
