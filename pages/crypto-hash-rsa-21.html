SHA-1 的加法常量与字扩展（PPT 第 33 页）

加法常量（PPT 原文）：

K1=5a827999，对应 0≤t≤19K_1 = \mathtt{5a827999}，\quad \text{对应 } 0 \le t \le 19K1​=5a827999，对应 0≤t≤19
K2=6ed9eba1，对应 20≤t≤39K_2 = \mathtt{6ed9eba1}，\quad \text{对应 } 20 \le t \le 39K2​=6ed9eba1，对应 20≤t≤39
K3=8f1bbcdc，对应 40≤t≤59K_3 = \mathtt{8f1bbcdc}，\quad \text{对应 } 40 \le t \le 59K3​=8f1bbcdc，对应 40≤t≤59
K4=ca62c1d6，对应 60≤t≤79K_4 = \mathtt{ca62c1d6}，\quad \text{对应 } 60 \le t \le 79K4​=ca62c1d6，对应 60≤t≤79

补这四个常量是怎么来的？ 它们不是随机数，而是**"有来历的无理数"**——具体说：

K1=⌊230×2⌋,K2=⌊230×3⌋,K3=⌊230×5⌋,K4=⌊230×10⌋K_1 = \left\lfloor 2^{30} \times \sqrt{2} \right\rfloor, \quad K_2 = \left\lfloor 2^{30} \times \sqrt{3} \right\rfloor, \quad K_3 = \left\lfloor 2^{30} \times \sqrt{5} \right\rfloor, \quad K_4 = \left\lfloor 2^{30} \times \sqrt{10} \right\rfloorK1​=⌊230×2​⌋,K2​=⌊230×3​⌋,K3​=⌊230×5​⌋,K4​=⌊230×10​⌋

（⌊⋅⌋\lfloor \cdot \rfloor⌊⋅⌋ 是向下取整。这里 2,3,5,10\sqrt{2}, \sqrt{3}, \sqrt{5}, \sqrt{10}2​,3​,5​,10​ 都是无理数。）

用无理数定常量的好处是：它让设计者无法"偷偷埋后门"。 如果常量是设计者随手挑的，那设计者可以反复试、直到找到一个对他自己有利的值（这就是所谓的"隐藏陷门"）。而 2\sqrt{2}2​ 的第 30 位是客观的数学事实，谁都能验算——这个常量不可能被"挑"出来。

【注】原课件没有交代这四个常量的来历，只看 PPT 的话会把它们当成随意指定的数字。记住"它们是 2,3,5,10\sqrt{2}, \sqrt{3}, \sqrt{5}, \sqrt{10}2​,3​,5​,10​ 的前 30 位小数"这件事，比背下四个十六进制串有用得多——因为这正是 SHA-1 设计者用来表示"我没有作弊"的方式。同样的手法在 MD5（T[i]=⌊232∣sin⁡i∣⌋T[i] = \lfloor 2^{32} |\sin i| \rfloorT[i]=⌊232∣sini∣⌋）和 AES 的轮常量里都能看到。

字扩展（PPT 原文）：

前 16 个字 W0,W1,…,W15W_0, W_1, \dots, W_{15}W0​,W1​,…,W15​，直接由输入得到。其余由公式 Wt=CLS1(Wt−3⊕Wt−8⊕Wt−14⊕Wt−16)W_t = CLS_1(W_{t-3} \oplus W_{t-8} \oplus W_{t-14} \oplus W_{t-16})Wt​=CLS1​(Wt−3​⊕Wt−8​⊕Wt−14​⊕Wt−16​) 依次得到。

（勘误：PPT 原文的公式写作 Wt=CLS1(Wt3Wt8 Wt14Wt16)，四个异或符号 ⊕\oplus⊕ 在排版时丢失了。完整形式应为上式。）

这个公式的含义，用一个示意说明：

当前 512 比特分组 Y_q
        │
        ↓ 切成 16 个 32 比特字
   W₀ W₁ W₂ … W₁₅      ← 16 个字，每个 32 比特，共 512 比特
        │
        ↓ 递推扩展
   W₁₆ = CLS₁( W₁₃ ⊕ W₈ ⊕ W₂ ⊕ W₀ )
                 └─┬─┘  └┬┘  └┬┘  └┬┘
             t-3=13  t-8=8 t-14=2 t-16=0
        ↓
   W₁₇ = CLS₁( W₁₄ ⊕ W₉ ⊕ W₃ ⊕ W₁ )
        ↓
        ⋮
   W₇₉ = …

规则：第 ttt 个字（16≤t≤7916 \le t \le 7916≤t≤79）由"往前数第 3、8、14、16 个字"异或后循环左移 1 位得到。

补为什么要做"字扩展"？ 因为 4 轮 × 20 步 = 80 步，每步需要一个新的 WtW_tWt​，而一个 512 比特分组只能提供 16 个字。这是纯粹的"用量问题"——但设计者没有简单地把 16 个字"轮流用 5 遍"，而是用递推生成新字，这里有三层考虑：

  1. 让消息比特被"用得更充分"：消息的每一个比特通过递推会影响到后面 60 多个字，扩散半径大大加长。
  2. 时间上的错位：Wt−3W_{t-3}Wt−3​ 和 Wt−16W_{t-16}Wt−16​ 的跨度不同（一个是"刚过去不久"，一个是"半个分组之前"），这种混合打乱了比特间的固定关系，抵抗差分分析。
  3. 顺序上的不可预知：因为 WtW_tWt​ 依赖前面 4 个字，攻击者没法预先算出并挑拣 WtW_tWt​ 的取值（这是抵抗"消息修改攻击"的关键——攻击者想改消息让 WtW_tWt​ 满足某个条件，会发现改动会连锁影响后面所有的字）。

补注意 SHA-1 的字扩展里那个"循环左移 1 位"：SHA-0（1993 年的原版）没有这个移位，Wt=Wt−3⊕Wt−8⊕Wt−14⊕Wt−16W_t = W_{t-3} \oplus W_{t-8} \oplus W_{t-14} \oplus W_{t-16}Wt​=Wt−3​⊕Wt−8​⊕Wt−14​⊕Wt−16​。1995 年的修订版给它加上了 CLS1CLS_1CLS1​，就成了 SHA-1。

这一个移位就是 SHA-0 和 SHA-1 的全部差别——而它挡住了当时已知的攻击方法。这是一个特别值得记住的案例：密码算法的安全性有时就藏在一个移位里，"看起来多余"的那一步往往承担着关键作用。
