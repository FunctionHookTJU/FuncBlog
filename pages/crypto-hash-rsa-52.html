3.3 小加密指数 e（PPT 第 31–32 页）

补先说动机：RSA 的加密和解密都是模幂运算，代价与指数的大小成正比。所以工程上有很强的动力去选一个小的 eee——加密快、省电、适合智能卡。

但小 eee 会带来两类攻击。PPT 花了 2 页专门讲这件事。

攻击一：同一消息群发（Håstad 广播攻击）（PPT 第 31–32 页）

PPT 第 31 页原文：

为了改进加密效率，我们希望选择小的加密指数 eee，例如，e=3e = 3e=3。一组实体可能选择相同小加密指数 eee。 如果一个实体 AAA 希望发送同一条消息 mmm 给三个实体，他们的公开模为 n1,n2,n3n_1, n_2, n_3n1​,n2​,n3​，而他们的加密指数都是 e=3e = 3e=3，则 AAA 将发送 ci≡m3(modni)c_i \equiv m^{3} \pmod{n_i}ci​≡m3(modni​)，这里 i=1,2,3i = 1, 2, 3i=1,2,3。由于这些模是两两互素，而攻击者可以在公共信道上得到 c1,c2,c3c_1, c_2, c_3c1​,c2​,c3​，因此可以根据中国剩余定理得到一个解 xxx，0≤x<n1⋅n2⋅n30 \le x < n_1 \cdot n_2 \cdot n_30≤x<n1​⋅n2​⋅n3​，满足三个同余式

{x≡c1(modn1)x≡c2(modn2)x≡c3(modn3)\begin{cases} x \equiv c_1 \pmod{n_1} \\ x \equiv c_2 \pmod{n_2} \\ x \equiv c_3 \pmod{n_3} \end{cases}⎩⎨⎧​x≡c1​(modn1​)x≡c2​(modn2​)x≡c3​(modn3​)​

PPT 第 32 页原文：

由于 m3<n1⋅n2⋅n3m^3 < n_1 \cdot n_2 \cdot n_3m3<n1​⋅n2​⋅n3​，就必然有 x=m3x = m^3x=m3。因此，通过计算整数 xxx 的三次方根，攻击者可以恢复出明文消息 mmm。因此，e=3e = 3e=3 这样的小加密指数不能使用在同一消息加密群发的情形。小加密指数在加密小消息 mmm 时同样存在问题，这是因为如果 m<n1/em < n^{1/e}m<n1/e，则密文 c≡me(modn)c \equiv m^{e} \pmod nc≡me(modn) 就可以通过简单计算 ccc 的 eee 次方根得到。

补这个攻击非常漂亮，值得完整走一遍。 攻击的前提条件有三个：

前提 说明
1 同一把密钥群发时用了相同的小 eee（这里是 e=3e=3e=3）
2 发的是同一条消息 mmm（比如同一份密钥、同一份文件）
3 各个模 nin_ini​ 两两互素（不同实体的模都是独立生成的素数乘积，两两互素几乎是必然的）

攻击步骤：

① 攻击者在公共信道上截获三份密文 c₁, c₂, c₃
        ↑ 注意：这是"被动攻击"，攻击者不需要任何交互，
          只要他能在信道上看得见（比如广播）就够了

② 用中国剩余定理（CRT）解三个同余式：

      x ≡ c₁ (mod n₁)
      x ≡ c₂ (mod n₂)
      x ≡ c₃ (mod n₃)
                          ↓
   得到唯一解 x，范围 0 ≤ x < n₁n₂n₃

③ 断言 x 就是 m³（理由见下）
                          ↓
④ 对 x 开三次方根 → 拿到 m

关键在第③步：为什么 x=m3x = m^3x=m3 而不是"m3m^3m3 模 n1n2n3n_1n_2n_3n1​n2​n3​ 的某个值"？

因为同余式 x≡m3(modni)x \equiv m^3 \pmod{n_i}x≡m3(modni​) 的"真正的解"就是 m3m^3m3 本身——只要 m3<n1n2n3m^3 < n_1 n_2 n_3m3<n1​n2​n3​。

核对一下这个不等式：

  • m<nim < n_im<ni​（RSA 的要求，因为明文必须落在 [0,ni−1][0, n_i - 1][0,ni​−1] 里），所以 m3<n13m^3 < n_1^3m3<n13​；
  • 而 n1n2n3n_1 n_2 n_3n1​n2​n3​ 里三个模大致同量级，所以 n1n2n3≈n13n_1 n_2 n_3 \approx n_1^3n1​n2​n3​≈n13​；

更准确地说：设三个模中最小的那个是 n1n_1n1​，则 m<n1m < n_1m<n1​（因为要用所有模都能装下 mmm，而 PPT 说的"同一条消息"意味着 mmm 必须小于每个 nin_ini​）。于是

m3<n13≤n1n2n3m^3 < n_1^3 \le n_1 n_2 n_3m3<n13​≤n1​n2​n3​

所以 m3m^3m3 落在 CRT 解的"标准区间" [0,n1n2n3)[0, n_1n_2n_3)[0,n1​n2​n3​) 之内，于是 x=m3x = m^3x=m3 精确成立，没有取模。✓

补这就是整个攻击的要害：

me<n1n2⋯nk⟹模运算完全"没生效"⟹直接开 e 次方根\boxed{m^e < n_1 n_2 \cdots n_k \quad \Longrightarrow \quad \text{模运算完全"没生效"} \quad \Longrightarrow \quad \text{直接开 $e$ 次方根}}me<n1​n2​⋯nk​⟹模运算完全"没生效"⟹直接开 e 次方根​

模运算"没生效"这几个字是理解所有小指数攻击的钥匙。RSA 的安全性依赖于"取幂之后绕圈"（模 nnn）——如果幂太小、根本没绕圈，那 RSA 就退化成了"一个普通的整数取幂"，没有任何密码学保护。

补需要几个接收者才能攻击成功？

PPT 用的是三个（因为 e=3e=3e=3）。推广一下：

k 个接收者、e=k⟹mk<n1n2⋯nk⟹攻击成立k \text{ 个接收者}、e = k \quad \Longrightarrow \quad m^{k} < n_1 n_2 \cdots n_k \quad \Longrightarrow \quad \text{攻击成立}k 个接收者、e=k⟹mk<n1​n2​⋯nk​⟹攻击成立

所以"e=3e = 3e=3 配 3 个接收者"刚好凑够。攻击者需要 eee 个同余式——这就是为什么 PPT 刚好举了三个实体的例子。

补防御方式：

  1. 不要用同一个小 eee 群发同一条消息——每个接收者用不同的 eee，或者对每个接收者的消息做不同的随机填充；
  2. 给消息加随机填充（第 3.11 节的 OAEP）：填充后每个人的"实际明文"都不同，cic_ici​ 就不再是"同一条消息的三次方"了，CRT 就失效了。这一条是最根本的解法。

攻击二：加密小消息（PPT 第 32 页）

PPT 原文（后半段）：

小加密指数在加密小消息 mmm 时同样存在问题，这是因为如果 m<n1/em < n^{1/e}m<n1/e，则密文 c≡me(modn)c \equiv m^{e} \pmod nc≡me(modn) 就可以通过简单计算 ccc 的 eee 次方根得到。

补这是"同一个漏洞的单机版本"，比上面的更简单。

条件：

m<n1/e⟺me<nm < n^{1/e} \quad \Longleftrightarrow \quad m^{e} < nm<n1/e⟺me<n

这时候：

c=me mod n=me(没有发生取模！)c = m^{e} \bmod n = m^{e} \quad (\text{没有发生取模！})c=memodn=me(没有发生取模！)

因为 mem^eme 本身就小于 nnn，取模等于没取。

于是攻击者只要对 ccc 开 eee 次方根就拿到 mmm 了。

补手算一个例子（用第 1.2 节例 1 的模）：

n = 6012707,  e = 3,  n^{1/3} ≈ 181.9

攻击者看到 c = 8000

因为 8000 < 6012707，所以 c 没有被取模
判断：8000 是不是完全立方数？
   20³ = 8000  ✓  是！

所以 m = 20     ← 直接开方，无需任何密钥

如果 m=200m = 200m=200（比 n1/3≈182n^{1/3} \approx 182n1/3≈182 大）：

2003=8000000,8000000 mod 6012707=1987293200^3 = 8000000, \qquad 8000000 \bmod 6012707 = 19872932003=8000000,8000000mod6012707=1987293

这时候 c=1987293c = 1987293c=1987293 已经被取模"打乱"了，开三次方根得不到整数——攻击失效。

补两类攻击的统一视角：

群发攻击 小消息攻击
攻击对象 多个接收者（用 CRT 把模"放大"） 单个接收者
"取模失效"的原因 mem^eme 小于 n1n2⋯nkn_1n_2\cdots n_kn1​n2​⋯nk​ mem^eme 小于 nnn
攻击代价 一次 CRT + 一次开方 一次开方
共同要害 mem^eme 没有超过模，取模运算形同虚设 同左

补一个直觉上的比喻：取模就像"把数字卷进一个圈里"。如果数字本来就比圈的周长小，根本不用卷——原地放着就完了。攻击者看到的就是那个"没被卷过的原值"。

补防御方式：

  1. 消息加随机填充（让 mmm 变得足够大且随机）——这是标准做法；
  2. 不要用太小的 eee——但这一条和第 4.3 节"要用小 eee 提升效率"是矛盾的，所以实际采用第 1 条；
  3. 在消息前面拼上固定的填充串，保证 mmm 接近 nnn 的量级。

补这一节的结论，值得记成一句话：

小 eee 本身不是问题，"模没生效"才是问题。

注意 e=3e=3e=3 和 e=65537e=65537e=65537 都是"小 eee"（第 4.3 节会推荐这两个），但加了正确填充之后它们都是安全的。所以第 4.3 节推荐小 eee、这一节攻击小 eee——两者不矛盾，前提条件不同。
